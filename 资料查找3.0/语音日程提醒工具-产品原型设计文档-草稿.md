# 语音日程提醒工具：产品原型设计文档

---

## 1. 交互蓝图
P1（任务创建-语音创建与查询）
P2（任务提醒-提醒触发与即时响应）
P3（任务修正）

### 1.1 能力链
P1 -> P2 -> P3 
 ^           |
 |-----------

### 1.2 核心交互规则
1.语音交互为主
2.消息回执为辅

## 2. 本期范围

### 2.1 本期做什么
1.用户语音创建日程，并事后用语音系统正确记录和查询
2.一句话可以完成创建/修改/查询
3.语音推送包含简洁信息，回执推送包含较完整信息
4.删除日程或者周期的时候，明确提醒

### 2.2 本期明确不做
1.复杂的ui交互
2.特殊的情况不做（跨时区）
3.不提供日历
4.暂不依赖除了语音之外的传感器
5.不做全天候录音和等待识别
6.不定义语音入口的具体载体
7.不做外部信号监控（如「老张三点没回消息就提醒我」）
8.修改其他人的日程或共享日历

## 3. P1 原型：语音创建与查询

### 流程 1：[一句话创建单次日程]

```text
用户：我今天下午7点要开一个半小时的会
系统语音：今天下午7点提醒你开会。

IM 回执：
  已创建日程
  标题：开会
  时间：今天 19:00 - 20:30
  操作：撤销 / 查看今天日程
```

### 流程 2：[一句话修正单次日程]

```text
用户：我今天7点的会推迟到7.30
系统语音：今天7点的会改到7:30。

IM 回执：
  已修改日程
  事项：开会
  原时间：今天 19:00
  新时间：今天 19:30
  操作：撤销修改
```

### 流程 3：[一句话删除单次日程]

```text
用户：我今天7点的会不开了
系统语音：确定取消今天7点的会吗？
用户：确定。
系统语音：已取消。

IM 回执：
  已删除日程
  事项：开会
  时间：今天 19:00
```

### 流程 4：[一句话查询单次日程]

```text
用户：我今天7点要干什么
系统语音：今天7点和pz开会。

IM 回执：
  今天 19:00 - 20:30
  事项：和pz开会
```

### 流程 5：[一句话查询日程]

```text
用户：我今天还要干什么
系统语音：今天还有2件事。下午3点和pz开会，晚上7点产品评审。

IM 回执：
  今天剩余日程（2条）
  15:00 和pz开会
  19:00 产品评审
```

## 4. P2 原型：提醒触发与即时响应

### 流程 6：提醒触发后关闭

```text
系统语音：提醒：今天 19:00 开会。

用户：知道了。

IM 回执：
  提醒已关闭
  事项：开会
  时间：今天 19:00
```

### 流程 7：稍后提醒

```text
系统语音：提醒：15分钟后开始周会。

用户：十分钟后再提醒。

系统语音：好，10分钟后再提醒你。

IM 回执：
  提醒已推迟
  事项：周会
  新提醒：10分钟后
```
```text
用户：晚点提醒我。

系统语音：晚多久？十分钟、半小时还是一小时？
```

### 流程 8：IM 受控回复

```text
IM 回执：
  提醒：客户拜访
  时间：今天 14:30
  按钮：[知道了] [10分钟后提醒] [30分钟后提醒]

用户点击：[10分钟后提醒]

IM 更新：
  已推迟至 14:40
```

## 5. P3 原型：已有日程变更与周期控制

### 流程 9：修改单次日程

```text
用户：把今天和pz的会改到下午四点。

系统语音：和pz的会已改到今天下午四点。

IM 回执：
  已修改日程
  事项：和pz开会
  原时间：今天 15:00
  新时间：今天 16:00
```

### 流程 10：周期范围确认

```text
用户：把每周五的周报改到周六上午。
系统语音：这是每周重复事项。只改本周，还是以后都改？
用户：以后都改。
系统语音：行，从本周开始改到每周六。上午几点？
```

### 流程 11：跳过一次
```text
用户：这周周报跳过一次。
系统语音：这周已经跳过了，没重复操作。
```

### 流程 13：单次事项的"跳过"

```text
用户：跳过明天下午三点和pz的会。
系统语音：这是单次日程，跳过就等于取消。确定取消吗？
用户：确定。
系统语音：已取消明天下午三点和pz的会，可以撤销。
```

### 流程 14：删除日程

```text
<!-- 明确命中 -->
用户：删掉今天下午三点和pz的会。

系统语音：已删除今天下午三点和pz的会。删错了就说撤销。

IM 回执：
  已删除日程
  事项：和pz开会
  时间：今天 15:00
  影响范围：单次日程
  操作：撤销删除
```

### 流程 15：修改后时间冲突

```text
用户：把今天和pz的会改到下午四点。

系统语音：下午四点已有项目评审。仍然把pz的会改到四点吗？

用户：还是改。

系统语音：改好了，两条日程会重叠，我在回执里标出来。

IM 回执：
  已修改日程
  事项：和pz开会
  新时间：今天 16:00
  冲突：今天 16:00 项目评审
```

## 6. 异常处理

| 状态 | 语音处理 | IM 处理 |
| --- | --- | --- |
| 没听清 | "我没听清，你再说一遍。" 追问| 展示已识别到的部分字段 |
| 缺少必要信息 | "这个安排预计多久？” 追问| 留待补字段，不创建不完整日程 |
| 找不到目标日程 | "没找到这条，我发你今天日程你确认下是哪条。" | 展示当天候选列表 |
| 查询结果为空 | "今天没有日程。" | 显示空状态和创建入口 |
| IM 发送失败 | 语音正常播报，后续补发 | 恢复后补发或标记失败，语音告知"回执没发出去" |

## 7. 验收标准

1. 产品不是日历 GUI，而是语音日程提醒工具。
2. 发现时间冲突时，系统在创建或修改前提示
3. 提醒语音默认只播标题和发生时间，不播地点和备注。
4. 周期事项变更必须说明范围
5. 单次事项的"跳过"解释为取消
6. 删除、终止、范围不明操作必须先确认
7. 修改、跳过、删除、终止完成后有 IM 回执和撤销入口。
