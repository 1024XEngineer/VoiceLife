# 字段统一设计：状态机与命名规范

> 日期：2026-07-27
> 目标：统一 PR #79、#78、#70 三份文档中所有实体的 status 字段和命名规则
> 核心原则：状态字段用设计模式统一；状态描述"是什么"，不描述"做了什么"

---

## 一、Status 字段统一

### 1.1 设计模式：有限状态机（FSM）+ 枚举约束

每个实体独立一个状态机，状态值用 snake_case 字符串，数据库层用 CHECK 约束硬限制。

### 1.2 Schedule（日程）

```
        ┌──────────┐
        │  active  │──── 用户说"取消" ────→ ┌───────────┐
        └────┬─────┘                       │ cancelled │
             │ start_time 已过              └───────────┘
             ▼
        ┌───────────┐
        │ completed │  （自动，不用于手动操作）
        └───────────┘
```

| 状态 | 含义 | 触发方式 |
| --- | --- | --- |
| `active` | 日程有效 | 创建时默认 |
| `completed` | 已过期 | 系统在 start_time 过去后自动标记 |
| `cancelled` | 用户主动取消 | delete_schedule 不物理删除，改为此状态 |

**废弃**：`cancelled` 替代物理删除。增加 `completed` 区分"过了时间"和"被取消"。

### 1.3 Reminder（提醒）

```
                         ┌──────────┐
                    ┌───→│ snoozed  │──┐
                    │    └──────────┘  │ 到期
                    │                  ▼
  ┌─────────┐  触发  ┌───────────┐  关闭  ┌───────────┐
  │ pending │──────→│ triggered  │──────→│ dismissed  │
  └─────────┘       └───────────┘       └───────────┘
```

| 状态 | 含义 |
| --- | --- |
| `pending` | 等待触发 |
| `triggered` | 已触发，正在播报/等待响应 |
| `snoozed` | 用户推迟，等待再次触发 |
| `dismissed` | 用户说"知道了"，本次提醒关闭 |

**废弃**：`pushed` → 改为 `triggered`；`closed` → 改为 `dismissed`；`delayed` / `multi-delayed` → 合并为 `snoozed` + `delay_count` 字段记录推迟次数。

### 1.4 RecurringSeries（周期系列）

```
  ┌──────────┐   暂停    ┌──────────┐   恢复    ┌──────────┐
  │  active  │──────────→│  paused  │──────────→│  active  │
  └────┬─────┘           └──────────┘           └──────────┘
       │ 终止
       ▼
  ┌───────────┐
  │ terminated│
  └───────────┘
```

| 状态 | 含义 |
| --- | --- |
| `active` | 周期生效中 |
| `paused` | 暂停（临时），`paused_until` 字段记录恢复时间 |
| `terminated` | 永久终止 |

`paused` 与 `terminated` 的关键区别：`paused` 有 `paused_until` 时间，到期后系统自动恢复为 `active`。

### 1.5 RecurringInstance（周期实例）

```
  ┌──────────┐   跳过   ┌──────────┐
  │  active  │──────────→│ skipped  │
  └────┬─────┘           └──────────┘
       │ 修改
       ▼
  ┌───────────┐
  │ modified  │  （override 字段记录修改了什么）
  └───────────┘
```

| 状态 | 含义 |
| --- | --- |
| `active` | 按 series 规则正常生成 |
| `skipped` | 本次跳过（不影响 series） |
| `modified` | 本次被修改（override 字段存差异） |

**修正**：原 #70 用 `modified` 作为状态——但"修改"是操作类型而非实例状态。改为：`modified` 是终态（这个实例已被修改，不再随 series 变化），override 字段存储修改后的差异字段。

### 1.6 Trigger（触发队列）

```
  ┌───────────┐   到期   ┌──────────┐
  │ scheduled │──────────→│  fired   │
  └─────┬─────┘           └──────────┘
        │ 取消
        ▼
  ┌───────────┐
  │ cancelled │
  └───────────┘
```

| 状态 | 含义 |
| --- | --- |
| `scheduled` | 已排期，等待触发 |
| `fired` | 已触发 |
| `cancelled` | 被取消（日程取消时级联） |

## 二、命名规范统一

### 2.1 ID 命名

| 规则 | 示例 | 说明 |
| --- | --- | --- |
| 主键统一命名为 `id` | `id` | 不叫 `schedule_id`、`reminder_id`。自增整数或 UUID |
| 外键命名为 `<target_table>_id` | `schedule_id` | 引用其他表的列 |
| API 返回值中的 ID 用 `id` | `{"id": 1, "event": "开会"}` | 因为在 schedule 对象的上下文中，`schedule_id` 冗余 |

### 2.2 时间字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `created_at` | TEXT (ISO 8601) | 创建时间，由系统自动设置 |
| `updated_at` | TEXT (ISO 8601) | 最后修改时间，由系统自动更新 |
| `deleted_at` | TEXT (ISO 8601) \| NULL | 软删除时间，查询默认 `WHERE deleted_at IS NULL` |

> 三张表都需要这三个字段，无一例外。

### 2.3 布尔字段

| 规则 | 示例 |
| --- | --- |
| 用 `is_` 前缀 | `is_completed`、`is_recurring` |
| 数据库存 INTEGER (0/1) | `is_recurring INTEGER NOT NULL DEFAULT 0` |
| API 返回 boolean | `"is_recurring": false` |

### 2.4 枚举字段

| 规则 | 示例 |
| --- | --- |
| 字符串小写 + 下划线 | `"active"`、`"pending"` |
| 数据库 CHECK 约束 | `CHECK(status IN ('active','completed','cancelled'))` |
| 默认值明确 | `DEFAULT 'active'` |

## 四、变更对照表

| 实体 | 原 #79/#70 字段 | 统一后 | 理由 |
| --- | --- | --- | --- |
| Schedule.id | `schedule_id` | `id` | 上下文已知实体类型 |
| Schedule.status | `active` \| `cancelled` | + `completed` | 区分过期和取消 |
| Schedule | 无 `deleted_at` | 新增 `deleted_at` | 软删除 |
| Reminder.status (#79) | `pending`/`triggered`/`snoozed`/`dismissed` | 保持 | #79 命名更好 |
| Reminder.status (#70) | `pending`/`pushed`/`closed`/`delayed`/`multi-delayed` | **废弃，改用 #79** | 统一 |
| Reminder | 无 `delay_count` | 新增 `delay_count` | 替代 `multi-delayed` |
| RecurringInstance.status | `active` \| `skipped` \| `modified` | 保持 | 语义清晰 |
| RecurringSeries | 无 `paused_until` | 新增 | 区分暂停和终止 |
