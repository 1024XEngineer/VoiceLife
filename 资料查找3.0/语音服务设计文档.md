
# 语音模块

定义 VoiceLife 的语音模块。这里的 语音模块 不是一块麦克风或功放板，而是连接用户语音、XRobot、日程、提醒等的软件交互层。

## 共同模式

    1. 有一个会话编排器，统一管理一轮语音从开始到结束。
    2. 音频数据和控制事件分开传递。
    3. STT、LLM、TTS 可以是三个可替换阶段，也可以由平台提供。
    4. 业务模块通过 Tool/Function/MCP 接入，不直接处理音频。
    5. 麦克风、扬声器和网络媒体属于适配层，不应该进入日程、提醒接口。

## 1. 核心目标

语音模块解决的事：

    1. 接收开始、停止、取消等会话命令。
    2. 把设备音频交给语音服务，再把服务返回的音频交给设备播放。
    3. 把语音服务产生的工具调用转给日程、提醒等业务模块。
    4. 把会话状态、转写、工具结果、播报结果和错误通知给 其他 模块。

## 2. 核心概念定义各部分是什么

各部分是什么

   概念                       理解            实际作用

                                              决定回复或调用工具
  ─────────────────────────  ──────────────  ───────────────────────────────────
   VoiceSessionCoordinator    总调度员        决定什么时候录音、处理、播放、取
                                              消和结束
  ─────────────────────────  ──────────────  ───────────────────────────────────
   ToolCall                   结构化派工单    把“创建日程”变成工具名和明确参数
  ─────────────────────────  ──────────────  ───────────────────────────────────
   ToolGateway                派单中心        根据工具名把请求送给 Schedule、
                                              Reminder 或 Memory
  ─────────────────────────  ──────────────  ───────────────────────────────────
   VoiceEvent                 状态通知栏      告诉 UI、IM 和诊断模块现在发生了
                                              什么
  ─────────────────────────  ──────────────  ───────────────────────────────────
   Announcement               主动广播        没有用户提问时，由提醒模块主动要
                                              求设备说一句话

    - VoiceSessionID（语音会话标识）
        - 本地生成。
        - 表示一次从打开语音能力到关闭的会话，可包含多轮对话。
        - 不等同于 XRobot 返回的 provider_session_id。

    - VoiceTurnID（语音轮次标识）
        - 表示用户说一句话到系统完成一次回复的过程。
        - 一次 Session 可以包含多个 Turn。
        - 日程创建、提醒关闭等工具调用必须关联到一个 Turn。

    - Generation（会话代次）
        - 每次取消、重连或开始新 Turn 时递增。
        - 旧代次迟到的 Provider 转写和音频一律丢弃，避免上一轮内容串到下一轮。
        - 已经分发给业务模块的 ToolCall 不能靠 Generation 回滚；其最终结果仍要发给 Application/IM，并标记 orphaned_turn。

            VoiceSessionID 可以理解为“这通电话的编号”。

            用户唤醒设备后创建一个 Session。在关闭语音能力前，用户可以连续说多句话。

            VoiceTurnID 是“这通电话中某一句话的编号”。

            例如：

            Session S1
            ├── Turn T1：明天下午三点帮我开会
            ├── Turn T2：提前十五分钟提醒
            └── Turn T3：算了，取消刚才的安排

            Generation 是“当前有效版本号”。

            假设 T1 使用 Generation 1。用户突然取消并开始 T2，系统把 Generation 改成 2。此
            时 T1 迟到的文字或音频即使到达，也会被丢弃，避免上一轮回答突然插进来。

    - SpeechProvider（语音服务提供方）
        - 对上提供统一的转写、回复、工具调用、语音输出和取消事件。
        - XRobot 是一个实现。
        - Provider 内部可以是 STT -> LLM -> TTS，也可以是实时语音模型；业务模块不感知这种差异。

    - AudioDevice（音频设备）
        - 只负责提供音频输入帧、接收音频输出帧和声明设备能力。
        - 当前连接的小智开发板是 V0 的第一个实现。
        - AudioDevice 不知道日程、提醒、MCP 或用户意图。

    - ToolCall（工具调用）
        - Provider/Agent 要求业务模块执行的一次结构化操作。
        - 包含 tool_call_id、tool_name、arguments、deadline 和上下文标识。
        - ToolGateway 负责路由，业务模块负责参数规则、事务和幂等。

    - Announcement（主动播报）
        - 由提醒或其他业务模块主动发起的一次语音输出请求。
        - 它不是普通对话回复，必须有 request_id、优先级、过期时间、打断策略和完成回执。

    - VoiceEvent（语音事件）
        - 语音模块对外发布的统一事件。
        - UI、IM、诊断和业务编排层通过事件了解进度，不直接读取语音模块内部状态。

## 3. 核心业务流程

### 流程一：用户说话并调用日程模块

    ~~~text
    按键 / 唤醒词
    -> VoiceSessionPort.StartTurn
    -> AudioDevicePort 开始采集
    -> SpeechProviderPort 接收音频
    -> Provider 返回 transcript.final
    -> Provider 发出 tool.call.requested
    -> ToolGateway 调用 Schedule ToolHandler
    -> Schedule 返回结构化结果
    -> ToolGateway 把 tool result 交回 Provider
    -> Provider 返回回复文本和音频
    -> AudioDevicePort 播放
    -> VoiceEventPort 发布 turn.completed
    ~~~

    例子：

    ~~~text
    用户：“明天下午三点开会，提前十五分钟提醒我”
    Provider/Agent：
    1. 调 create_schedule
    2. 调 add_reminder
    业务模块：
    1. Schedule 保存日程并返回 schedule_id
    2. Reminder 保存提醒并返回 reminder_id
    语音模块：
    1. 只负责转发两次 ToolCall 和 ToolResult
    2. 播放 Provider 返回的确认语音
    3. 发布工具结果和播放完成事件
    ~~~

    语音模块不能自己拼接 SQL，也不能根据自然语言直接修改日程对象。

### 流程二：提醒模块发起主动播报

    ~~~text
    Reminder 到点
    -> AnnouncementPort.Enqueue
    -> VoiceSessionCoordinator 检查当前会话和 Provider 能力
    -> 可播报：排队或按策略打断，完成后回执
    -> 不可播报：返回 UNSUPPORTED / UNAVAILABLE
    -> Application 决定是否改走 IM 或屏幕通知
    ~~~

### 流程三：用户取消或开始新一轮

    ~~~text
    用户按停止 / 再次唤醒
    -> VoiceSessionPort.CancelTurn
    -> Generation + 1
    -> Provider 取消旧 Turn
    -> AudioDevice 停止旧播放
    -> 清理旧代次队列
    -> 发布 turn.cancelled
    -> 旧代次 Provider 转写或音频到达时发布 diagnostic.stale_event 并丢弃
    ~~~

    取消必须幂等。重复取消同一个 Turn 仍返回成功，不得恢复旧音频或重复通知业务模块。

## 4. 模块调用关系

### 4.1 小智官方架构：单体固件内的中心编排

以 `xiaozhi-esp32@e0074e90` 为准，小智官方的软件调用关系如下：

~~~text
Button / Wake Word / Board
             |
             | StartListening / StopListening / ToggleChatState
             v
      Application (singleton)
      - 主任务和 EventGroup
      - DeviceStateMachine
      - 直接分派 tts / stt / llm / mcp JSON
          |                     |
          |                     +------> McpServer ------> Board / Codec Tools
          |
          +------> AudioService <------> AudioCodec <------> MIC / Speaker
          |        采集、AFE/VAD、Opus 编解码、播放队列
          |
          +------> Protocol <==========> XRobot Server
                   WebSocket / MQTT       ASR / LLM / TTS
                   audio / listen /       stt / tts / mcp /
                   abort / mcp            binary audio
~~~

音频数据在官方实现中是两条独立流：

~~~text
MIC -> Audio Engine -> Encode Queue -> Opus Encoder -> Send Queue -> Protocol -> Server
Server -> Protocol -> Decode Queue -> Opus Decoder -> Playback Queue -> Speaker
~~~

这种设计对单设备固件是合理的：调用链短，音频队列和设备状态都在一个进程内。但 `Application` 是固件总协调器，不是供其他模块调用的稳定语音 API。

直接把小智 `Application` 当语音模块的问题：
    - 中心类承担太多跨模块职责，每接入日程、提醒或 IM 都可能要修改固件中心类，难以独立测试和替换
    - Provider 协议会泄漏给业务模块，如果 Schedule 或 UI 直接读这些字段，以后更换 XRobot 或协议版本时要跟着改业务代码

### 4.2 目标架构：保留小智音频链路，拆出跨模块接口

~~~text
UI / Button / Wake Word
          |                                      Reminder / Application
          v                                                |
  VoiceSessionPort                                         v
          |                                       AnnouncementPort
          +------------------+-----------------------------+
                             v
                VoiceSessionCoordinator
                  |         |         |         |
                  |         |         |         +----> VoiceEventPort
                  |         |         |                  |
                  |         |         |                  +----> UI / IM / Diagnostics
                  |         |         |
                  |         |         +----> ToolGateway <====> Schedule / Reminder / Memory
                  |         |                    ToolCall / ToolResult
                  |         |
                  |         +----> SpeechProviderPort
                  |                    |
                  |                    +----> XRobot Adapter
                  |                              |
                  |                              +----> Xiaozhi Protocol <====> XRobot Server
                  |
                  +----> AudioDevicePort
                              |
                              +----> Xiaozhi Audio Adapter
                                        |
                                        +----> AudioService <----> AudioCodec
~~~

  1. 用户按键或说唤醒词
  2. Coordinator 创建 Session 和 Turn
  3. 小智板录音
  4. XRobot 把声音转成文字并理解意图
  5. XRobot 发出两个 ToolCall
     create_schedule
     add_reminder
  6. ToolGateway 把两个任务分别交给日程和提醒模块
  7. 日程、提醒模块真正写入数据并返回结果
  8. XRobot生成“好的，已经为你安排”的回复音频
  9. 小智板播放回复
  10. VoiceEvent 通知 UI 和 IM：操作完成

## API 接口设计 \(V0 - Voice-Centric\)

本节只列其他模块能够调用的接口。XRobot 协议、音频帧、Codec、Provider 回调和设备适配器都属于语音模块内部实现，不在这里展开。
以下使用 HTTP 方法和路径表达接口语义。如果 V0 最终采用进程内调用，方法名和返回语义保持一致。

### 1. 接口总览

**语音会话**

- `POST   /v1/voice/sessions` —— 创建语音会话。
- `GET    /v1/voice/sessions/{sessionId}` —— 查询语音会话状态。
- `DELETE /v1/voice/sessions/{sessionId}` —— 关闭语音会话。
- `POST   /v1/voice/sessions/{sessionId}/turns` —— 开始一轮用户语音输入。
- `POST   /v1/voice/sessions/{sessionId}/turns/{turnId}/stop-input` —— 结束本轮录音并进入处理。
- `POST   /v1/voice/sessions/{sessionId}/turns/{turnId}/cancel` —— 取消本轮处理或播放。

**事件订阅**

- `GET    /v1/voice/events` —— 订阅语音状态、转写、工具结果、播报结果和错误。

**业务工具接入**

- `POST   /v1/voice/tools` —— 注册日程、提醒或记忆工具。
- `GET    /v1/voice/tools` —— 查询已经注册的工具。
- `POST   /v1/voice/tool-calls/{toolCallId}/result` —— 返回业务工具执行结果。
- `POST   /v1/voice/tool-calls/{toolCallId}/cancel` —— 请求取消尚未完成的工具调用。

**主动播报**

- `POST   /v1/voice/announcements` —— 提交主动播报。
- `GET    /v1/voice/announcements/{announcementId}` —— 查询播报状态。
- `POST   /v1/voice/announcements/{announcementId}/cancel` —— 取消播报。

### 2. 详细接口参数

#### 1\) 创建语音会话（StartSession）

- **方法与路径**: `POST /v1/voice/sessions`
- **说明**: Application、UI、按键或唤醒词适配器创建一次语音会话。成功后返回 `sessionId`，后续操作都使用这个 ID。
- **入参 \(Body\)**:
    - `requestId` \(string, 必填\): 请求幂等 ID，重试时保持不变。
    - `deviceId` \(string, 必填\): 逻辑设备 ID。
    - `agentId` \(string, 必填\): 语音 Agent 或 Provider 配置 ID。
    - `userId` \(string, 可选\): 当前用户 ID。
    - `trigger` \(string, 必填\): `button`、`wake_word`、`ui` 或 `system`。
    - `locale` \(string, 可选\): 语言和地区，例如 `zh-CN`。
- **出参 \(Body\)**: `data` 为创建结果，包含 `sessionId` 和初始状态 `opening`。

#### 2\) 查询语音会话（GetSnapshot）

- **方法与路径**: `GET /v1/voice/sessions/{sessionId}`
- **说明**: UI 或 Diagnostics 查询当前是否正在听、处理中、播放或已经结束。
- **入参 \(Path\)**: `sessionId` \(string, 必填\): 语音会话 ID。
- **出参 \(Body\)**:
    - `data.sessionId` \(string\): 会话 ID。
    - `data.state` \(string\): `opening`、`ready`、`closing`、`closed` 或 `failed`。
    - `data.activeTurnId` \(string, 可选\): 当前 Turn ID。
    - `data.lastError` \(object, 可选\): 最近一次错误。

#### 3\) 关闭语音会话（CloseSession）

- **方法与路径**: `DELETE /v1/voice/sessions/{sessionId}`
- **说明**: 关闭会话并停止尚未完成的录音或播放。重复关闭同一个会话不会产生第二次操作。
- **入参 \(Path\)**: `sessionId` \(string, 必填\): 要关闭的会话 ID。
- **入参 \(Query\)**: `reason` \(string, 可选\): `user_close`、`session_close` 或 `fatal_error`。
- **出参 \(Body\)**: `data` 为关闭后的会话状态，成功关闭后为 `closed`。

#### 4\) 开始一轮语音输入（StartTurn）

- **方法与路径**: `POST /v1/voice/sessions/{sessionId}/turns`
- **说明**: 在已有会话中开始接收用户的一句话。成功后返回 `turnId`；一个 Session 可以先后包含多个 Turn。
- **入参 \(Path\)**: `sessionId` \(string, 必填\): 必须处于 `ready` 状态的会话 ID。
- **入参 \(Body\)**:
    - `requestId` \(string, 必填\): 请求幂等 ID。
    - `inputMode` \(string, 必填\): `push_to_talk`、`wake_word` 或 `continuous`。
    - `interruptPolicy` \(string, 可选\): `reject` 或 `cancel_current`，V0 不支持隐式排队。
    - `wakeWord` \(string, 可选\): `inputMode=wake_word` 时的唤醒词。
- **出参 \(Body\)**: `data` 为创建结果，包含 `turnId` 和状态 `capturing`。

#### 5\) 结束本轮录音（StopInput）

- **方法与路径**: `POST /v1/voice/sessions/{sessionId}/turns/{turnId}/stop-input`
- **说明**: 停止麦克风输入并让语音服务开始处理。它不会取消本轮回复。
- **入参 \(Path\)**: `sessionId` 和 `turnId` \(string, 必填\): 目标会话和轮次 ID。
- **入参 \(Body\)**: `reason` \(string, 必填\): `user_release`、`vad_end` 或 `timeout`。
- **出参 \(Body\)**: `data` 为 `turnId` 和新状态 `processing`。

#### 6\) 取消本轮语音（CancelTurn）

- **方法与路径**: `POST /v1/voice/sessions/{sessionId}/turns/{turnId}/cancel`
- **说明**: 取消当前 Turn 的识别、回复或播放。已经由日程、提醒等模块提交的数据不会被语音模块回滚。
- **入参 \(Path\)**: `sessionId` 和 `turnId` \(string, 必填\): 目标会话和轮次 ID。
- **入参 \(Body\)**: `reason` \(string, 必填\): `user_cancel`、`new_turn`、`session_close`、`provider_error` 或 `device_error`。
- **出参 \(Body\)**: `data` 为 `turnId` 和最终状态 `cancelled`，重复取消返回成功。

#### 7\) 订阅语音事件（Subscribe）

- **方法与路径**: `GET /v1/voice/events`
- **说明**: UI、IM 和 Diagnostics 通过事件流接收会话状态、转写文本、工具结果、播报结果和错误。连接关闭即停止订阅。
- **入参 \(Query\)**:
    - `sessionId` \(string, 可选\): 只订阅指定会话。
    - `turnId` \(string, 可选\): 只订阅指定 Turn。
    - `eventType` \(string, 可选\): 按事件类型过滤，例如 `transcript.final` 、`tool.call.completed` 或 `error`。
- **出参 \(Stream\)**: 每条事件包含 `eventId`、`eventType`、关联 ID 和 `payload`。

#### 8\) 注册业务工具（RegisterTool）

- **方法与路径**: `POST /v1/voice/tools`
- **说明**: Schedule、Reminder 或 Memory 注册可供语音 Agent 调用的工具名称、参数说明和处理器。语音模块只负责路由，不执行具体业务。
- **入参 \(Body\)**:
    - `toolName` \(string, 必填\): 工具名称，例如 `create_schedule`。
    - `schemaVersion` \(string, 必填\): 工具参数版本。
    - `description` \(string, 必填\): 给 Agent 使用的工具说明。
    - `inputSchema` \(object, 必填\): 工具参数的 JSON Schema。
    - `ownerModule` \(string, 必填\): 工具所属模块，例如 `schedule`。
- **出参 \(Body\)**: `data` 为注册成功的工具定义，包含 `toolName`、`schemaVersion` 和 `ownerModule`。

#### 9\) 查询业务工具（ListTools）

- **方法与路径**: `GET /v1/voice/tools`
- **说明**: Application 或 Diagnostics 查询当前已注册的工具，用于检查语音 Agent 能否调用对应业务能力。
- **入参 \(Query\)**: `ownerModule` \(string, 可选\): 按所属模块过滤。
- **出参 \(Body\)**: `data` 为工具定义数组，每项包含 `toolName`、`schemaVersion`、`description`、`inputSchema` 和 `ownerModule`。

#### 10\) 返回业务工具结果（SubmitToolResult）

- **方法与路径**: `POST /v1/voice/tool-calls/{toolCallId}/result`
- **说明**: Schedule、Reminder 或 Memory 执行工具后，把最终结果交回语音模块。语音模块再决定是否将结果送回当前 Provider。
- **入参 \(Path\)**: `toolCallId` \(string, 必填\): 事件中下发的工具调用 ID。
- **入参 \(Body\)**:
    - `status` \(string, 必填\): `succeeded`、`failed`、`cancelled` 或 `timed_out`。
    - `result` \(object, 可选\): 成功时的业务结果。
    - `error` \(object, 可选\): 失败时的统一错误对象。
    - `orphanedTurn` \(boolean, 必填\): 原 Turn 已取消但业务结果仍有效时为 `true`。
- **出参 \(Body\)**: `data` 为接收结果，包含 `toolCallId` 和 `accepted`。

#### 11\) 取消业务工具调用（CancelToolCall）

- **方法与路径**: `POST /v1/voice/tool-calls/{toolCallId}/cancel`
- **说明**: Application 或语音会话取消时，请求业务模块停止尚未完成的工具调用；这是尽力取消，不代表事务回滚。
- **入参 \(Path\)**: `toolCallId` \(string, 必填\): 要取消的工具调用 ID。
- **入参 \(Body\)**: `reason` \(string, 必填\): 取消原因。
- **出参 \(Body\)**: `data` 为取消请求接收结果；事务已提交时，仍通过结果接口返回真实结果。

#### 12\) 提交主动播报（Enqueue）

- **方法与路径**: `POST /v1/voice/announcements`
- **说明**: Reminder 或 Application 提交一段需要播出的文本。接口返回 `announcementId`；请求被接受不等于已经播完。
- **入参 \(Body\)**:
    - `requestId` \(string, 必填\): 播报请求的幂等 ID。
    - `sourceModule` \(string, 必填\): 请求来源，例如 `reminder`。
    - `text` \(string, 必填\): 要播出的文本。
    - `priority` \(string, 可选\): `normal` 或 `high`。
    - `interruptPolicy` \(string, 必填\): `wait_current_turn`、`interrupt_output` 或 `reject_if_busy`。
    - `expiresAt` \(string, 可选\): 过期时间，超过后不再播报。
    - `deduplicationKey` \(string, 可选\): 防止同一提醒重复播报。
    - `deviceId` \(string, 必填\): 目标设备 ID。
- **出参 \(Body\)**: `data` 为播报回执，包含 `announcementId`、初始状态 `queued` 和 `accepted`。

#### 13\) 查询主动播报（Get）

- **方法与路径**: `GET /v1/voice/announcements/{announcementId}`
- **说明**: 查询播报处于排队、播放、完成、失败、过期还是取消状态。只有 `completed` 才表示语音已经完整播出。
- **入参 \(Path\)**: `announcementId` \(string, 必填\): 主动播报 ID。
- **出参 \(Body\)**: `data` 包含 `announcementId`、`state`、`accepted`、`startedAt`、`completedAt` 和 `error`。

#### 14\) 取消主动播报（Cancel）

- **方法与路径**: `POST /v1/voice/announcements/{announcementId}/cancel`
- **说明**: 取消尚未完成的播报。已经完成或过期的播报不会重新进入队列。
- **入参 \(Path\)**: `announcementId` \(string, 必填\): 要取消的播报 ID。
- **入参 \(Body\)**: `reason` \(string, 必填\): `user_cancel`、`expired`、`session_close` 或 `provider_error`。
- **出参 \(Body\)**: `data` 为取消结果，包含 `announcementId` 和最终状态。

## 5. 状态与并发

### 5.1 Session 状态

~~~text
closed -> opening -> ready -> closing -> closed
             |
             +-> failed
~~~

### 5.2 Turn 状态

~~~text
created -> capturing -> processing -> speaking -> completed
    |          |            |           |
    +----------+------------+-----------> cancelled
               +------------------------> failed
~~~

### 5.3 Announcement 状态

Announcement 使用 API 接口设计中的独立状态机。它不能与 TurnState 合成一个 is_speaking，因为主动提醒和用户对话可能同时存在。

### 5.4 状态所有权

- VoiceSessionCoordinator 是 Session、Turn、Generation 的唯一写入者。
- AnnouncementPort 是 Announcement 请求状态的入口，最终状态仍由 Coordinator 驱动。
- Provider 和 Device 只能发事件，不能直接修改公共状态。
- UI、IM 和 Diagnostics 只读状态。
