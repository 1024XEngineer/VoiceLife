# 语音模块需求与接口设计 V0

本文定义 VoiceLife V0 语音模块的职责、调用关系和对外接口。这里的“语音模块”不是麦克风或功放板，而是连接小智开发板、XRobot、日程、提醒、记忆、UI 和 IM 的软件交互层。

## 1. 核心目标

语音模块负责四件事：

1. 接收创建会话、开始说话、停止录音和取消等命令。
2. 把设备采集的音频交给 XRobot，再把 XRobot 返回的音频交给设备播放。
3. 把 XRobot 发出的结构化工具调用转给日程、提醒和记忆等业务模块。
4. 把转写、工具结果、播放结果和错误通知给 UI、IM 和诊断模块。

语音模块不负责：

- 不直接修改日程、提醒或记忆数据。
- 不把自然语言直接转换成 SQL 或业务对象。
- 不让业务模块接触 PCM、Opus、Codec、WebSocket 或 XRobot 原始消息。
- 不把“请求已接收”当成“操作已完成”。最终结果必须通过状态或事件确认。

V0 采用以下设计原则：

- 音频数据和控制事件分开传递。
- STT、LLM、TTS 可以由同一个平台提供，也可以拆成可替换的服务。
- 业务能力统一通过 `ToolCall` 接入，不直接处理音频。
- 麦克风、扬声器和网络协议放在适配器内，不进入业务接口。
- 会话状态只由一个协调器维护，避免多个模块同时修改状态。

## 2. 核心概念

| 概念 | 理解 | 作用 |
| --- | --- | --- |
| `AudioDevice` | 耳朵和嘴巴 | 采集麦克风声音并播放回复音频。小智开发板是 V0 的第一个实现。 |
| `SpeechProvider` | 外接大脑 | 把语音转成文字，理解用户意图，决定回复或调用工具。XRobot 是 V0 的第一个实现。 |
| `VoiceSessionCoordinator` | 总调度员 | 统一安排录音、处理、工具调用、播放、取消和结束。 |
| `ToolCall` | 结构化任务单 | 把“创建日程”变成工具名和明确参数。 |
| `ToolGateway` | 派单中心 | 按工具名把任务交给日程、提醒或记忆模块。 |
| `VoiceEvent` | 状态通知 | 告诉 UI、IM 和诊断模块当前发生了什么。 |
| `Announcement` | 主动播报 | 没有用户提问时，由提醒等模块主动请求设备播报一段话。 |

### 2.1 三个关联标识

- **`VoiceSessionID`（会话 ID）**：表示一次完整语音会话，可以理解为“一通电话的编号”。一次会话可以包含多轮问答。它由本地生成，不等同于 XRobot 返回的远端会话 ID。
- **`VoiceTurnID`（轮次 ID）**：表示用户说一句话到系统完成一次回复的过程，可以理解为“这通电话中某一句话的编号”。工具调用必须关联到具体轮次。
- **`Generation`（有效代次）**：表示当前仍然有效的处理版本。开始新一轮、取消或重连时递增，用来识别上一轮迟到的转写和音频。

例如：

```text
Session S1
├── Turn T1：明天下午三点帮我开会
├── Turn T2：提前十五分钟提醒
└── Turn T3：算了，取消刚才的安排
```

如果 T1 使用 `Generation 1`，用户取消后系统进入 `Generation 2`，那么 T1 迟到的转写和回复音频会被丢弃，不能插入新一轮对话。

`Generation` 只能阻止旧的语音结果继续播放，不能回滚已经提交的业务操作。日程模块如果已经保存成功，仍要返回真实结果；语音模块把该结果标记为 `orphanedTurn=true`，再通知 Application 或 IM。

## 3. 核心业务流程

### 3.1 用户通过语音创建日程和提醒

```text
按键或唤醒词
-> 创建 Session 和 Turn
-> 小智开发板开始采集音频
-> XRobot 接收音频并返回最终转写
-> XRobot 发出 ToolCall
-> ToolGateway 把 ToolCall 交给日程或提醒模块
-> 业务模块执行操作并返回 ToolResult
-> ToolResult 返回 XRobot
-> XRobot 生成回复文本和音频
-> 小智开发板播放回复
-> VoiceEvent 发布完成结果
```

例子：用户说“明天下午三点开会，提前十五分钟提醒我”。

1. XRobot 发出 `create_schedule` 和 `add_reminder` 两个 `ToolCall`。
2. 日程模块保存日程，提醒模块保存提醒。
3. 语音模块转发两个结果，并播放 XRobot 返回的确认语音。
4. UI 和 IM 通过 `VoiceEvent` 收到最终结果。

语音模块只负责调度和转发，不直接写日程数据库。

### 3.2 提醒模块发起主动播报

```text
Reminder 到点
-> 提交 Announcement
-> VoiceSessionCoordinator 检查设备和 Provider 是否支持播报
-> 支持：排队或按策略打断当前播放
-> 播放完成后发布 completed 事件
-> 不支持或设备不可用：返回错误
-> Application 决定是否改用 IM 或屏幕通知
```

`accepted` 或 `queued` 只表示语音模块已经接收请求，不表示播报完成。只有状态变为 `completed`，才表示音频已经播放完毕。

当前小智官方 `Protocol` 没有通用的 `PlayTts(text)` 接口。因此，主动播报接口可以先定义完整，但能否通过 XRobot 直接播放文本，必须实测后才能确认。

### 3.3 用户取消或开始新一轮

```text
用户按下停止或再次唤醒
-> 取消当前 Turn
-> Generation 加 1
-> XRobot 停止旧轮次
-> 小智开发板停止旧音频
-> 清理旧代次队列
-> 发布 turn.cancelled
-> 丢弃之后到达的旧转写和旧音频
```

取消必须幂等。重复取消同一个 Turn 仍返回成功，不能恢复旧音频，也不能重复触发业务操作。

如果工具调用已经交给业务模块，取消只能请求业务模块停止，不能保证事务回滚。业务模块若已提交数据，仍返回真实结果。

## 4. 模块调用关系

### 4.1 小智官方架构

以下结构以 `xiaozhi-esp32@e0074e90` 为准：

```text
Button / Wake Word / Board
             |
             v
      Application (singleton)
      - 主任务和设备状态机
      - 分派 stt / tts / llm / mcp 消息
          |                     |
          |                     +----> McpServer ----> Board / Codec Tools
          |
          +----> AudioService <----> AudioCodec <----> MIC / Speaker
          |      采集、AFE/VAD、Opus 编解码、播放队列
          |
          +----> Protocol <========> XRobot Server
                 WebSocket / MQTT    ASR / LLM / TTS
```

音频分为上行和下行两条流：

```text
MIC -> Audio Engine -> Opus Encoder -> Protocol -> Server
Server -> Protocol -> Opus Decoder -> Playback Queue -> Speaker
```

小智官方实现适合单设备固件：调用链短，音频、网络和设备状态都在一个进程内。它的 `Application` 是固件总协调器，不是为日程、提醒、记忆、UI 和 IM 提供的稳定公共接口。

### 4.2 直接照搬小智架构的问题

| 问题 | 对 XE6-15 的影响 |
| --- | --- |
| `Application` 同时管理音频、网络、设备状态、界面和 MCP | 每接入一个业务模块都可能修改中心类，难以单独测试和替换。 |
| 业务模块直接读取 XRobot 的 `stt`、`tts`、`mcp` 消息 | 更换 Provider 或协议版本时，日程、提醒和 UI 都要跟着修改。 |
| 没有对业务模块开放本地 `Session`、`Turn` 和 `Generation` 模型 | 取消、重连后，旧转写、旧音频和迟到的工具结果难以统一判断。 |
| 内部回调不是统一的跨模块事件 | UI、IM 和诊断模块无法从同一接口获取进度和最终结果。 |
| 没有通用的主动文本播报接口 | 提醒模块无法区分“请求已接收”和“已经播放完成”。 |

### 4.3 XE6-15 目标架构

```text
UI / Button / Wake Word
          |                                      Reminder / Application
          v                                                |
  VoiceSession API                                         v
          |                                       Announcement API
          +------------------+-----------------------------+
                             v
                VoiceSessionCoordinator
                  |         |         |         |
                  |         |         |         +----> VoiceEvent
                  |         |         |                  |
                  |         |         |                  +----> UI / IM / Diagnostics
                  |         |         |
                  |         |         +----> ToolGateway <====> Schedule / Reminder / Memory
                  |         |                    ToolCall / ToolResult
                  |         |
                  |         +----> SpeechProvider Adapter
                  |                    |
                  |                    +----> XRobot Protocol <====> XRobot Server
                  |
                  +----> AudioDevice Adapter
                              |
                              +----> Xiaozhi AudioService <----> AudioCodec
```

这套设计保留小智现有的音频和协议链路，只在它与业务模块之间增加稳定接口，不要求增加网络请求，也不要求重写 Opus 编解码和播放队列。

这样设计有四个直接作用：

1. 日程、提醒和记忆只处理 `ToolCall`，不依赖 XRobot 原始协议。
2. `Session + Turn + Generation` 可以统一处理取消、重连和迟到事件。
3. 请求是否接收、业务是否完成、音频是否播完都有各自状态，不再依赖一个全局布尔值。
4. 可以分别用 Mock Provider、Mock Device 和 Mock Tool 测试，不必每次都连接真实开发板。

## API 接口设计 \(V0 - Voice-Centric\)

本节只列其他模块可以调用的接口。XRobot 协议、音频帧、Codec、Provider 回调和设备适配器属于语音模块内部实现，不在这里展开。

以下用 HTTP 方法和路径表达接口语义。如果 V0 最终采用进程内调用，方法名、参数和返回语义保持一致。

### 1. 接口总览

**语音会话**

- `POST /v1/voice/sessions`：创建语音会话。
- `GET /v1/voice/sessions/{sessionId}`：查询语音会话状态。
- `DELETE /v1/voice/sessions/{sessionId}`：关闭语音会话。
- `POST /v1/voice/sessions/{sessionId}/turns`：开始一轮语音输入。
- `POST /v1/voice/sessions/{sessionId}/turns/{turnId}/stop-input`：结束本轮录音。
- `POST /v1/voice/sessions/{sessionId}/turns/{turnId}/cancel`：取消本轮处理或播放。

**事件订阅**

- `GET /v1/voice/events`：订阅语音状态、转写、工具结果、播报结果和错误。

**业务工具接入**

- `POST /v1/voice/tools`：注册业务工具。
- `GET /v1/voice/tools`：查询已注册的工具。
- `POST /v1/voice/tool-calls/{toolCallId}/result`：返回工具执行结果。
- `POST /v1/voice/tool-calls/{toolCallId}/cancel`：请求取消尚未完成的工具调用。

**主动播报**

- `POST /v1/voice/announcements`：提交主动播报。
- `GET /v1/voice/announcements/{announcementId}`：查询播报状态。
- `POST /v1/voice/announcements/{announcementId}/cancel`：取消播报。

### 2. 详细接口参数

#### 1\) 创建语音会话

- **方法与路径**: `POST /v1/voice/sessions`
- **说明**: Application、UI、按键或唤醒词适配器创建一次语音会话。成功后返回 `sessionId`，后续操作都使用这个 ID。
- **入参 \(Body\)**:
    - `requestId` \(string, 必填\): 请求幂等 ID，重试时保持不变。
    - `deviceId` \(string, 必填\): 逻辑设备 ID。
    - `agentId` \(string, 必填\): XRobot Agent 或 Provider 配置 ID。
    - `userId` \(string, 可选\): 当前用户 ID。
    - `trigger` \(string, 必填\): `button`、`wake_word`、`ui` 或 `system`。
    - `locale` \(string, 可选\): 语言和地区，例如 `zh-CN`。
- **出参 \(Body\)**: `data` 包含 `sessionId` 和初始状态 `opening`。

#### 2\) 查询语音会话

- **方法与路径**: `GET /v1/voice/sessions/{sessionId}`
- **说明**: UI 或诊断模块查询会话当前是否可用、正在关闭或已经结束。
- **入参 \(Path\)**:
    - `sessionId` \(string, 必填\): 语音会话 ID。
- **出参 \(Body\)**:
    - `data.sessionId` \(string\): 语音会话 ID。
    - `data.state` \(string\): `opening`、`ready`、`closing`、`closed` 或 `failed`。
    - `data.activeTurnId` \(string, 可选\): 当前正在处理的轮次 ID。
    - `data.lastError` \(object, 可选\): 最近一次错误。

#### 3\) 关闭语音会话

- **方法与路径**: `DELETE /v1/voice/sessions/{sessionId}`
- **说明**: 关闭会话，并停止尚未完成的录音或播放。重复关闭同一会话不会产生第二次操作。
- **入参 \(Path\)**:
    - `sessionId` \(string, 必填\): 要关闭的语音会话 ID。
- **入参 \(Query\)**:
    - `reason` \(string, 可选\): `user_close`、`idle_timeout` 或 `fatal_error`。
- **出参 \(Body\)**: `data` 包含 `sessionId` 和最终状态 `closed`。

#### 4\) 开始一轮语音输入

- **方法与路径**: `POST /v1/voice/sessions/{sessionId}/turns`
- **说明**: 在已有会话中开始接收用户的一句话。一个 Session 可以先后包含多个 Turn，但 V0 同一时间只处理一个 Turn。
- **入参 \(Path\)**:
    - `sessionId` \(string, 必填\): 必须处于 `ready` 状态的会话 ID。
- **入参 \(Body\)**:
    - `requestId` \(string, 必填\): 请求幂等 ID。
    - `inputMode` \(string, 必填\): `push_to_talk`、`wake_word` 或 `continuous`。
    - `interruptPolicy` \(string, 可选, 默认 `reject`\): `reject` 或 `cancel_current`。V0 不支持隐式排队。
    - `wakeWord` \(string, 可选\): `inputMode=wake_word` 时识别到的唤醒词。
- **出参 \(Body\)**: `data` 包含 `turnId` 和初始状态 `capturing`。

#### 5\) 结束本轮录音

- **方法与路径**: `POST /v1/voice/sessions/{sessionId}/turns/{turnId}/stop-input`
- **说明**: 停止本轮麦克风输入，让 XRobot 开始处理已经收到的音频。它不会取消本轮回复。
- **入参 \(Path\)**:
    - `sessionId` \(string, 必填\): 语音会话 ID。
    - `turnId` \(string, 必填\): 要停止录音的轮次 ID。
- **入参 \(Body\)**:
    - `reason` \(string, 必填\): `user_release`、`vad_end` 或 `timeout`。
- **出参 \(Body\)**: `data` 包含 `turnId` 和新状态 `processing`。

#### 6\) 取消本轮语音

- **方法与路径**: `POST /v1/voice/sessions/{sessionId}/turns/{turnId}/cancel`
- **说明**: 取消当前 Turn 的识别、回复或播放。已经由日程、提醒等模块提交的数据不会被语音模块回滚。
- **入参 \(Path\)**:
    - `sessionId` \(string, 必填\): 语音会话 ID。
    - `turnId` \(string, 必填\): 要取消的轮次 ID。
- **入参 \(Body\)**:
    - `reason` \(string, 必填\): `user_cancel`、`new_turn`、`session_close`、`provider_error` 或 `device_error`。
- **出参 \(Body\)**: `data` 包含 `turnId` 和最终状态 `cancelled`。重复取消返回相同结果。

#### 7\) 订阅语音事件

- **方法与路径**: `GET /v1/voice/events`
- **说明**: UI、IM、业务模块和诊断模块通过 SSE 事件流接收会话状态、转写、工具调用、工具结果、播报结果和错误。连接关闭后停止订阅。
- **入参 \(Query\)**:
    - `sessionId` \(string, 可选\): 只订阅指定会话。
    - `turnId` \(string, 可选\): 只订阅指定轮次。
    - `eventType` \(string, 可选\): 按事件类型过滤，例如 `transcript.final`、`tool.call.requested`、`tool.call.completed` 或 `error`。
- **出参 \(Stream\)**: 每条事件包含 `eventId`、`eventType`、`occurredAt`、关联 ID 和 `payload`。

#### 8\) 注册业务工具

- **方法与路径**: `POST /v1/voice/tools`
- **说明**: 日程、提醒或记忆模块声明可供 XRobot Agent 调用的工具。语音模块保存工具定义并负责路由，不执行具体业务。
- **入参 \(Body\)**:
    - `toolName` \(string, 必填\): 工具名称，例如 `create_schedule`。
    - `schemaVersion` \(string, 必填\): 工具参数版本。
    - `description` \(string, 必填\): 提供给 Agent 的工具说明。
    - `inputSchema` \(object, 必填\): 工具入参的 JSON Schema。
    - `ownerModule` \(string, 必填\): 工具所属模块，例如 `schedule`。
- **出参 \(Body\)**: `data` 为注册成功的工具定义，包含 `toolName`、`schemaVersion` 和 `ownerModule`。

#### 9\) 查询业务工具

- **方法与路径**: `GET /v1/voice/tools`
- **说明**: Application 或诊断模块查询已经注册的工具，检查 XRobot Agent 能否调用相应业务能力。
- **入参 \(Query\)**:
    - `ownerModule` \(string, 可选\): 按所属模块过滤。
- **出参 \(Body\)**: `data` 为工具定义数组，每项包含 `toolName`、`schemaVersion`、`description`、`inputSchema` 和 `ownerModule`。

#### 10\) 返回业务工具结果

- **方法与路径**: `POST /v1/voice/tool-calls/{toolCallId}/result`
- **说明**: 日程、提醒或记忆模块执行工具后，把真实结果交回语音模块。语音模块再判断是否把结果送回当前 XRobot Turn。
- **入参 \(Path\)**:
    - `toolCallId` \(string, 必填\): `tool.call.requested` 事件中的工具调用 ID。
- **入参 \(Body\)**:
    - `status` \(string, 必填\): `succeeded`、`failed`、`cancelled` 或 `timed_out`。
    - `result` \(object, 可选\): 成功时的业务结果。
    - `error` \(object, 可选\): 失败时的错误信息。
- **出参 \(Body\)**: `data` 包含 `toolCallId` 和 `accepted`。如果原 Turn 已取消，语音模块仍发布结果事件，并自动标记 `orphanedTurn=true`。

#### 11\) 取消业务工具调用

- **方法与路径**: `POST /v1/voice/tool-calls/{toolCallId}/cancel`
- **说明**: 请求业务模块停止尚未完成的工具调用。这是尽力取消，不代表已经提交的事务会回滚。
- **入参 \(Path\)**:
    - `toolCallId` \(string, 必填\): 要取消的工具调用 ID。
- **入参 \(Body\)**:
    - `reason` \(string, 必填\): 取消原因。
- **出参 \(Body\)**: `data` 包含 `toolCallId` 和 `accepted`。业务模块若已提交事务，仍通过结果接口返回真实结果。

#### 12\) 提交主动播报

- **方法与路径**: `POST /v1/voice/announcements`
- **说明**: 提醒模块或 Application 提交一段需要播放的文本。请求被接收不等于已经播放完成。
- **入参 \(Body\)**:
    - `requestId` \(string, 必填\): 播报请求的幂等 ID。
    - `sourceModule` \(string, 必填\): 请求来源，例如 `reminder`。
    - `text` \(string, 必填\): 要播放的文本。
    - `priority` \(string, 可选, 默认 `normal`\): `normal` 或 `high`。
    - `interruptPolicy` \(string, 必填\): `wait_current_turn`、`interrupt_output` 或 `reject_if_busy`。
    - `expiresAt` \(string, 可选, ISO 8601\): 过期时间，超过后不再播放。
    - `deduplicationKey` \(string, 可选\): 防止同一提醒重复播报。
    - `deviceId` \(string, 必填\): 目标设备 ID。
- **出参 \(Body\)**: `data` 包含 `announcementId`、`accepted` 和 `state`。接收成功时 `accepted=true`、`state=queued`；能力不支持或设备不可用时返回 `accepted=false`、`state=rejected` 和错误信息。

#### 13\) 查询主动播报

- **方法与路径**: `GET /v1/voice/announcements/{announcementId}`
- **说明**: 查询播报当前处于排队、准备、播放、完成、失败、过期、取消还是拒绝状态。只有 `completed` 表示音频已经播放完毕。
- **入参 \(Path\)**:
    - `announcementId` \(string, 必填\): 主动播报 ID。
- **出参 \(Body\)**: `data` 包含 `announcementId`、`state`、`accepted`、`startedAt`、`completedAt` 和 `error`。

#### 14\) 取消主动播报

- **方法与路径**: `POST /v1/voice/announcements/{announcementId}/cancel`
- **说明**: 取消尚未完成的播报。重复取消返回相同结果，已经完成或过期的播报不会重新进入队列。
- **入参 \(Path\)**:
    - `announcementId` \(string, 必填\): 要取消的主动播报 ID。
- **入参 \(Body\)**:
    - `reason` \(string, 必填\): `user_cancel`、`expired`、`session_close` 或 `provider_error`。
- **出参 \(Body\)**: `data` 包含 `announcementId` 和取消后的状态。

## 5. 状态

### 5.1 Session 状态

```text
(未创建) -> opening -> ready -> closing -> closed
                |         |         |
                +---------+---------+-> failed
```

### 5.2 Turn 状态

```text
created -> capturing -> processing -> speaking -> completed
    |          |            |           |
    +----------+------------+-----------+-> cancelled
               +------------+-----------+-> failed
```

### 5.3 Announcement 状态

```text
queued -> preparing -> playing -> completed
   |          |          |
   +----------+----------+-> failed / expired / cancelled

提交时无法接收 -> rejected
```
