# 语音服务设计文档

> 日期：2026-07-27
> 定位：L2 智能会话核心层的音频子系统，提供语音输入捕捉、语音输出播放、唤醒词检测和语音交互状态管理
> 依赖：L4 操作系统适配层（AudioPlayer、本地定时任务）、L5 SQLite、云端灵矽 ASR/TTS

---

## 一、服务定位

语音服务是 VoiceLife 与用户之间的音频桥梁。它不处理业务逻辑（日程增删改查归 Schedule 服务，IM 推送归 IM 服务），只负责三件事：

1. **听**——麦克风采集 → Opus 编码 → 上传云端 ASR
2. **说**——云端 TTS 音频 → 解码 → 喇叭播放
3. **唤醒**——本地 ESP-SR 引擎检测"小鹏小鹏"

### 与其他三个服务的关系

```
用户语音
    ↓
┌─────────────────────────────────┐
│          语音服务（本模块）       │
│  听：mic → opus → 云端 ASR      │
│  说：云端 TTS → 解码 → speaker  │
│  唤醒：ESP-SR "小鹏小鹏"        │
└───┬──────────────┬─────────────┘
    │ 识别文本      │ 播放指令
    ▼               ▼
┌─────────┐   ┌──────────┐   ┌──────────┐
│ Schedule │   │    IM    │   │    L5    │
│  服务    │   │   服务   │   │ 持久化层  │
│ (PR#79) │   │ (PR#78)  │   │ (PR#70)  │
└─────────┘   └──────────┘   └──────────┘
```

| 调用方向 | 说明 |
| --- | --- |
| 语音服务 → 云端灵矽 | 上传 Opus 音频流；接收 ASR 文本 / TTS 音频 |
| Schedule 服务 → 语音服务 | 提醒触发时调用 `PlayTts(text)` 播报；Function Calling 完成时调用 `PlayTts(text)` 反馈结果 |
| IM 服务 → 语音服务 | 无直接调用。语音和 IM 并行，互不阻塞 |
| L5 → 语音服务 | 语音服务不直接访问 L5。状态通过事件传递给 Schedule 服务落盘 |

## 二、音频管道

```
[麦克风] → [I2S 驱动] → [AEC 回声消除] → [VAD 人声检测]
                                                    ↓ 有人声
                                            [Opus 编码器]
                                                    ↓
                                            [WebSocket → 灵矽 ASR]
                                                    ↓
                                            [识别文本 → LLM]

[灵矽 TTS 音频] → [WebSocket 接收] → [Opus 解码器] → [I2S 驱动] → [喇叭]
```

### 管道元素

| 元素 | 实现 | 说明 |
| --- | --- | --- |
| 音频采集 | ESP32 I2S 驱动 + MEMS 麦克风 | 16kHz, 16bit, 单声道 |
| 回声消除（AEC） | ESP-SR AEC 模块 | 消除喇叭播放对麦克风的干扰，实现全双工 |
| 人声检测（VAD） | ESP-SR VAD（vadnet） | 判断是否有人在说话，降低静音上传带宽 |
| Opus 编码/解码 | libopus（ESP-IDF 组件） | 60ms 帧长，压缩比 ~10:1 |
| 云端通信 | 灵矽 WebSocket 协议 | opus 音频上行 + TTS 音频下行 |

## 三、对外接口

语音服务向上层（应用主循环 / Schedule 服务）暴露以下接口：

### 3.1 唤醒词管理

```cpp
// 初始化唤醒词引擎，注册回调
bool InitWakeWord(const std::string& model_path);

// 开始监听唤醒词（上电后自动调用）
void StartWakeWordDetection();

// 停止监听唤醒词（进入对话模式时调用）
void StopWakeWordDetection();

// 唤醒词检测回调
using WakeWordCallback = std::function<void()>;
void SetOnWakeWordDetected(WakeWordCallback callback);
```

### 3.2 音频对话

```cpp
// 开始录音并上传音频流到灵矽 ASR。ASR 结果通过回调返回
void StartListening();

// 停止录音。通常在 VAD 检测到静音后自动调用，或手动打断
void StopListening();

// ASR 识别结果回调
using AsrCallback = std::function<void(const std::string& text, bool is_final)>;
void SetOnAsrResult(AsrCallback callback);
```

### 3.3 语音播放（供 Schedule 服务调用）

```cpp
// 播放 TTS 文本。将文本发送给灵矽 TTS，接收音频并播放
// 返回 true 表示已开始播放（非阻塞——播放异步进行）
bool PlayTts(const std::string& text);

// 停止当前播放（用户打断时调用）
void StopPlayback();

// 播放状态回调
enum class PlaybackState { IDLE, PLAYING, INTERRUPTED, COMPLETED };
using PlaybackCallback = std::function<void(PlaybackState state)>;
void SetOnPlaybackStateChanged(PlaybackCallback callback);

// 设置音量（0-100）
void SetVolume(int volume);
```

### 3.4 会话管理

```cpp
// 开始一次语音对话（唤醒词检测 → 停止唤醒 → 开始录音 → ASR → LLM → TTS → 恢复唤醒）
void StartConversation();

// 结束一次语音对话
void EndConversation();

// 当前会话状态
enum class ConversationState { IDLE, WAKING, LISTENING, PROCESSING, SPEAKING };
ConversationState GetConversationState();
```

## 四、与 Schedule 服务的接口契约

### 4.1 Schedule 调用语音服务

Schedule 服务在以下场景调用语音服务的 `PlayTts(text)`：

| 场景 | 调用示例 |
| --- | --- |
| 提醒触发 | `PlayTts("提醒：今天 19:00 开会")` |
| 创建日程成功 | `PlayTts("妥了，今天下午7点提醒你开会")` |
| 查询日程结果 | `PlayTts("今天还有2件事。下午3点和pz开会，晚上7点产品评审")` |
| 操作确认询问 | `PlayTts("确定取消今天7点的会吗？")` |
| 冲突提示 | `PlayTts("下午四点已有项目评审，仍然把会改到四点吗？")` |
| 错误反馈 | `PlayTts("没找到这条日程")` |

> Schedule 服务不关心 TTS 的实现细节——它只调用 `PlayTts(text)`，语音服务负责编码、传输、解码、播放全链路。

### 4.2 语音服务触发 Schedule 服务

语音服务通过回调将 ASR 识别文本传递给上层，由上层（应用主循环）调用灵矽 LLM 进行 Function Calling，灵矽返回的 Function Call 再调度 Schedule 服务的对应接口：

```
ASR 文本 → 灵矽 LLM（Function Calling）→ create_schedule(...)
                                         → query_schedule(...)
                                         → update_schedule(...)
                                         → delete_schedule(...)
```

> 语音服务不直接调用 Schedule 服务。它只产出"用户说了什么"→ 交给上层调度。

## 五、与 IM 服务的关系

| 对比项 | 语音服务 | IM 服务 |
| --- | --- | --- |
| 通道方向 | 用户 ↔ 设备（双向） | 设备 → 用户手机（单向推送）+ 用户手机 → 设备（卡片回调） |
| 时效性 | 实时、不可回看 | 持久、可回看 |
| 内容 | TTS 短语音播报 | 结构化 IM 卡片 |
| 并行关系 | 同一业务事件同时驱动语音播报和 IM 推送 | |

> 语音和 IM 是同一业务事件的两个并行出口。任何一个通道失败不阻塞另一个。

## 六、与 L5 持久化层的关系

语音服务**不直接访问 L5**。原因：

1. 语音服务是无状态的音频管道——它不持有业务数据
2. 操作结果（创建/修改/删除的记录）由 Schedule 服务写入 L5
3. 会话上下文（ConversationContext）驻留内存，不落盘（PR #70 已定义）

> 如果未来需要记录语音交互日志（如 ASR 识别准确率统计），由上层应用将日志事件转发给 L5 的 `receipts` 表，不经过语音服务。

## 七、完整交互时序

### 7.1 创建日程

```
用户：   "小鹏小鹏，明天下午7点开会"
         ↓
语音：   唤醒词检测 → StartConversation()
         ↓
语音：   StartListening() → 音频上传灵矽 ASR
         ↓
灵矽：   ASR 返回文本 "明天下午7点开会"
         ↓
上层：   调用灵矽 LLM → Function Calling → create_schedule(event="开会", start_time="2026-07-28T19:00+08:00")
         ↓
Schedule: 创建日程 → SQLite 写入 → 返回 schedule_id=1
         ↓
上层：   PlayTts("妥了，明天下午7点提醒你开会") → 语音服务播放
         ↓
上层：   并行触发 IM 服务推送回执卡片
         ↓
语音：   EndConversation() → 恢复唤醒词检测
```

### 7.2 提醒触发

```
Schedule: 本地定时器到期 → 读取日程 "开会" (19:00)
         ↓
Schedule: PlayTts("提醒：今天 19:00 开会") → 语音服务播放
         ↓
Schedule: 并行触发 IM 服务推送提醒卡片
         ↓
用户：   "小鹏小鹏，十分钟后再提醒"
         ↓
语音：   唤醒词打断播放 → StopPlayback()
         ↓
语音：   StartListening() → ASR 文本 → 灵矽 LLM → snooze_reminder(reminder_id=1, snooze_minutes=10)
         ↓
Schedule: 更新提醒状态 → PlayTts("好，10分钟后再提醒你")
```

## 八、状态机

```
┌─────────┐  唤醒词检测  ┌─────────┐  开始录音  ┌───────────┐
│  IDLE   │────────────→│ WAKING  │──────────→│ LISTENING │
└─────────┘             └─────────┘            └─────┬─────┘
     ▲                                               │ ASR 完成
     │                    ┌───────────┐               ▼
     │    播放完成        │ SPEAKING  │←┐     ┌─────────────┐
     └───────────────────└─────┬─────┘ │     │ PROCESSING  │
                               │       │     └─────────────┘
                               │ 用户打断 (唤醒词)  │ LLM 返回结果
                               └───────────────────┘
```

| 状态 | 说明 | 允许的操作 |
| --- | --- | --- |
| `IDLE` | 空闲，等待唤醒词 | 唤醒词检测 |
| `WAKING` | 检测到唤醒词，准备对话 | 开始录音 |
| `LISTENING` | 正在录音并上传音频 | 停止录音、音量调节 |
| `PROCESSING` | ASR 完成，等待 LLM + Function Calling | 无用户交互 |
| `SPEAKING` | 正在播放 TTS | 打断（唤醒词）、音量调节 |

> 状态转换由语音服务内部管理。上层通过 `GetConversationState()` 查询当前状态，通过 `PlayTts()` 触发 `SPEAKING` 状态。

| 本模块接口 | 调用方 | 触发场景 |
| --- | --- | --- |

## 十一、设计决策

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| 语音服务是否直接调用 Schedule 服务？ | **否**——只产出 ASR 文本 | 保持单一职责。调度逻辑在上层应用 |
| 语音服务是否直接访问 L5？ | **否** | 语音服务无状态。业务数据归 Schedule 服务 |
| TTS 播放是否阻塞？ | **否**——异步非阻塞 | 播放期间仍需响应唤醒词打断 |
| 全双工还是半双工？ | **全双工**（需 AEC 硬件支持） | 用户可在 TTS 播放时说"小鹏小鹏"打断 |
| 唤醒词仅限 P2 还是全局？ | **仅限 P2 提醒场景** | P1 创建/查询通过物理按键触发（按下说话），避免误唤醒 |
