
# 语音模块

定义 VoiceLife 的语音模块。这里的 语音模块 不是一块麦克风或功放板，而是连接用户语音、XRobot、日程、提醒等的软件交互层。

## 共同模式

    1. 有一个会话编排器，统一管理一轮语音从开始到结束。
    2. 音频数据和控制事件分开传递。
    3. STT、LLM、TTS 可以是三个可替换阶段，也可以由平台提供。
    4. 业务模块通过 Tool/Function/MCP 接入，不直接处理音频。
    5. 麦克风、扬声器和网络媒体属于适配层，不应该进入日程、提醒接口。

## 1. 核心目标

语音模块解决的事：

    1. 接收开始、停止、取消等会话命令。
    2. 把设备音频交给语音服务，再把服务返回的音频交给设备播放。
    3. 把语音服务产生的工具调用转给日程、提醒等业务模块。
    4. 把会话状态、转写、工具结果、播报结果和错误通知给 其他 模块。

## 2. 核心概念定义

    - VoiceSessionID（语音会话标识）
        - 本地生成。
        - 表示一次从打开语音能力到关闭的会话，可包含多轮对话。
        - 不等同于 XRobot 返回的 provider_session_id。

    - VoiceTurnID（语音轮次标识）
        - 表示用户说一句话到系统完成一次回复的过程。
        - 一次 Session 可以包含多个 Turn。
        - 日程创建、提醒关闭等工具调用必须关联到一个 Turn。

    - Generation（会话代次）
        - 每次取消、重连或开始新 Turn 时递增。
        - 旧代次迟到的 Provider 转写和音频一律丢弃，避免上一轮内容串到下一轮。
        - 已经分发给业务模块的 ToolCall 不能靠 Generation 回滚；其最终结果仍要发给 Application/IM，并标记 orphaned_turn。

    - SpeechProvider（语音服务提供方）
        - 对上提供统一的转写、回复、工具调用、语音输出和取消事件。
        - XRobot 是一个实现。
        - Provider 内部可以是 STT -> LLM -> TTS，也可以是实时语音模型；业务模块不感知这种差异。

    - AudioDevice（音频设备）
        - 只负责提供音频输入帧、接收音频输出帧和声明设备能力。
        - 当前连接的小智开发板是 V0 的第一个实现。
        - AudioDevice 不知道日程、提醒、MCP 或用户意图。

    - ToolCall（工具调用）
        - Provider/Agent 要求业务模块执行的一次结构化操作。
        - 包含 tool_call_id、tool_name、arguments、deadline 和上下文标识。
        - ToolGateway 负责路由，业务模块负责参数规则、事务和幂等。

    - Announcement（主动播报）
        - 由提醒或其他业务模块主动发起的一次语音输出请求。
        - 它不是普通对话回复，必须有 request_id、优先级、过期时间、打断策略和完成回执。

    - VoiceEvent（语音事件）
        - 语音模块对外发布的统一事件。
        - UI、IM、诊断和业务编排层通过事件了解进度，不直接读取语音模块内部状态。

## 3. 核心业务流程

### 流程一：用户说话并调用日程模块

    ~~~text
    按键 / 唤醒词
    -> VoiceSessionPort.StartTurn
    -> AudioDevicePort 开始采集
    -> SpeechProviderPort 接收音频
    -> Provider 返回 transcript.final
    -> Provider 发出 tool.call.requested
    -> ToolGateway 调用 Schedule ToolHandler
    -> Schedule 返回结构化结果
    -> ToolGateway 把 tool result 交回 Provider
    -> Provider 返回回复文本和音频
    -> AudioDevicePort 播放
    -> VoiceEventPort 发布 turn.completed
    ~~~

    例子：

    ~~~text
    用户：“明天下午三点开会，提前十五分钟提醒我”
    Provider/Agent：
    1. 调 create_schedule
    2. 调 add_reminder
    业务模块：
    1. Schedule 保存日程并返回 schedule_id
    2. Reminder 保存提醒并返回 reminder_id
    语音模块：
    1. 只负责转发两次 ToolCall 和 ToolResult
    2. 播放 Provider 返回的确认语音
    3. 发布工具结果和播放完成事件
    ~~~

    语音模块不能自己拼接 SQL，也不能根据自然语言直接修改日程对象。

    ### 流程二：提醒模块发起主动播报

    ~~~text
    Reminder 到点
    -> AnnouncementPort.Enqueue
    -> VoiceSessionCoordinator 检查当前会话和 Provider 能力
    -> 可播报：排队或按策略打断，完成后回执
    -> 不可播报：返回 UNSUPPORTED / UNAVAILABLE
    -> Application 决定是否改走 IM 或屏幕通知
    ~~~
## 4. 模块调用关系

### 4.1 小智官方架构：单体固件内的中心编排

以 `xiaozhi-esp32@e0074e90` 为准，小智官方的软件调用关系如下：

~~~text
Button / Wake Word / Board
             |
             | StartListening / StopListening / ToggleChatState
             v
      Application (singleton)
      - 主任务和 EventGroup
      - DeviceStateMachine
      - 直接分派 tts / stt / llm / mcp JSON
          |                     |
          |                     +------> McpServer ------> Board / Codec Tools
          |
          +------> AudioService <------> AudioCodec <------> MIC / Speaker
          |        采集、AFE/VAD、Opus 编解码、播放队列
          |
          +------> Protocol <==========> XRobot Server
                   WebSocket / MQTT       ASR / LLM / TTS
                   audio / listen /       stt / tts / mcp /
                   abort / mcp            binary audio
~~~

音频数据在官方实现中是两条独立流：

~~~text
MIC -> Audio Engine -> Encode Queue -> Opus Encoder -> Send Queue -> Protocol -> Server
Server -> Protocol -> Decode Queue -> Opus Decoder -> Playback Queue -> Speaker
~~~

这种设计对单设备固件是合理的：调用链短，音频队列和设备状态都在一个进程内。但 `Application` 是固件总协调器，不是供其他模块调用的稳定语音 API。

直接把小智 `Application` 当语音模块的问题：
- 中心类承担太多跨模块职责，每接入日程、提醒或 IM 都可能要修改固件中心类，难以独立测试和替换
- Provider 协议会泄漏给业务模块，如果 Schedule 或 UI 直接读这些字段，以后更换 XRobot 或协议版本时要跟着改业务代码

### 4.1 目标架构：保留小智音频链路，拆出跨模块接口

~~~text
UI / Button / Wake Word
          |                                      Reminder / Application
          v                                                |
  VoiceSessionPort                                         v
          |                                       AnnouncementPort
          +------------------+-----------------------------+
                             v
                VoiceSessionCoordinator
                  |         |         |         |
                  |         |         |         +----> VoiceEventPort
                  |         |         |                  |
                  |         |         |                  +----> UI / IM / Diagnostics
                  |         |         |
                  |         |         +----> ToolGateway <====> Schedule / Reminder / Memory
                  |         |                    ToolCall / ToolResult
                  |         |
                  |         +----> SpeechProviderPort
                  |                    |
                  |                    +----> XRobot Adapter
                  |                              |
                  |                              +----> Xiaozhi Protocol <====> XRobot Server
                  |
                  +----> AudioDevicePort
                              |
                              +----> Xiaozhi Audio Adapter
                                        |
                                        +----> AudioService <----> AudioCodec
~~~

## API 接口设计

### 1. 接口总览

**语音会话管理 (VoiceSessionPort)**

- `StartSession(StartSessionRequest) -> StartSessionResult` —— 打开一次语音会话。
- `StartTurn(StartTurnRequest) -> StartTurnResult` —— 开始接收一轮用户输入。
- `StopInput(voice_session_id, voice_turn_id, reason) -> Result` —— 结束当前 Turn 的音频输入。
- `CancelTurn(voice_session_id, voice_turn_id, reason) -> Result` —— 取消当前 Turn 及其未完成输出。
- `CloseSession(voice_session_id, reason) -> Result` —— 关闭 Session 并释放 Provider/Device 资源。
- `GetSnapshot(voice_session_id) -> VoiceSnapshot` —— 读取当前状态快照。

**统一事件通知 (VoiceEventPort)**

- `Publish(VoiceEvent) -> Result` —— 由语音模块内部发布统一事件。
- `Subscribe(VoiceEventFilter, VoiceEventHandler) -> SubscriptionID` —— UI、IM、Memory、Diagnostics 订阅事件。
- `Unsubscribe(SubscriptionID) -> Result` —— 取消订阅。

**业务工具调用 (ToolGateway)**

- `RegisterTool(ToolDefinition, ToolHandler) -> Result` —— Schedule、Reminder、Memory 注册业务工具。
- `ListTools() -> ToolDefinition[]` —— 返回当前版本的 Tool Registry。
- `Dispatch(ToolCallRequest) -> Future<ToolCallResult>` —— 将 Provider 的工具调用路由给业务模块。
- `Cancel(tool_call_id, reason) -> Result` —— 尽力取消 ToolCall，不承担事务回滚。

**主动播报 (AnnouncementPort)**

- `Enqueue(AnnouncementRequest) -> AnnouncementReceipt` —— Reminder 或 Application 请求一次主动播报。
- `Cancel(announcement_id, reason) -> Result` —— 取消尚未完成的播报。
- `Get(announcement_id) -> AnnouncementSnapshot` —— 查询播报快照。

**内部适配器接口 (不对业务模块开放)**

- `SpeechProviderPort` —— 将 XRobot、Realtime 或其他 Provider 转成统一语音事件。
- `AudioDevicePort` —— 将当前小智板转成统一音频输入、输出和设备错误事件。

### 2. 详细接口参数

#### 1\) 公共请求上下文

- **对象**: `RequestContext`
- **说明**: 所有需要跨模块追踪的请求共用此上下文。会话级命令没有 Turn 时，`voice_turn_id` 可以为空。
- **字段**:
    - `request_id` (string, 必填): 创建或入队请求的幂等请求号。
    - `voice_session_id` (string, 可选): 本地语音会话 ID。
    - `voice_turn_id` (string, 可选): 本地语音轮次 ID。
    - `generation` (integer, 必填): 会话代次；旧代次的 Provider 转写和音频必须丢弃。
    - `trace_id` (string, 必填): 跨模块诊断链路 ID。
    - `issued_at` (string, ISO 8601, 必填): 请求发出时间。
    - `deadline_at` (string, ISO 8601, 可选): 调用方截止时间；为空时使用被调用方自己的上限。
- **示例**:

~~~json
{
  "request_id": "req_01J...",
  "voice_session_id": "vs_01J...",
  "voice_turn_id": "vt_01J...",
  "generation": 7,
  "trace_id": "trace_01J...",
  "issued_at": "2026-07-29T15:00:00+08:00",
  "deadline_at": "2026-07-29T15:00:10+08:00"
}
~~~
#### 2\) 发布和订阅语音事件

- **方法与路径**: `VoiceEventPort.Publish`、`VoiceEventPort.Subscribe`
- **说明**: 语音模块向外发布会话状态、转写、Tool、输出、播报和错误事件。外部模块只订阅，不直接写入公共状态。
- **入参 (Publish)**:
    - `event` (VoiceEvent, 必填): 统一事件对象。
- **入参 (Subscribe)**:
    - `filter` (VoiceEventFilter, 必填): 可按 `event_type`、`voice_session_id`、`voice_turn_id`、`request_id` 和 `source` 过滤。
    - `handler` (VoiceEventHandler, 必填): 订阅者的有界队列处理器。
- **出参**:
    - `Publish`: `Result`；只表示事件进入分发，不等待 UI、IM 或日志写入完成。
    - `Subscribe`: `subscription_id` (string)。
    - `Unsubscribe`: `Result`。
- **发布权限**: `VoiceSessionCoordinator` 是状态类事件的唯一发布者；慢订阅者不能反向阻塞采集、Provider 回调或播放。
- **VoiceEvent 字段**:
    - `event_id` (string, 必填): 事件唯一 ID。
    - `event_type` (string, 必填): 事件类型。
    - `occurred_at` (string, ISO 8601, 必填): 事件发生时间。
    - `voice_session_id`、`voice_turn_id`、`generation` (按场景必填): 关联会话、轮次和代次。
    - `request_id`、`trace_id`、`source` (string): 请求、诊断和来源信息。
    - `payload` (object): 事件专属内容，必须限长并脱敏。
- **公共事件**:

| `event_type` | 关键 payload | 主要订阅者 |
| --- | --- | --- |
| `session.state.changed` | previous、current、reason | UI、Diagnostics |
| `turn.state.changed` | previous、current、reason | UI、IM、Diagnostics |
| `transcript.partial` | text | UI |
| `transcript.final` | text | UI、可选 Memory Adapter |
| `tool.call.requested` | tool_call_id、tool_name | Diagnostics |
| `tool.call.completed` | tool_call_id、tool_name、status、result、orphaned_turn | Application、IM、Diagnostics |
| `tool.call.failed` | tool_call_id、tool_name、status、error、orphaned_turn | Application、IM、Diagnostics |
| `output.started` | output_id | UI、Diagnostics |
| `output.completed` | output_id、played_duration_ms | UI、Diagnostics |
| `announcement.state.changed` | announcement_id、state、reason | Reminder、IM、UI |
| `error` | error | UI、Application、Diagnostics |
| `diagnostic.stale_event` | dropped_event_type、old_generation | Diagnostics |

同一个 ToolCall 只发布一个终态事件。`transcript.partial` 只用于展示，不能触发写操作；只有 Provider 明确提交的 `transcript.final` 或 ToolCall 才能进入业务流程。

#### 3\) 创建语音会话

- **方法与路径**: `VoiceSessionPort.StartSession(StartSessionRequest)`
- **调用方**: Application 或 UI。
- **说明**: 创建一个本地 VoiceSession，并异步打开 Provider 与 AudioDevice。
- **入参**:
    - `request_id` (string, 必填): 幂等请求号。
    - `device_id` (string, 必填): 逻辑设备标识，不是 USB VID/PID。
    - `user_id` (string, 可选): 当前已知用户标识。
    - `agent_id` (string, 必填): XRobot/Agent 配置标识。
    - `locale` (string, 可选): 语言和地区。
    - `trigger` (enum, 必填): `button`、`wake_word`、`ui`、`system`。
    - `metadata` (object, 可选): 限长扩展字段，不放 Token。
- **出参**:

~~~json
{
  "accepted": true,
  "voice_session_id": "vs_01J...",
  "state": "opening",
  "error": null
}
~~~

同一个 `request_id` 重试时返回同一个 `voice_session_id`。Provider 握手完成后，再通过 `session.state.changed` 发布 `ready`。

#### 4\) 开始语音轮次

- **方法与路径**: `VoiceSessionPort.StartTurn(StartTurnRequest)`
- **调用方**: UI、按键适配器或唤醒词适配器。
- **说明**: 在 ready 的 Session 中创建一轮输入。
- **入参**:
    - `request_id` (string, 必填): 幂等请求号。
    - `voice_session_id` (string, 必填): 已处于 `ready` 的 Session。
    - `input_mode` (enum, 必填): `push_to_talk`、`wake_word`、`continuous`。
    - `wake_word` (string, 可选): `input_mode=wake_word` 时可带。
    - `interrupt_policy` (enum, 可选): `reject`、`cancel_current`、`queue`。
- **出参**:

~~~json
{
  "accepted": true,
  "voice_turn_id": "vt_01J...",
  "generation": 7,
  "state": "capturing",
  "error": null
}
~~~

- `reject`: 当前正在播放时返回 `TURN_BUSY`。
- `cancel_current`: 先取消旧 Turn，再创建新 Turn。
- `queue`: V0 不支持，返回 `UNSUPPORTED_CAPABILITY`，不隐式排队。

#### 5\) 结束输入

- **方法与路径**: `VoiceSessionPort.StopInput(voice_session_id, voice_turn_id, reason)`
- **调用方**: 按键适配器、VAD 适配器或 UI。
- **说明**: 停止当前 Turn 的音频采集，让 Turn 从 `capturing` 进入 `processing`。
- **入参**:
    - `voice_session_id`、`voice_turn_id` (string, 必填): 目标会话和轮次；二者组合是幂等身份。
    - `reason` (enum, 必填): `user_release`、`vad_end`、`timeout`。
- **出参**: `Result`。重复调用返回同一最终语义，不再次提交音频结束信号。

#### 6\) 取消语音轮次

- **方法与路径**: `VoiceSessionPort.CancelTurn(voice_session_id, voice_turn_id, reason)`
- **说明**: 取消当前 Turn 及其未完成输出；取消不回滚已经提交的业务事务。
- **入参**:
    - `voice_session_id`、`voice_turn_id` (string, 必填): 目标会话和轮次。
    - `reason` (enum, 必填): `user_cancel`、`new_turn`、`session_close`、`provider_error`、`device_error`。
- **处理顺序**:
    1. `Generation` 递增。
    2. 通知 Provider 取消旧 Turn。
    3. 停止旧播放并清理旧代次队列。
    4. 尚未分发的 ToolCall 标记为 `cancelled`；已分发的调用向 ToolHandler 请求取消。
    5. 已提交的业务写操作不能由语音模块回滚，最终 ToolResult 仍发布给 Application/IM，但不再送回旧 Provider Turn。
    6. 发布 `turn.state.changed=cancelled`。
- **出参**: `Result`。重复取消同一 `voice_turn_id` 返回成功。

#### 7\) 关闭会话和读取快照

- **方法与路径**:
    - `VoiceSessionPort.CloseSession(voice_session_id, reason)`
    - `VoiceSessionPort.GetSnapshot(voice_session_id)`
- **说明**: 关闭会话释放 Provider/Device 资源；快照只用于展示和诊断，业务流程仍以事件和调用结果为准。
- **入参**:
    - `voice_session_id` (string, 必填): 目标会话。
    - `reason` (enum, CloseSession 必填): `user_close`、`session_close`、`fatal_error`。
- **出参 (GetSnapshot)**:

~~~json
{
  "voice_session_id": "vs_01J...",
  "session_state": "ready",
  "active_turn_id": null,
  "turn_state": null,
  "announcement_state": null,
  "provider_state": "ready",
  "device_state": "ready",
  "generation": 7
}
~~~

#### 8\) 发起业务工具调用

- **方法与路径**: `ToolGateway.Dispatch(ToolCallRequest)`
- **调用方**: `VoiceSessionCoordinator`；Provider Adapter 只负责协议转换。
- **说明**: 将 Provider 的 `tools/call` 转成业务模块可处理的结构化请求。
- **入参 (Body)**:

~~~json
{
  "tool_call_id": "tc_01J...",
  "tool_name": "create_schedule",
  "schema_version": "v0",
  "arguments": {
    "event": "项目周会",
    "start_time": "2026-07-30T15:00:00+08:00"
  },
  "context": {
    "voice_session_id": "vs_01J...",
    "voice_turn_id": "vt_01J...",
    "generation": 7,
    "trace_id": "trace_01J..."
  },
  "deadline_at": "2026-07-29T15:00:10+08:00",
  "idempotency_key": "provider-call-42"
}
~~~

- **字段约束**:
    - `tool_call_id`、`tool_name`、`schema_version`、`arguments` (必填)。
    - `deadline_at` (可选): 超时后由 ToolGateway 结束本次调用。
    - `idempotency_key` (必填): 业务模块用于防止重复副作用。
- **出参**: `Future<ToolCallResult>`。
- **路由规则**: ToolGateway 只校验名称、版本、截止时间和重复 ID；ToolHandler 负责业务参数、事务和幂等。

#### 9\) 返回业务工具结果

- **方法与路径**: `ToolGateway.Dispatch -> ToolCallResult`
- **说明**: 业务 ToolHandler 的最终结果。结果既给 Application/IM，也在当前 Generation 仍有效时交回 Provider。
- **出参 (Body)**:

~~~json
{
  "tool_call_id": "tc_01J...",
  "tool_name": "create_schedule",
  "status": "succeeded",
  "orphaned_turn": false,
  "result": {
    "created": true,
    "schedule_id": 12
  },
  "error": null,
  "completed_at": "2026-07-29T15:00:03+08:00"
}
~~~

- `status` 取 `succeeded`、`failed`、`cancelled`、`timed_out`。
- 失败时 `result` 为空，`error` 使用“错误契约”中的统一结构。
- `orphaned_turn=true` 表示原 Turn 已取消，但业务结果仍然有效；不再调用旧 Provider Turn 的 `SubmitToolResult`。
- `Cancel` 是尽力取消，不是事务回滚：事务已提交时必须返回真实的 `succeeded` 或 `failed`，不能伪造 `cancelled`。

**当前项目的 Tool 候选**:

| 业务模块 | Tool 候选 | 语音模块做什么 | 语音模块不做什么 |
| --- | --- | --- | --- |
| Schedule | create_schedule、query_schedule、update_schedule、delete_schedule、query_recent_operations、undo_operation | 路由请求和返回结果 | 不判断时间冲突，不写日程库 |
| Reminder | add_reminder、update_reminder、remove_reminder、snooze_reminder、dismiss_reminder、query_reminder | 路由用户对提醒的操作 | 不运行提醒状态机，不决定重试次数 |
| Memory | search_memory、archive_turn（名称待 Memory 模块定稿） | 可在 Turn 前后调用适配器 | 不保存长期记忆，不把录音当记忆 |
| IM | 通常不注册为语音 Tool | 把业务结果事件交给 Application | 不直接发企微/短信，不管理送达重试 |

PR #79 和 PR #82 对时间类型、返回结构和部分工具语义仍有差异。V0 实现前必须先冻结一个 `schema_version`，不能在 Adapter 里补字段掩盖冲突。

#### 10\) 注册和取消业务工具

- **方法与路径**:
    - `ToolGateway.RegisterTool(ToolDefinition, ToolHandler)`
    - `ToolGateway.ListTools()`
    - `ToolGateway.Cancel(tool_call_id, reason)`
- **说明**: 业务模块注册 Handler，Coordinator 负责调用和取消关联。
- **入参**:
    - `ToolDefinition`、`ToolHandler` (RegisterTool 必填)。
    - `tool_call_id`、`reason` (Cancel 必填)。
- **出参**:
    - `RegisterTool`、`Cancel`: `Result`。
    - `ListTools`: `ToolDefinition[]`。
- **取消语义**:
    - 尚未交给 Handler 时，可直接返回最终状态 `cancelled`。
    - 已进入 Handler 时，只转发取消请求；返回成功只表示业务模块收到请求。
    - 已提交事务时，最终结果仍通过 VoiceEventPort 发布给 Application/IM，并按情况设置 `orphaned_turn=true`。

#### 11\) 其他模块调用方式

- **说明**: 业务模块只通过下表的公共 Port 和 VoiceEvent 交互，不接触 PCM、Opus、WebSocket 或设备句柄。
- **调用约束**:

| 模块 | 调用语音模块 | 接收语音模块 | 约束 |
| --- | --- | --- | --- |
| Memory | 可选：提供会话上下文 | `transcript.final`、`turn.completed` | V0 可不接；只能异步归档，不阻塞播放 |
| IM | 无需直接控制音频 | ToolResult、AnnouncementResult、最终错误 | 由 Application 生成可回看的回执 |
| UI / Display | StartSession、StartTurn、StopInput、CancelTurn | 状态、转写、工具进度、错误 | `transcript.partial` 只展示 |
| Config | 提供 Provider、设备和日志配置 | 配置应用结果 | Token 不进入事件和普通日志 |
| Diagnostics | GetSnapshot、Subscribe | 全量脱敏事件和指标 | 不保存原始音频和完整敏感文本 |

- **结果归属**: Schedule、Reminder、Memory 负责各自业务数据和幂等；IM 负责回执格式和发送；语音模块只负责关联 ID、路由和事件发布。

#### 12\) 请求主动播报

- **方法与路径**: `AnnouncementPort.Enqueue(AnnouncementRequest)`
- **调用方**: Reminder 或 Application。
- **说明**: 提交一条与当前对话独立的主动语音输出请求。播报结果通过 `VoiceEventPort` 的 `announcement.state.changed` 发送，不在 AnnouncementPort 上维护第二套订阅协议。
- **入参 (Body)**:

~~~json
{
  "request_id": "reminder-5-trigger-3",
  "source_module": "reminder",
  "content": {
    "type": "text",
    "text": "项目周会将在十五分钟后开始"
  },
  "priority": "high",
  "interrupt_policy": "wait_current_turn",
  "expires_at": "2026-07-29T09:50:00+08:00",
  "deduplication_key": "reminder:5:2026-07-29T09:45:00+08:00",
  "target": {
    "device_id": "xiaozhi-01"
  },
  "metadata": {
    "reminder_id": 5
  }
}
~~~

- `content.type` (V0): 只允许 `text` 或 `audio_ref`；`audio_ref` 必须是受控资源引用。
- `interrupt_policy`:

| 值 | 行为 |
| --- | --- |
| `wait_current_turn` | 当前 Turn 结束后播报；到期则 `expired` |
| `interrupt_output` | 只打断当前语音输出，不取消已经提交的业务 Tool |
| `reject_if_busy` | 当前有 Turn 或其他播报时立即拒绝 |

- **出参**: `AnnouncementReceipt`。

#### 13\) 查询或取消主动播报

- **方法与路径**:
    - `AnnouncementPort.Cancel(announcement_id, reason)`
    - `AnnouncementPort.Get(announcement_id)`
- **入参**:
    - `announcement_id` (string, 必填): 播报 ID，也是取消操作的幂等身份。
    - `reason` (enum, Cancel 必填): `user_cancel`、`expired`、`session_close`、`provider_error`。
- **出参**:
    - `Cancel`: `Result`。
    - `Get`: `AnnouncementSnapshot`。
- **出参 (Get)**:

~~~json
{
  "announcement_id": "ann_01J...",
  "state": "playing",
  "accepted": true,
  "provider": "xrobot",
  "started_at": "2026-07-29T09:45:02+08:00",
  "completed_at": null,
  "error": null
}
~~~

- **约束**: 已是 `completed`、`expired` 或 `cancelled` 的播报不会重新排队。

#### 14\) 主动播报回执和状态

- **对象**: `AnnouncementReceipt`
- **出参 (Body)**:

~~~json
{
  "accepted": true,
  "announcement_id": "ann_01J...",
  "state": "queued",
  "provider": null,
  "error": null
}
~~~

- **状态流转**:

~~~text
queued -> preparing -> playing -> completed
   |          |           |
   +--------> cancelled <-+
   +--------> expired
   +--------> failed
~~~

- `accepted=true`: 请求通过校验并进入队列，不表示已经开始或完成播放。
- `queued`: 等待能力准备、当前 Turn 结束或前一个播报完成。
- `preparing`: Provider/设备准备输出，尚未开始播放。
- `playing`: 设备已经开始输出音频。
- `completed`: 音频完整输出，Reminder 才能记为语音送达。
- `failed`: 断线、合成失败或播放失败；业务模块可以走 IM 降级。
- `expired`: 超过 `expires_at`，不再播放过时提醒。
- `cancelled`: `completed` 前被取消，不能记为送达。
- 如果能力检查已确认 Provider 不支持主动播报，`Enqueue` 直接返回 `accepted=false` 和 `ANNOUNCEMENT_UNSUPPORTED`，不先接受再异步改口。

#### 15\) Provider 适配器接口（内部）

- **方法与路径**: `SpeechProviderPort`
- **说明**: 业务模块不直接调用此接口；它把 XRobot、Realtime 或其他 Provider 转成统一事件。
- **方法**:

~~~text
GetCapabilities() -> SpeechProviderCapabilities
OpenSession(ProviderSessionRequest) -> ProviderSession
StartTurn(ProviderTurnRequest) -> Result
PushAudio(AudioFrame) -> Result
EndInput(voice_turn_id) -> Result
SubmitToolResult(ToolCallResult) -> Result
CancelTurn(voice_turn_id, generation, reason) -> Result
RequestSpeech(SpeechRequest) -> Result
CloseSession(reason) -> Result
Events() -> Stream<ProviderEvent>
~~~

- **能力声明**:

~~~json
{
  "streaming_input": "supported",
  "partial_transcript": "unknown",
  "tool_call": "supported",
  "streaming_output_audio": "supported",
  "cancel_turn": "supported",
  "scripted_speech": "unknown",
  "proactive_session": "unknown"
}
~~~

每个能力使用 `supported`、`unsupported`、`unknown` 三态；`unknown` 按不支持处理。

- **XRobot Adapter 映射**:

| 统一接口/事件 | XRobot/xiaozhi 映射 |
| --- | --- |
| OpenSession | WebSocket connect + hello |
| StartTurn | listen state=start |
| PushAudio | 二进制 Opus 音频 |
| EndInput | listen state=stop |
| CancelTurn | abort + 本地 generation 隔离 |
| provider.transcript | stt JSON |
| provider.output.state | tts start/sentence_start/stop |
| provider.output.audio | 下行二进制音频 |
| provider.tool.call | mcp JSON-RPC tools/call |
| SubmitToolResult | mcp JSON-RPC result/error |
| RequestSpeech(text) | 当前未确认，返回 UNSUPPORTED |

XRobot 的 remote session_id 只保存在 Adapter 内并进入诊断上下文，不替代 `VoiceSessionID`。
