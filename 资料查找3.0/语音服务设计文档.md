
# 语音模块

定义 VoiceLife 的语音模块。这里的 语音模块 不是一块麦克风或功放板，而是连接用户语音、XRobot、日程、提醒等的软件交互层。

## 共同模式

    1. 有一个会话编排器，统一管理一轮语音从开始到结束。
    2. 音频数据和控制事件分开传递。
    3. STT、LLM、TTS 可以是三个可替换阶段，也可以由平台提供。
    4. 业务模块通过 Tool/Function/MCP 接入，不直接处理音频。
    5. 麦克风、扬声器和网络媒体属于适配层，不应该进入日程、提醒接口。

## 1. 核心目标

语音模块解决的事：

    1. 接收开始、停止、取消等会话命令。
    2. 把设备音频交给语音服务，再把服务返回的音频交给设备播放。
    3. 把语音服务产生的工具调用转给日程、提醒等业务模块。
    4. 把会话状态、转写、工具结果、播报结果和错误通知给 其他 模块。

## 2. 核心概念定义

    - VoiceSessionID（语音会话标识）
        - 本地生成。
        - 表示一次从打开语音能力到关闭的会话，可包含多轮对话。
        - 不等同于 XRobot 返回的 provider_session_id。

    - VoiceTurnID（语音轮次标识）
        - 表示用户说一句话到系统完成一次回复的过程。
        - 一次 Session 可以包含多个 Turn。
        - 日程创建、提醒关闭等工具调用必须关联到一个 Turn。

    - Generation（会话代次）
        - 每次取消、重连或开始新 Turn 时递增。
        - 旧代次迟到的 Provider 转写和音频一律丢弃，避免上一轮内容串到下一轮。
        - 已经分发给业务模块的 ToolCall 不能靠 Generation 回滚；其最终结果仍要发给 Application/IM，并标记 orphaned_turn。

    - SpeechProvider（语音服务提供方）
        - 对上提供统一的转写、回复、工具调用、语音输出和取消事件。
        - XRobot 是一个实现。
        - Provider 内部可以是 STT -> LLM -> TTS，也可以是实时语音模型；业务模块不感知这种差异。

    - AudioDevice（音频设备）
        - 只负责提供音频输入帧、接收音频输出帧和声明设备能力。
        - 当前连接的小智开发板是 V0 的第一个实现。
        - AudioDevice 不知道日程、提醒、MCP 或用户意图。

    - ToolCall（工具调用）
        - Provider/Agent 要求业务模块执行的一次结构化操作。
        - 包含 tool_call_id、tool_name、arguments、deadline 和上下文标识。
        - ToolGateway 负责路由，业务模块负责参数规则、事务和幂等。

    - Announcement（主动播报）
        - 由提醒或其他业务模块主动发起的一次语音输出请求。
        - 它不是普通对话回复，必须有 request_id、优先级、过期时间、打断策略和完成回执。

    - VoiceEvent（语音事件）
        - 语音模块对外发布的统一事件。
        - UI、IM、诊断和业务编排层通过事件了解进度，不直接读取语音模块内部状态。

## 3. 核心业务流程

### 流程一：用户说话并调用日程模块

    ~~~text
    按键 / 唤醒词
    -> VoiceSessionPort.StartTurn
    -> AudioDevicePort 开始采集
    -> SpeechProviderPort 接收音频
    -> Provider 返回 transcript.final
    -> Provider 发出 tool.call.requested
    -> ToolGateway 调用 Schedule ToolHandler
    -> Schedule 返回结构化结果
    -> ToolGateway 把 tool result 交回 Provider
    -> Provider 返回回复文本和音频
    -> AudioDevicePort 播放
    -> VoiceEventPort 发布 turn.completed
    ~~~

    例子：

    ~~~text
    用户：“明天下午三点开会，提前十五分钟提醒我”
    Provider/Agent：
    1. 调 create_schedule
    2. 调 add_reminder
    业务模块：
    1. Schedule 保存日程并返回 schedule_id
    2. Reminder 保存提醒并返回 reminder_id
    语音模块：
    1. 只负责转发两次 ToolCall 和 ToolResult
    2. 播放 Provider 返回的确认语音
    3. 发布工具结果和播放完成事件
    ~~~

    语音模块不能自己拼接 SQL，也不能根据自然语言直接修改日程对象。

    ### 流程二：提醒模块发起主动播报

    ~~~text
    Reminder 到点
    -> AnnouncementPort.Enqueue
    -> VoiceSessionCoordinator 检查当前会话和 Provider 能力
    -> 可播报：排队或按策略打断，完成后回执
    -> 不可播报：返回 UNSUPPORTED / UNAVAILABLE
    -> Application 决定是否改走 IM 或屏幕通知
    ~~~
