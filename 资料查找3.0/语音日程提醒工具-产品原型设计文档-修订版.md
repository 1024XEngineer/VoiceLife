# 语音日程提醒工具：产品原型设计文档
---

## 1. 交互蓝图
P1（记一件事 / 提醒一件事 / 查询一件事）
P2（提醒触发、预告、打断、追问详情、即时响应）
P3（修改、跳过、删除、撤销）

### 1.1 能力链
P1 -> P2 -> P3 
 ^           |
 |-----------

### 1.2 核心交互规则
1. 语音交互为主，消息回执为辅
2. 语音只做短反馈和必要追问，完整信息进 IM
3. P2 响应需先说唤醒词"小鹏小鹏"，再跟指令；可打断当前播报
4. 高风险操作必须确认，不允许静默执行
5. 操作后必须可撤销（15 分钟内，跨会话计入）

### 1.3 语音人设
语音反馈像一个办事稳当的助手：温和但有结论，简短但不糊弄。高风险动作认真确认，不替用户猜。

### 1.4 风险分级

| 风险 | 示例 | 处理方式 |
| --- | --- | --- |
| 低风险 | 记一件事、创建日程、查询、关闭提醒、稍后提醒 | 直接执行，短语音反馈，IM 留回执 |
| 中风险 | 修改唯一命中的单次日程、跳过一次周期事项 | 说明影响对象，执行后回读，保留撤销 |
| 高风险 | 删除、终止周期、修改整个系列、候选不唯一、单次事项被跳过 | 执行前确认，不允许静默处理 |

## 2. 本期范围

### 2.1 本期做什么
1. 记一件事：无时间维度的记录（停车位、取件码等）
2. 提醒一件事：用户说时间，系统到时提醒
3. 查询一件事：问"我要干什么"，系统回答
4. 一句话可包含多条事项（"车停A130，明天10点开会"→一条记录+一条提醒）
5. 提醒触发时：预告（提前10min）+ 提醒（到时），可用唤醒词打断并追问详情
6. 删除或修改周期时明确提醒

### 2.2 本期明确不做
1. 复杂的 UI 交互
2. 跨时区
3. 不提供日历 GUI
4. 第三方平台日历同步
5. 复杂的周期性提醒（仅支持每天/每周/每月）
6. 全天候录音和等待识别
7. 外部信号监控
8. 修改其他人的日程或共享日历

## 3. P1 原型：记一件事 / 提醒一件事 / 查询一件事

### 流程 1：一句话创建提醒事项

```text
用户：我今天下午7点要开一个半小时的会
系统语音：今天下午7点提醒你开会。

IM 回执：
  已创建提醒
  标题：开会
  时间：今天 19:00 - 20:30
  操作：撤销 / 查看今天日程
```

### 流程 2：记一件事（无时间维度）

```text
用户：我车停在A130了
系统语音：记下了，车停在A130。

IM 回执：
  已记录
  内容：车停在A130
  类型：记录
  操作：删除
```

### 流程 3：一句话包含多条

```text
用户：我车停A130了，另外明天早上10点提醒我开会
系统语音：记下了车停在A130，明天10点提醒你开会。

IM 回执：
  [记录] 车停在A130
  [提醒] 明天 10:00 开会
```

### 流程 4：一句话修正提醒

```text
用户：我今天7点的会推迟到7.30
系统语音：今天7点的会改到7:30。

IM 回执：
  已修改日程
  事项：开会
  原时间：今天 19:00
  新时间：今天 19:30
  操作：撤销修改
```

### 流程 5：一句话删除

```text
用户：我今天7点的会不开了
系统语音：确定取消今天7点的会吗？
用户：确定。
系统语音：已取消。

IM 回执：
  已删除日程
  事项：开会
  时间：今天 19:00
  操作：撤销删除
```

### 流程 6：查询事项

```text
用户：我今天7点要干什么
系统语音：今天7点和pz开会。

IM 回执：
  今天 19:00 - 20:30
  事项：和pz开会
```

### 流程 7：查询全部

```text
<!-- 0条 -->
用户：我今天还要干什么
系统语音：今天没有其他安排了。

<!-- 1-3条 -->
用户：我今天还要干什么
系统语音：今天还有2件事。下午3点和pz开会，晚上7点产品评审。

IM 回执：
  今天剩余（2条）
  15:00 和pz开会
  19:00 产品评审

<!-- 超过3条 -->
用户：我今天还要干什么
系统语音：今天还有5件事，最近一件是下午3点和pz开会。我把列表发你。
```

## 4. P2 原型：提醒触发与即时响应

<!-- 唤醒词"小鹏小鹏"+指令。预告提前10min，提醒到点触发。 -->

### 流程 8：提醒触发后关闭

```text
系统语音：提醒：今天 19:00 开会。

用户：小鹏小鹏，知道了。

系统语音：好的。

IM 回执：
  提醒已关闭
  事项：开会
  时间：今天 19:00
```

### 流程 9：稍后提醒

```text
系统语音：提醒：15分钟后开始周会。

用户：小鹏小鹏，十分钟后再提醒。

系统语音：好，10分钟后再提醒你。

IM 回执：
  提醒已推迟
  事项：周会
  新提醒：10分钟后
```
```text
用户：小鹏小鹏，晚点提醒我。

系统语音：晚多久？十分钟、半小时还是一小时？
```

### 流程 10：打断提醒并追问详情

```text
系统语音：提醒：今天 15:00 到 17:00 产品会议。

用户：小鹏小鹏，会议地点在哪？

系统语音：在阳明M01。
```

### 流程 11：多条提醒同时到达

```text
系统语音：现在是下午三点。您共有两个排程：开会日程和跳舞提醒事项。

用户：小鹏小鹏，一个小时后再提醒我跳舞吧。

系统语音：好的。开会日程的提醒已关闭，跳舞提醒一小时后提醒你。
```

### 流程 12：IM 受控回复

```text
IM 回执：
  提醒：客户拜访
  时间：今天 14:30
  按钮：[知道了] [10分钟后提醒] [30分钟后提醒]

用户点击：[10分钟后提醒]

IM 更新：
  已推迟至 14:40
```

## 5. P3 原型：已有日程变更与周期控制

<!-- 冲突处理复用 P1 流程。撤销窗口 15 分钟，跨会话计入。 -->

### 流程 13：修改单次日程

```text
用户：把今天和pz的会改到下午四点。

系统语音：和pz的会已改到今天下午四点。

IM 回执：
  已修改日程
  事项：和pz开会
  原时间：今天 15:00
  新时间：今天 16:00
```

### 流程 14：周期范围确认

```text
用户：把每周五的周报改到周六上午。
系统语音：这是每周重复事项。只改本周，还是以后都改？
用户：以后都改。
系统语音：行，从本周开始改到每周六。上午几点？
```

### 流程 15：跳过一次

```text
<!-- 首次跳过 -->
用户：这周周报跳过一次。
系统语音：妥了，只跳过这周五这一次，下周五还会提醒。

IM 回执：
  已跳过本次
  事项：提交周报
  跳过：本周五 17:00
  下次提醒：下周五 17:00
  操作：撤销跳过
```

```text
<!-- 重复跳过 -->
用户：这周周报跳过一次。
系统语音：这周已经跳过了，没重复操作。
```

### 流程 16：单次事项的"跳过"

```text
用户：跳过明天下午三点和pz的会。
系统语音：这是单次日程，跳过就等于取消。确定取消吗？
用户：确定。
系统语音：已取消明天下午三点和pz的会，可以撤销。
```

### 流程 17：暂停或终止周期

```text
<!-- 暂停 -->
用户：出差这三天先暂停背单词提醒。
系统语音：我会暂停今天到周五的背单词提醒，周六恢复。确定吗？
用户：确定。
系统语音：妥了，周六恢复背单词提醒。
```

```text
<!-- 终止 -->
用户：以后不用再提醒我提交周报了。
系统语音：这会停止之后所有周报提醒，确定终止吗？
用户：确定。
系统语音：已终止周报周期提醒，15分钟内还能撤销恢复。
```

### 流程 18：删除日程

```text
<!-- 明确命中 -->
用户：删掉今天下午三点和pz的会。
系统语音：已删除今天下午三点和pz的会。删错了就说撤销。

IM 回执：
  已删除日程 / 事项：和pz开会 / 时间：今天 15:00 / 操作：撤销删除
```

```text
<!-- 模糊命中 -->
用户：删掉明天的项目会。
系统语音：我找到两个相关日程，先别删错。我发你选一下。

IM 候选：1. 明天 10:00 项目周会 / 2. 明天 15:00 项目复盘会
```

### 流程 19：修改后时间冲突

<!-- 冲突处理复用 P1 的冲突检测约定 -->

```text
用户：把今天和pz的会改到下午四点。
系统语音：下午四点已有项目评审。仍然把pz的会改到四点吗？
用户：还是改。
系统语音：改好了，两条日程会重叠，我在回执里标出来。
```

### 流程 20：撤销

```text
用户：撤销刚才的修改。
系统语音：恢复好了，pz的会已经回到原时间。

IM 回执：
  已撤销修改
  事项：和pz开会
  恢复为：今天 15:00
```

```text
<!-- 超时 -->
用户：撤销昨天删的那个会。
系统语音：已经超过15分钟，不能撤销了。要不要重新创建一条？
```

```text
<!-- 连续第二次撤销 -->
用户：撤销。
系统语音：没有更多可撤销的操作了。
```

## 6. 异常处理

| 状态 | 语音处理 | IM 处理 |
| --- | --- | --- |
| 没听清 | "我没听清，你再说一遍。" | 展示已识别到的部分字段 |
| 缺少必要信息 | "这个安排预计多久？" | 留待补字段，不创建不完整日程 |
| 未提供时间 | 转为记录事项，追问"需要设置提醒时间吗？" | 创建为记录类型 |
| 时间已过 | "这个时间已经过了。要我记下来还是改个时间？" | 展示选项 |
| 找不到目标日程 | "没找到这条，我发你今天日程你确认下是哪条。" | 展示当天候选列表 |
| 多个候选日程 | "相关的有点多，我发你列表选。" | 展示最多5条候选 |
| 查询结果为空 | "今天没有日程。" | 显示空状态和创建入口 |
| 多条提醒同时触发 | "现在是X点，您共有N个排程：A和B。" | 每条提醒单独一条回执 |
| 用户未回应提醒 | 1min 无回应自动推迟 | 保留未响应记录 |
| 操作执行失败 | "这次没改成，原日程没变。" | 显示失败原因和重试入口 |
| IM 发送失败 | 语音正常播报，后续补发 | 恢复后补发或标记失败 |
| 撤销超时（>15min） | "已经超过15分钟，不能撤销了。要不要重新创建？" | 提供重新创建入口 |
| 连续撤销 | "没有更多可撤销的操作了。" | 无 |

## 7. 验收标准

1. 产品不是日历 GUI，而是语音日程提醒工具。
2. 用户能记一件事（无时间）和提醒一件事（有时间），一句话可包含多条。
3. 发现时间冲突时，系统在创建或修改前提示。
4. 提醒语音默认只播标题和发生时间，不播地点和备注。
5. P2 响应需先说唤醒词"小鹏小鹏"；可打断播报追问详情。
6. 周期事项变更必须说明影响范围：仅本次 / 后续 / 整个系列。
7. 单次事项的"跳过"解释为取消，执行前必须确认。
8. 删除、终止、范围不明操作必须先确认。
9. 修改、跳过、删除、终止完成后有 IM 回执和撤销入口。
10. 撤销窗口 15 分钟，跨会话计入；超时拒绝；无更多可撤销操作时拒绝。
11. 多条提醒同时到达时，语音播报总数和事项名称。
