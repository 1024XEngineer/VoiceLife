# 灵矽平台接入可行性调查报告

> 日期：2026-07-27
> 调查对象：https://linx.qiniu.com/docs/
> 结论：**灵矽与小智 hello 握手格式兼容，具备接入条件。**需完成真实设备联通测试后hello 握手格式兼容。

---

## 一、核心发现

灵矽文档目录直接包含「开源小智固件接入指南」——这意味着灵矽**专门为小智做了适配**，不是我们去找灵矽对接，而是灵矽已经在小智生态里了。三份关键文档确认了完整兼容性：

| 文档 | 地址 | 内容 |
| --- | --- | --- |
| WebSocket 协议 | `/xrobot/platform/websocket` | hello 握手、opus 音频流、JSON 文本消息 |
| 端侧 MCP 协议 | `/xrobot/mcp/hardware-mcp` | JSON-RPC 2.0 tools/list、tools/call |
| 小智固件接入 | `/xrobot/guide/xiaozhi-firmware` | 编译→烧录→设备绑定三步接入 |
| 智能体提示指南 | `/xrobot/guide/灵矽智能硬件智能体提示指南` | 6 模块 System Prompt 设计框架 |

## 二、协议兼容性逐项对比

### 2.1 WebSocket 握手

| 对比项 | 小智源码 | 灵矽文档 | 兼容？ |
| --- | --- | --- | --- |
| 端点 | NVS 中的 `url` 字段 | `wss://xrobo-io.qiniuapi.com/v1/ws/` | 改 URL 即可 |
| 认证 | `Authorization: Bearer <token>` | 完全相同 | 兼容 |
| 设备标识 | `Device-Id` + `Client-Id` | 完全相同 | 兼容 |
| 协议版本 | `Protocol-Version: 1` | 完全相同 | 兼容 |

### 2.2 Hello 消息

小智源码发送的 hello：
```json
{
  "type": "hello", "version": 1,
  "features": { "mcp": true },
  "transport": "websocket",
  "audio_params": {
    "format": "opus", "sample_rate": 16000,
    "channels": 1, "frame_duration": 60
  }
}
```

灵矽文档期望的 hello：**字段名、类型、值完全一致。** 灵矽额外支持 `play_buffer_duration` 和 PCM 格式——前者是可选增强，后者小智不需要改。

### 2.3 音频格式

| 对比项 | 小智 | 灵矽 | 兼容？ |
| --- | --- | --- | --- |
| 编码 | Opus | Opus（也支持 PCM） | 完全兼容 |
| 采样率 | 16000 Hz | 16000 Hz | 完全兼容 |
| 声道 | 1（单声道） | 1 | 完全兼容 |
| 帧时长 | 60ms | 60ms | 完全兼容 |

### 2.4 MCP 协议（JSON-RPC 2.0）

小智 `mcp_server.cc` 已实现的：

| 方法 | 小智源码 | 灵矽文档 | 兼容？ |
| --- | --- | --- | --- |
| `initialize` | 接收并响应 | 灵矽主动发送 | **需要确认**小智是否已实现 |
| `tools/list` | 返回已注册的工具列表 | 灵矽调用获取工具 | 已实现 |
| `tools/call` | 执行工具并返回结果 | 灵矽调用执行工具 | 已实现 |

> `initialize` 方法如果小智源码未实现，需要补 ~20 行代码（参考灵矽文档示例）。

### 2.5 工具描述管理

灵矽提供了 REST API（`/v1/device/tools`）用于自定义设备工具的**描述文本**——注意这不是工具本身的实现，而是告诉 LLM "这个工具是干什么的"。工具的实现仍然在小智源码的 `InitializeTools()` 里注册。

流程：
```
1. 在小智源码中注册工具（AddTool）
2. 在灵矽控制台通过 API 或界面为工具添加中文描述
3. LLM 根据描述决定何时调用哪个工具
```

## 三、接入步骤（预计半天）

### 第 1 步：注册灵矽账号 + 创建智能体

访问 https://linx.qiniu.com/ → 注册 → 创建智能体 → 获取 API Token。

### 第 2 步：修改 WebSocket URL

小智源码中需要改 URL、Token，并完成设备绑定和 OTA 激活：

```cpp
// 方案 A：在 NVS 中配置（推荐，无需改代码）
// 通过串口命令或 Web 配网界面设置：
//   websocket.url = wss://xrobo-io.qiniuapi.com/v1/ws/
//   websocket.token = <灵矽 API Token>

// 方案 B：硬编码（开发阶段）
// 直接在 settings 默认值中写死 URL
```

### 第 3 步：配置 VoiceLife 工具描述

在灵矽控制台通过设备工具描述 API 注册我们的五大服务：

| 工具名 | 描述 |
| --- | --- |
| `calendar.create_event` | 创建一条日程，需要标题和时间 |
| `calendar.query_events` | 查询指定日期范围的日程 |
| `calendar.modify_event` | 修改已有日程的时间/标题/地点 |
| `calendar.delete_event` | 删除指定日程 |
| `reminder.skip_once` | 跳过本次周期提醒，不影响后续 |
| `reminder.snooze` | 推迟本次提醒 N 分钟 |
| `calendar.undo` | 撤销最近一次操作 |

### 第 4 步：编译 + 烧录 + 测试

```bash
idf.py set-target esp32s3
idf.py build
idf.py -p /dev/cu.usbmodem* flash monitor
```

对着设备说"小鹏小鹏"，观察串口日志确认 WebSocket 连接成功。

## 四、VoiceLife 特有的工具设计

VoiceLife 需要的五大领域服务映射到灵矽 MCP 工具：

| 领域服务 | MCP 工具名 | 参数 |
| --- | --- | --- |
| 日历服务 | `calendar.create_event` | title, start_time, end_time, location, notes |
| 日历服务 | `calendar.query_events` | keyword, start_from, start_to |
| 提醒服务 | `reminder.dismiss` | reminder_id |
| 提醒服务 | `reminder.snooze` | reminder_id, snooze_minutes |
| 撤销服务 | `system.undo_last` | 无（撤销最近操作） |
| 变更服务 | `calendar.modify_event` | schedule_id, field, new_value |
| 变更服务 | `calendar.delete_event` | schedule_id |
| 备忘录服务 | `memo.record` | content |
| 备忘录服务 | `memo.query` | keyword |

> 这些工具在设备端 `InitializeTools()` 中注册，在灵矽控制台配置中文描述，LLM 就能理解何时调用。

## 五、System Prompt 设计

灵矽提供了 6 模块提示词框架，VoiceLife 的 System Prompt 按此结构填入：

```
# 人格
你是小鹏，一个办事稳当的语音日程助手。温和、简短、有结论。

# 环境
你在用户的 ESP32 智能设备上运行，通过语音和 IM 回执双通道服务。

# 语调
简短直接，确认时认真。不说废话，不在删除时开玩笑。

# 目标
帮用户记事项、设提醒、查日程。一句话完成操作，不反复追问。

# 防护栏
删除和终止操作必须确认。不替用户猜意图。不保存密码和证件号。

# 工具
[上述 9 个 MCP 工具的完整 schema]
```

## 六、结论

| 维度 | 结论 |
| --- | --- |
| 协议兼容性 | hello 握手格式一致；`initialize` 方法需连通测试确认；opus 音频参数匹配 |
| 接入工作量 | 预计半天（改 URL + Token + 工具描述 + System Prompt）。需预留 1 天处理设备绑定和 OTA 激活流程 |
| 需要改小智源码吗 | 大概率不需要改动通信协议层；需固定小智 commit/tag 和板级配置后确认 |
| 风险 | 低。灵矽有专门的小智固件接入文档，但设备绑定、OTA 激活、MCP initialize 流程需实机验证 |
