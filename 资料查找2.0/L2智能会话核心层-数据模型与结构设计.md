# L2 智能会话核心层数据模型与结构设计

本文给 Issue #65 的 L2 部分定边界：L2 不保存日程业务事实，只保存一次语音交互需要的会话状态、工具调用计划、确认上下文和播报结果。日程、提醒、周期、撤销、回执等事实模型仍由 L3/L5 负责。

下一步应按本文把 L2 拆成可入库的空骨架代码：类型、接口、模块调用链先固定，ASR/LLM/TTS 和 L3 业务实现可以先用桩接上。

## 2. L2 边界

### 2.1 L2 负责什么

L2 负责一次语音交互从输入到输出的编排：

1. 接收 L1 的语音输入、IM 受控操作或通知事件。
2. 调 ASR 得到用户文本。
3. 维护当前会话上下文，例如“这个”“刚才那条”“当前提醒”指向谁。
4. 调 LLM Function Calling，得到结构化工具调用。
5. 通过本地服务调用分发器调用 L3。
6. 根据 L3 结果生成短语音反馈和 IM 回执引用。
7. 调 TTS，把要播报的内容交给 L4 音频播放。

### 2.2 L2 不负责什么

这些能力不放在 L2：

- 不直接读写 SQLite。
- 不实现日程冲突算法。
- 不展开周期实例。
- 不决定提醒是否到期。
- 不保存长期记忆。
- 不生成业务回执内容的最终事实，只转发 L3 返回的结果。
- 不绕过 L3 执行删除、终止、跳过、撤销等高风险操作。

这个边界的好处是：语音 Agent 可以换模型、换 ASR、换 TTS，但日程事实和业务规则不会跟着漂。

## 3. L2 模块结构

```text
L1 UI / IM / Notification Action
        |
        v
VoiceTurnController
        |
        +--> ASRAdapter
        |
        +--> DialogueContextStore
        |
        +--> LLMOrchestrator
        |       |
        |       v
        |   ToolRegistry
        |       |
        |       v
        +--> LocalServiceDispatcher ----> L3 local services
        |
        +--> ResponseComposer
        |
        +--> TTSAdapter ----> L4 AudioPlayer
```

| 模块 | 职责 | 对外接口 |
| --- | --- | --- |
| `VoiceTurnController` | 管一轮语音输入、打断、停止、错误恢复 | `startTurn`、`appendAudio`、`stopTurn`、`interruptTurn` |
| `ASRAdapter` | 把音频转文本 | `transcribe(stream): TranscriptResult` |
| `DialogueContextStore` | 保存短期上下文和待确认动作 | `getContext`、`updateContext`、`clearExpired` |
| `LLMOrchestrator` | 组织系统提示词、上下文和工具 Schema，得到工具调用或追问 | `plan(turn): AgentPlan` |
| `ToolRegistry` | 定义 L2 可调用的业务语义工具，不暴露 SQLite 表 | `listTools`、`validateCall` |
| `LocalServiceDispatcher` | 把工具调用转发给 L3，并统一处理成功、失败、确认令牌 | `dispatch(call): ToolResult` |
| `ResponseComposer` | 把 ToolResult 变成语音短句、IM 回执引用、下一步追问 | `compose(result): AgentReply` |
| `TTSAdapter` | 把语音短句转为播放任务 | `speak(reply): TtsJob` |
| `GuardrailPolicy` | 拦截敏感记录、越权工具、伪造确认、跨层调用 | `checkInput`、`checkToolCall`、`checkReply` |

## 4. 核心数据模型

下面是 L2 需要固化的模型。字段名按 TypeScript 草案写，后续可以直接落到 `src/voice-agent/types.ts`。

### 4.1 VoiceSession

`VoiceSession` 表示一个用户在当前设备上的短期会话。它不等同于用户账号，也不做长期历史。

```ts
type VoiceSessionState =
  | "idle"
  | "listening"
  | "transcribing"
  | "planning"
  | "dispatching"
  | "awaiting_user"
  | "speaking"
  | "error";

interface VoiceSession {
  id: string;
  deviceId: string;
  channel: "voice" | "im_action" | "notification_action";
  state: VoiceSessionState;
  timeZone: string; // MVP 固定 Asia/Shanghai
  activeTurnId: string | null;
  context: DialogueContext;
  createdAt: string;
  updatedAt: string;
  expiresAt: string;
}
```

建议：会话上下文默认 10 分钟过期。过期后用户再说“刚才那个”，系统必须重新查找候选项，不能猜。

### 4.2 VoiceTurn

`VoiceTurn` 表示用户一次输入和系统一次响应。

```ts
type VoiceTurnState =
  | "started"
  | "asr_done"
  | "planned"
  | "tool_dispatched"
  | "reply_ready"
  | "spoken"
  | "interrupted"
  | "failed";

interface VoiceTurn {
  id: string;
  sessionId: string;
  source: "microphone" | "im_button" | "system_due_event";
  state: VoiceTurnState;
  audioMeta?: AudioInputMeta;
  transcript?: TranscriptResult;
  plan?: AgentPlan;
  toolCalls: ToolCallEnvelope[];
  toolResults: ToolResultEnvelope[];
  reply?: AgentReply;
  startedAt: string;
  finishedAt: string | null;
}

interface AudioInputMeta {
  sampleRate: number;
  channels: number;
  codec: "pcm" | "opus" | "platform";
}
```

L2 可以保存转写文本用于本轮判断，但不保存原始录音。需要写入回执的用户原话，由 L3 在 `OperationReceipt` 里保存结构化快照。

### 4.3 TranscriptResult

```ts
interface TranscriptResult {
  text: string;
  language: "zh-CN" | "en" | "unknown";
  confidence: number | null;
  isFinal: boolean;
  receivedAt: string;
}
```

低置信度不直接执行高风险操作。比如 ASR 把“删掉”听成“稍后”，L2 必须让 LLM 和 L3 走确认流程，而不是自己补判断。

### 4.4 DialogueContext

`DialogueContext` 是 L2 最重要的模型。它解决语音里的指代问题。

```ts
interface DialogueContext {
  currentEventId: string | null;
  currentOccurrenceStartAt: string | null;
  currentReminderId: string | null;
  currentReceiptId: string | null;
  recentCandidateRefs: CandidateRef[];
  pending: PendingInteraction | null;
  lastToolCallId: string | null;
  lastOperationId: string | null;
  expiresAt: string;
}

interface CandidateRef {
  kind: "event" | "occurrence" | "reminder" | "note" | "operation";
  id: string;
  title: string;
  startsAt?: string;
  reminderId?: string;
  source: "query" | "find" | "due_reminder" | "receipt";
}
```

规则：

- 用户说“这个”“刚才那个”时，只能绑定到 `currentEventId`、`currentReminderId` 或 `recentCandidateRefs`。
- 候选超过 1 个时，L2 必须追问，不允许让 LLM 直接选。
- 只要用户改变了时间、标题或范围，原确认令牌失效，重新调用 L3 检查。

### 4.5 PendingInteraction

L2 要区分“缺信息追问”和“高风险确认”。两者不能混在一个布尔值里。

```ts
type ClarificationReason =
  | "missing_time"
  | "missing_duration"
  | "missing_scope"
  | "ambiguous_target";

type ConfirmationReason =
  | "calendar_conflict"
  | "delete_event"
  | "terminate_series"
  | "skip_single_event";

interface ConfirmationGrant {
  token: string;                    // L3 签发的 opaque capability
  requestId: string;
  sessionId: string;
  toolCallId: string;
  toolCallDigest: string;
  expiresAt: string;
  consumedAt: string | null;
}

type PendingInteraction =
  | PendingClarification
  | PendingConfirmation;

interface PendingClarification {
  type: "clarification";
  reason: ClarificationReason;
  missingFields: string[];
  question: string;
  draftToolCall: ToolCallEnvelope;
  expiresAt: string;
}

interface PendingConfirmation {
  type: "confirmation";
  reason: ConfirmationReason;
  question: string;
  confirmation: ConfirmationGrant | null;
  originalToolCall: ToolCallEnvelope;
  expiresAt: string;
}
```

确认令牌由 L3 生成，并且必须在服务端绑定到 `requestId`、`sessionId`、`toolCallId` 和 `toolCallDigest`；L3 校验时同时检查有效期、参数绑定和是否已消费。L2 只能保存和原样传回，不能自己生成、改写或复用。

### 4.6 AgentPlan

`AgentPlan` 是 LLM 一次推理后的计划。它可能是追问，也可能是一个或多个工具调用。

```ts
type AgentPlanType = "ask_user" | "call_tools" | "speak_only" | "reject";

interface AgentPlan {
  id: string;
  type: AgentPlanType;
  userText: string;
  normalizedTimeZone: string;
  reasoningLabel: string; // 给开发调试，不给用户朗读
  questions: string[];
  toolCalls: ToolCallEnvelope[]; // 同一 plan 内只允许互不依赖的并行调用
  rejectedReason?: "sensitive_note" | "unsupported_scope" | "unsafe_operation";
}
```

L2 不能把 `reasoningLabel` 暴露给用户。用户只听结果、追问或失败原因。
需要依赖前一步结果的动作，必须拆成下一轮 `AgentPlan` 重新规划，不允许在同一个 `toolCalls` 数组里串联。

### 4.7 ToolCallEnvelope

工具调用使用业务语义，不使用数据库语义。

```ts
type L2ToolName =
  | "calendar.create"
  | "calendar.query"
  | "calendar.find"
  | "calendar.modify"
  | "calendar.skipOccurrence"
  | "calendar.pauseSeries"
  | "calendar.resumeSeries"
  | "calendar.terminateSeries"
  | "calendar.delete"
  | "reminder.listDue"
  | "reminder.close"
  | "reminder.snooze"
  | "reminder.getDetails"
  | "note.record"
  | "note.query"
  | "transaction_undo";

interface ToolCallEnvelope {
  id: string;
  name: L2ToolName;
  arguments: Record<string, unknown>;
  requiresUserVisibleResult: boolean;
  createdAt: string;
}
```

这些名字比 `calendar_events.insert`、`reminder_instances.update` 更适合 L2。L2 面向的是用户意图，不面向表操作。

### 4.8 ToolResultEnvelope

```ts
interface ToolResultEnvelope {
  toolCallId: string;
  ok: boolean;
  speech: string;
  receiptId: string | null;
  data: Record<string, unknown>;
  requiresConfirmation: boolean;
  confirmation?: ConfirmationGrant;
  candidates?: CandidateRef[];
  undoTransactionId?: string;
  errorCode?: string;
}
```

约束：

- `ok=false` 时，L2 不能说“已创建”“已删除”。
- `requiresConfirmation=true` 时，L2 只播 `speech`，把 `confirmation` 原样写入 `PendingConfirmation`，并在用户确认后原样重试。
- 有 `receiptId` 时，L2 把它交给 L1/IM 展示，不复制一份回执事实。

### 4.9 AgentReply

```ts
interface AgentReply {
  turnId: string;
  speechText: string;
  imMessage?: {
    text: string;
    receiptId?: string;
    actions: ImAction[];
  };
  nextState: VoiceSessionState;
  contextPatch: Partial<DialogueContext>;
}

interface ImAction {
  actionId: string;
  label: string;
  capabilityToken: string; // 只传不透明能力票据，不传工具调用体
}
```

IM 的按钮是受控入口，只能绑定当前回执、提醒或会话上下文。客户端只回传 `actionId` 和 `capabilityToken`，服务端按预登记能力票据还原固定动作，不能把 `ToolCallEnvelope` 暴露给前端。

### 4.10 ProactiveVoiceEvent

提醒到期不是用户说话触发，而是 L3/L4 推给 L2 的主动播报事件。

```ts
interface ProactiveVoiceEvent {
  id: string;
  type: "main_reminder_due" | "weak_reminder_due" | "snoozed_reminder_due";
  reminderId: string;
  eventId: string;
  occurrenceStartAt: string;
  title: string;
  triggerAt: string;
  speechText: string;
  receiptId: string;
  createdAt: string;
}
```

L2 收到主动事件后只负责播报和更新当前提醒上下文。是否到期、是否超过三次推迟、是否应该弱提醒，都由 L3 提前算好。

## 5. L2 到 L3 的工具契约

L2 调 L3 只走业务工具，不碰表。下面这组工具与 PR #62 原型基本一致，但命名统一为 L2 语义。

| L2 工具 | 对应 L3 服务 | 输入要点 | 输出要点 |
| --- | --- | --- | --- |
| `calendar.create` | 日历服务 | 标题、开始时间、结束时间/时长、地点、备注、周期、确认令牌 | 创建结果、冲突确认、回执 ID |
| `calendar.query` | 日历服务 | 时间范围、关键词、分页 | 摘要、候选引用、回执 ID |
| `calendar.find` | 日历服务 | 用户描述、时间范围、上下文 | 候选项列表 |
| `calendar.modify` | 日历变更服务 | eventId、originalStartAt、scope、字段变更、确认令牌 | 修改结果、影响范围、撤销 ID、回执 ID |
| `calendar.skipOccurrence` | 日历变更服务 | eventId、originalStartAt、确认令牌 | 幂等跳过结果、撤销 ID |
| `calendar.pauseSeries` | 日历变更服务 | eventId、from、until | 暂停结果、撤销 ID |
| `calendar.resumeSeries` | 日历变更服务 | eventId | 恢复结果、撤销 ID |
| `calendar.terminateSeries` | 日历变更服务 | eventId、from、确认令牌 | 终止结果、撤销 ID |
| `calendar.delete` | 日历变更服务 | eventId、scope、确认令牌 | 删除结果、撤销 ID |
| `reminder.listDue` | 提醒服务 | now、当前设备 | 到期提醒列表 |
| `reminder.close` | 提醒服务 | reminderId | 关闭结果，日程不变 |
| `reminder.snooze` | 提醒服务 | reminderId、minutes | 推迟结果，日程不变 |
| `reminder.getDetails` | 提醒服务 | reminderId | 地点、备注、完整内容 |
| `note.record` | 备忘录服务 | content、category | 24 小时临时记录 |
| `note.query` | 备忘录服务 | query | 未过期临时记录 |
| `transaction_undo` | 事务撤销服务 | undoTransactionId | 恢复结果、回执 ID |

重点规则：

- L2 传给 `calendar.modify` 的 `eventId` 和 `originalStartAt` 必须来自 `calendar.find` 或 `calendar.query`，不能让 LLM 编造。
- 周期事项必须显式带 `scope`，没有范围就先追问。
- 是否需要确认由 L3 在 `requiresConfirmation` 中返回；L2 只保存 `confirmation`、等待用户确认，再按原样重试。
- L3 返回失败时，L2 只播失败原因，不自己补救成另一个业务动作。

## 6. L2 状态流

### 6.1 普通创建

```text
idle
  -> listening
  -> transcribing
  -> planning
  -> dispatching calendar.create
  -> speaking
  -> idle
```

如果缺时间或时长：

```text
planning
  -> awaiting_user(PendingClarification)
  -> 用户补充
  -> planning
```

如果有冲突：

```text
dispatching calendar.create
  -> awaiting_user(PendingConfirmation: calendar_conflict)
  -> 用户确认
  -> dispatching calendar.create with token
```

### 6.2 提醒即时处理

```text
ProactiveVoiceEvent
  -> speaking
  -> context.currentReminderId = reminderId
  -> 用户说“十分钟后提醒我”
  -> dispatching reminder.snooze
  -> speaking
```

这条链路不能调用 `calendar.modify`。用户说“改到今晚八点”才进入日程变更。

### 6.3 日程变更

```text
用户说“把今天日报改到晚上七点”
  -> calendar.find
  -> 只有一个候选
  -> 如果是周期事项且范围清楚，calendar.modify
  -> 如果范围不清，PendingClarification(scope)
  -> L3 返回结果和 undoTransactionId
  -> 语音回读 + IM 回执
```

## 7. 空骨架代码建议

L2 建议单独成包，不继续散落在 WebSocket、MCP 和具体 L3 service 里。

```text
src/voice-agent/
  types.ts                  L2 数据模型
  ports.ts                  ASR、LLM、TTS、L3 工具端口
  turn-controller.ts        一轮语音交互编排
  context-store.ts          会话上下文和待确认动作
  tool-registry.ts          Function Calling 工具定义
  local-dispatcher.ts       工具调用到 L3 port 的分发
  response-composer.ts      ToolResult 到语音/IM 输出
  guardrail-policy.ts       敏感内容和越权调用拦截
  proactive-events.ts       到期提醒主动播报入口
```

端口定义示例：

```ts
interface VoiceAgentPorts {
  asr: AsrPort;
  llm: LlmPort;
  tts: TtsPort;
  tools: LocalToolPort;
  clock: ClockPort;
  contextStore: DialogueContextStorePort;
}

interface LocalToolPort {
  dispatch(call: ToolCallEnvelope): Promise<ToolResultEnvelope>;
}
```

骨架代码的验收重点不是“能真实识别语音”，而是主干能串起来：L1 发起 turn，L2 得到计划，L2 调用 L3 port，L2 生成 reply，L4 收到 TTS 播放请求。

## 8. 技术风险

| 风险 | 影响 | L2 处理方式 |
| --- | --- | --- |
| LLM 编造 eventId 或 reminderId | 误改、误删 | ID 必须来自 `calendar.find/query/reminder.listDue` 的候选引用 |
| LLM 把提醒稍后理解成改日程 | P2/P3 边界混乱 | `reminder.snooze` 和 `calendar.modify` 分工具，系统提示词和 ToolRegistry 强约束 |
| 高风险确认被伪造 | 删除、终止被误执行 | 确认令牌只由 L3 生成，L2 不生成、不改写 |
| 多轮语音打断 | 上一轮结果覆盖新一轮 | 每个 turn 有 `turnId`，被 interrupt 的 turn 结果丢弃 |
| 主动提醒和用户语音同时发生 | 播报错乱 | L2 需要音频队列和 turn 优先级：用户主动输入可打断播报 |
| 本地控制接口暴露 | 外部调用本地工具 | L2 控制 WebSocket/HTTP 只允许本机或可信 L1，外部 AI 只走受控工具通道 |
| 敏感临时记录 | 误存密码、验证码 | L2 先做敏感词拦截，L3 再做服务端拒绝 |
| 业务模型漂移 | L2 和 L3 对不上 | L2 只引用 L3 返回的 ID、回执和状态，不复制数据库结构 |

## 9. 验收标准

1. 能画出 L2 内部模块关系，且能说明每个模块的输入输出。
2. `VoiceSession`、`VoiceTurn`、`DialogueContext`、`ToolCallEnvelope`、`ToolResultEnvelope`、`AgentReply` 有明确字段。
3. L2 不出现 SQLite 表名和 SQL 查询。
4. L2 到 L3 的工具契约覆盖创建、查询、提醒关闭、稍后、查找、修改、跳过、暂停、恢复、终止、删除、临时记录、撤销。
5. L3 标记 `requiresConfirmation` 的动作都有确认流程模型。
6. “这个”“刚才那条”“当前提醒”只能从 `DialogueContext` 和候选引用解析。
7. 主动提醒通过 `ProactiveVoiceEvent` 进入 L2，不由 L2 自己扫描到期提醒。
8. 任一语音 turn 被打断后，旧 turn 不能继续写上下文或播报结果。
9. IM 受控按钮必须绑定具体 receipt/reminder/context，不能裸调用开放工具。
10. 后续空骨架代码能按 `src/voice-agent/` 结构拆出接口，并和 L1/L3/L4 串联。
