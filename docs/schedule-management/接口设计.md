# 日程管理接口设计

## 0. 概述

本文档定义 VoiceLife 日程管理模块的**函数式接口**（无 HTTP，供大模型 / MCP Tool 调用）。

设计基于 `data-model.md` 的三张表：`ScheduleRule`（周期规则）、`Schedule`（日程实例）、`ScheduleException`（单次例外）。

核心数据模型约定：

- **一次性日程** = `rule_id` 为空的 `Schedule`
- **周期实例** = `rule_id` 指向某条 `ScheduleRule` 的 `Schedule`

## 1. 通用约定

### 1.1 定位方式

| 目标 | 定位字段 |
| --- | --- |
| 一次性日程 | `schedule_id` |
| 周期中的某一次 | `rule_id + original_start_time`（无论已生成/未生成） |

> `original_start_time` 是某一次的**原始发生时间**，类型为 `datetime`。它是周期实例的统一定位键，调用方从 `query_schedule_rules` 的返回结果中透传，不自行计算。

### 1.2 状态枚举

- 日程实例 `Schedule.status`：`active`(1) / `cancelled`(2) / `completed`(3)
- 周期规则 `ScheduleRule.status`：`active`(1) / `cancelled`(2) / `completed`(3)

### 1.3 字段修改语义

- **省略**字段 = 不修改
- **空字符串 / null** = 清空该字段

### 1.4 冲突检测

修改或创建时间时，若 `ignore_conflict=false`，检测与其他 active 实例的时间重叠；有冲突则返回冲突列表且不执行写操作。

### 1.5 本轮范围

- ❌ 不含操作撤销（undo）
- ❌ 不含提醒（reminder）

## 2. 接口总览

### 一次性日程（4）

| 接口 | 用途 |
| --- | --- |
| `create_schedule` | 创建一次性日程 |
| `query_schedules` | 查询具体实例 |
| `update_schedule` | 修改一次性日程 |
| `delete_schedule` | 删除一次性日程 |

### 周期规则（4）

| 接口 | 用途 |
| --- | --- |
| `create_schedule_rule` | 创建周期规则并生成首条实例 |
| `query_schedule_rules` | 查询周期规则 |
| `update_schedule_rule` | 修改整条周期规则 |
| `cancel_schedule_rule` | 取消整条周期规则 |

### 周期中的某一次（3）

| 接口 | 用途 |
| --- | --- |
| `update_schedule_occurrence` | 修改周期中的某一次 |
| `skip_schedule_occurrence` | 跳过周期中的某一次 |
| `generate_next_schedule_instance` | 生成规则的下一条实例 |

## 3. 一次性日程接口

### 3.1 create_schedule（创建一次性日程）

创建一条一次性日程，即插入一条 `rule_id = NULL` 的 `Schedule`。

**入参**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `event` | string | ✅ | 事件标题 |
| `start_time` | datetime | ❌ | 开始时间；为空表示无固定时间的备忘 |
| `end_time` | datetime | ❌ | 结束时间；需 > `start_time` |
| `location` | string | ❌ | 事件地点 |
| `notes` | string | ❌ | 事件备注 |
| `ignore_conflict` | bool | ❌（默认 false） | 是否忽略时间冲突 |

**出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `message` | string | 处理说明 |
| `schedule` | Schedule | 创建后的实例（含自增 id） |
| `conflicts` | Schedule[] | 冲突实例；无冲突为空 |
| `error` | string | 错误信息 |

**处理规则**

1. 插入一条 `Schedule`，`rule_id=NULL`、`status=active`。
2. `ignore_conflict=false` 时先做冲突检测；有冲突则只返回 `conflicts`、不创建。

### 3.2 query_schedules（查询具体实例）

查询 `Schedule` 表里的具体实例，**不区分**一次性/周期性。

**入参**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schedule_id` | int | ❌ | 按实例 ID 精确查询 |
| `rule_id` | int | ❌ | 查询某规则已生成的实例 |
| `keyword` | string | ❌ | 关键词，模糊匹配 event/location/notes |
| `start_from` | datetime | ❌ | start_time 下限 |
| `start_to` | datetime | ❌ | start_time 上限 |
| `status` | string | ❌（默认 active） | active / cancelled / completed / all |
| `limit` | int | ❌（默认 10，最大 50） | 返回条数 |
| `offset` | int | ❌（默认 0） | 分页偏移量 |

**出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schedules` | Schedule[] | 符合条件的实例，按 start_time 升序 |
| `total` | int | 符合条件的总数，不受 limit/offset 影响 |
| `error` | string | 错误信息 |

**处理规则**

1. 只查 `Schedule` 表，不动态展开周期规则的未来实例。
2. 多个条件为 AND 关系。
3. 不传时间条件时，默认查询未来（`start_time >= now()`）。

### 3.3 update_schedule（修改一次性日程）

修改一条一次性日程（`rule_id=NULL`）。

**入参**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schedule_id` | int | ✅ | 一次性日程 ID |
| `event` | string | ❌ | 新标题（空字符串清空） |
| `start_time` | datetime | ❌ | 新开始时间 |
| `end_time` | datetime | ❌ | 新结束时间（null 清空） |
| `location` | string | ❌ | 新地点（空字符串清空） |
| `notes` | string | ❌ | 新备注（空字符串清空） |
| `ignore_conflict` | bool | ❌（默认 false） | 是否忽略时间冲突 |

**出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schedule` | Schedule | 更新后的实例 |
| `conflicts` | Schedule[] | 冲突实例 |
| `error` | string | 错误信息 |

**处理规则**

1. 校验 `rule_id` 为空（一次性）；若非空，返回 error 提示改用 `update_schedule_occurrence`。
2. 更新提供的字段。
3. 改时间且 `ignore_conflict=false` 时做冲突检测。

### 3.4 delete_schedule（删除一次性日程）

取消一条一次性日程，标记 cancelled，不物理删除。

**入参**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schedule_id` | int | ✅ | 一次性日程 ID |

**出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schedule_id` | int | 被取消的日程 ID |
| `deleted` | bool | 是否成功取消 |
| `error` | string | 错误信息 |

**处理规则**

1. 校验 `rule_id` 为空（一次性）；若非空，返回 error 提示改用 `skip_schedule_occurrence`。
2. `status → cancelled`。

## 4. 周期规则接口

### 4.1 create_schedule_rule（创建周期规则）

创建一条周期规则，并立即物化首条实例。

**入参**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `event` | string | ✅ | 默认标题 |
| `freq_type` | string | ✅ | daily / weekly / monthly / yearly（1/2/3/4） |
| `start_time` | time | ✅ | 每次默认发生时间 |
| `start_date` | date | ✅ | 规则生效日期 |
| `end_time` | time | ❌ | 每次默认结束时间 |
| `location` | string | ❌ | 默认地点 |
| `notes` | string | ❌ | 默认备注 |
| `interval_val` | int | ❌（默认 1） | 周期间隔（每 N 天/周/月/年） |
| `weekdays_mask` | int | ❌ | weekly 用：1~127，bit0=周一 |
| `monthly_mode` | int | ❌ | monthly 用：1=指定日期，2=当月最后一天 |
| `day_of_month` | int | ❌ | monthly/yearly 用：1~31 |
| `month_of_year` | int | ❌ | yearly 用：1~12 |
| `end_date` | date | ❌ | 失效日期（与 occurrence_count 二选一） |
| `occurrence_count` | int | ❌ | 最大次数（与 end_date 二选一） |
| `ignore_conflict` | bool | ❌（默认 false） | 是否忽略冲突 |

**出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `rule` | ScheduleRule | 创建后的规则 |
| `schedules` | Schedule[] | 本次立即生成的实例（通常 1 条，可能为空） |
| `conflicts` | Schedule[] | 冲突实例 |
| `error` | string | 错误信息 |

**处理规则**

1. 校验 freq_type 及对应参数：weekly 需 `weekdays_mask`；monthly 需 `monthly_mode`；yearly 需 `month_of_year` + `day_of_month`。
2. 校验 `end_date` 与 `occurrence_count` 二选一（都不给 = 无限重复）。
3. 创建 ScheduleRule（`status=active`）。
4. 立即生成首条实例：从 `start_date` 起、且 ≥ now()，按 freq 算出第一个匹配日，物化成 Schedule。
5. `ignore_conflict=false` 时对首条实例做冲突检测。

### 4.2 query_schedule_rules（查询周期规则）

查询周期规则定义，返回规则 + 单次例外 + 未来几次原始发生时间。

**入参**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `rule_id` | int | ❌ | 按规则 ID 精确查询 |
| `keyword` | string | ❌ | 关键词，模糊匹配 event/location/notes |
| `status` | string | ❌（默认 active） | active / cancelled / completed / all |
| `limit` | int | ❌（默认 10，最大 50） | 返回条数 |
| `offset` | int | ❌（默认 0） | 分页偏移量 |

**出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `rules` | ScheduleRule[] | 规则列表，每条附带 exceptions 和 upcoming_occurrences |
| `total` | int | 符合条件的总数 |
| `error` | string | 错误信息 |

其中每条 `rule` 附带：

```text
{
    ...规则字段,
    exceptions: [ ScheduleException, ... ],          // 该规则被修改/跳过的那些次
    upcoming_occurrences: [                          // 未来 3 次原始发生时间
        { original_start_time: datetime },
        ...
    ]
}
```

**处理规则**

1. 只查 ScheduleRule 表，不展开无限实例。
2. `exceptions` 由 `ScheduleException.rule_id` 关联查出。
3. `upcoming_occurrences` 由规则字段计算未来 3 次原始发生时间。

### 4.3 update_schedule_rule（修改整条周期规则）

修改整条规则 = 用新规则覆盖未来，历史不动。**破坏性操作，调用前需二次确认。**

**入参**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `rule_id` | int | ✅ | 规则 ID |
| `event` | string | ❌ | 新默认标题（空字符串清空） |
| `location` | string | ❌ | 新默认地点（空字符串清空） |
| `notes` | string | ❌ | 新默认备注（空字符串清空） |
| `freq_type` | string | ❌ | daily / weekly / monthly / yearly |
| `interval_val` | int | ❌ | 周期间隔 |
| `weekdays_mask` | int | ❌ | weekly 用 |
| `monthly_mode` | int | ❌ | monthly 用 |
| `day_of_month` | int | ❌ | monthly/yearly 用 |
| `month_of_year` | int | ❌ | yearly 用 |
| `start_time` | time | ❌ | 每次默认发生时间 |
| `end_time` | time | ❌ | 每次默认结束时间（null 清空） |
| `start_date` | date | ❌ | 生效日期 |
| `end_date` | date | ❌ | 失效日期（与 occurrence_count 二选一） |
| `occurrence_count` | int | ❌ | 最大次数 |
| `ignore_conflict` | bool | ❌（默认 false） | 是否忽略冲突 |

**出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `rule` | ScheduleRule | 更新后的规则 |
| `schedules` | Schedule[] | 按新规则重新生成的未来实例 |
| `conflicts` | Schedule[] | 冲突实例 |
| `error` | string | 错误信息 |

**处理规则**

1. 校验 freq_type 及对应参数、end_date/occurrence_count 二选一。
2. 更新规则字段（不提供的保持原值）。
3. 保留历史实例（`start_time < now()`）。
4. 删除尚未发生的已物化实例和 ScheduleException（其 original_start_time 基于旧规则）。
5. 按新规则生成首条（下一条）实例。
6. `ignore_conflict=false` 时做冲突检测。

### 4.4 cancel_schedule_rule（取消整条周期规则）

取消整条规则，标记 cancelled（不物理删）。建议调用前二次确认。

**入参**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `rule_id` | int | ✅ | 规则 ID |

**出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `rule` | ScheduleRule | 取消后的规则（status=cancelled） |
| `cancelled_count` | int | 被标记取消的未来实例数量 |
| `error` | string | 错误信息 |

**处理规则**

1. `ScheduleRule.status → cancelled`。
2. 尚未发生的已物化实例 `status → cancelled`（标记，不物理删）。
3. 历史实例不动。
4. 之后 `generate_next_schedule_instance` 对 cancelled 规则不生成。

## 5. 周期中的某一次接口

### 5.1 update_schedule_occurrence（修改周期中的某一次）

修改周期规则中的某一次，无论已生成/未生成。

**入参**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `rule_id` | int | ✅ | 规则 ID |
| `original_start_time` | datetime | ✅ | 要修改那一次的原始发生时间 |
| `event` | string | ❌ | 新标题（空字符串清空） |
| `start_time` | datetime | ❌ | 新开始时间 |
| `end_time` | datetime | ❌ | 新结束时间（null 清空） |
| `location` | string | ❌ | 新地点（空字符串清空） |
| `notes` | string | ❌ | 新备注（空字符串清空） |
| `ignore_conflict` | bool | ❌（默认 false） | 是否忽略冲突 |

**出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schedule` | Schedule | 已物化实例更新后的结果；未物化实例为空 |
| `exception` | ScheduleException | 写入/更新的 modify 例外 |
| `conflicts` | Schedule[] | 冲突实例 |
| `error` | string | 错误信息 |

**处理规则**

1. 定位 `(rule_id, original_start_time)`。
2. **已物化**：更新 Schedule；同时写 `ScheduleException(type=modify, schedule_id 关联)` 记录偏离（否则改规则重生成时会被默认值覆盖）。
3. **未物化**：写 `ScheduleException(type=modify, schedule_id=NULL, override_* 存改动)`；不立即物化，等 `generate_next` 到达时应用。
4. 改时间且 `ignore_conflict=false` 时做冲突检测。

### 5.2 skip_schedule_occurrence（跳过周期中的某一次）

跳过周期规则中的某一次，无论已生成/未生成。

**入参**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `rule_id` | int | ✅ | 规则 ID |
| `original_start_time` | datetime | ✅ | 要跳过那一次的原始发生时间 |

**出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schedule` | Schedule | 已生成实例标记取消后的结果；未生成实例为空 |
| `exception` | ScheduleException | 写入的 skip 例外 |
| `error` | string | 错误信息 |

**处理规则**

1. 定位 `(rule_id, original_start_time)`。
2. 若已生成对应 Schedule（经 exception 的 schedule_id 关联，或 start_time 匹配），标记 `cancelled`。
3. 写 `ScheduleException(type=skip)`。之后 `generate_next` 走到这一天时跳过。

### 5.3 generate_next_schedule_instance（生成下一条实例）

生成某规则在 `now()` 之后的下一条未生成实例。

**入参**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `rule_id` | int | ✅ | 规则 ID |

**出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schedule` | Schedule | 生成的下一条实例；无下一条时为空 |
| `error` | string | 错误信息 |

**处理规则**

1. 读规则（`status` 须为 active）。
2. 从 `now()` 向后，按规则算出下一个候选原始发生时间。
3. 查该原始时间的 `ScheduleException`：
   - `skip` → 跳过，回到第 2 步算下一个
   - `modify` → 应用 override，物化，结束
   - 无 → 直接物化，结束
4. 物化前防重：该原始时间已有 Schedule 则视为已生成，继续向后。
5. 无下一条（规则已取消 / 到达 end_date / occurrence_count 用尽）时返回空 + 说明。
