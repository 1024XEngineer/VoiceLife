# 语音日程助手原型说明

## 原型目标

这是一个以语音为主要入口、以 IM 承载持久回执的个人日程与提醒助手。灵矽承担 ASR、Agent 和 TTS；本项目通过 MCP 管理日程、周期实例、提醒状态、临时记录和操作回执。

当前原型按照整合 Proposal 验证三段连续闭环：

1. 创建、冲突确认、临时记录，以及自然日/周/月/年查询。
2. 到期提醒、提前弱提醒、关闭和最多三次稍后提醒。
3. 修改、跳过、暂停/恢复、终止、删除与 10 分钟撤销。

当前 Web 原型只有一个页面：默认“语音”页签提供按住说话入口，“消息”页签暂时代替尚未接入的真实 IM，展示语音操作结果并提供“知道了”“10 分钟后”和“撤销”等受控操作。它不是日历管理 GUI。

## 产品行为

### 创建、记录与查询

- 支持单次、每天、每周和每月日程；时区固定为 `Asia/Shanghai`。
- 单个日程至少需要标题和发生时间。会议、拜访、课程等时间段日程还必须提供结束时间或持续分钟数；原型不设置默认时长。
- 点提醒之间同刻、时间段相互重叠、点提醒落入时间段都会触发冲突确认。用户未确认前不写入日程、提醒或回执；确认后保留全部冲突事项，不自动调整。
- 未单独说明提醒时间时，主提醒在日程开始时触发。时间段日程默认在开始前 15 分钟发送弱提醒；用户明确拒绝时才关闭。弱提醒无需回应且不替代主提醒。
- 无提醒时间的非敏感小事可作为临时记录保存 24 小时，例如停车位置。密码、验证码、取件码和支付码不会保存；给出提醒时间的小事改为创建日程。
- “今天”按 00:00 至次日 00:00 查询，包含已发生事项；“接下来”才从当前时刻开始。工具同样支持指定日期、本周、本月和今年的明确范围。
- 语音查询最多播报前两条，IM 保存完整结果。

### 提醒处理

- 主提醒到达时先写入并实时推送 IM 回执，再尝试主动语音播放，两条通道彼此不阻塞。
- 同一轮多项提醒按触发时间排序，合并为一段 TTS 依次播报标题和时间，避免平台丢失连续音频；IM 中仍保留独立提醒。
- “知道了”只关闭当前提醒；“十分钟后提醒我”只改变当前提醒的下一触发时间，两者都不修改底层日程。
- 推迟时长缺失必须追问。每条提醒最多推迟三次；第三次推迟再次到期后仍保留 IM 回执，但不再主动语音播报。
- 没有用户回应时不会重复主动播报；IM 回执继续保留。地点和备注只在用户要求详情时提供。
- 多条提醒同时到期且回应无法确定目标时，必须先询问具体提醒。

### 日程变更

- 单次日程可修改标题、开始/结束时间、地点和备注。
- 周期日程支持三种明确范围：仅本次、本次及以后、整个系列。“本次及以后”通过在目标实例处分割系列实现，之前实例保持原规则。
- 支持跳过一次周期实例；重复跳过幂等。对单次日程说“跳过”会先说明其等同取消，再请求确认。
- 支持暂停周期到指定时间、提前恢复，以及从指定实例起终止未来周期。
- 支持删除单次日程或整个系列。
- 修改、跳过、暂停、恢复、终止和删除都会生成语音/IM 回执，并创建 10 分钟有效的撤销操作。
- 跳过、终止、删除和单次取消必须二次确认。改期产生冲突时也必须确认，系统不会自动移动其他事项。

## 交互通道

### 语音入口

本地单页原型使用浏览器语音识别完成 ASR。用户在“语音”页签按住按钮说话，松开后识别文本经本地服务发送给已绑定的灵矽 Agent；Agent 判断意图并调用 MCP，TTS 回复由 Mac 客户端通过电脑扬声器播放。Chrome 首次使用时需要授予麦克风权限。

灵矽 Web Demo 仍可作为兼容入口。无论从哪一个语音入口发起，Agent 的所有日程读写都必须经过 MCP。实际配置规则见 [灵矽 Agent 提示词](linx-agent-prompt.md)。

### IM 回执

单页原型中的“消息”页签实时展示创建、查询、临时记录、提醒和日程变更结果，暂时代替真实 IM。它不接受开放式日程指令，仅允许处理当前提醒和撤销近期变更。

### 灵矽设置

语音页左下角提供本地设置入口。设置页包含 API Key、MCP 接入点、Agent 绑定和 Mac 设备激活教程，可保存 Agent ID 与可选音色 ID、复制临时 X-MCP-Token、生成设备激活码并播放连接测试。API Key 和设备 Token 只写入本机 `.env`，状态接口只返回是否已配置，不回显密钥。配置写入后需重启主服务，设置页的连接测试会直接读取最新配置。

### Mac 主动语音客户端

Web Demo 不能接收本地服务向其已有会话主动注入的提醒。原型因此提供一个 Mac 设备客户端：定时器发现提醒到期后，客户端向独立灵矽设备 WebSocket 会话发送文本，接收 PCM 或 Opus TTS 音频，并通过 macOS 扬声器播放。PCM 回复会在第一批音频到达后立即流式播放；Opus 仍采用完整接收后解码播放的兼容路径。

Mac 客户端只负责向灵矽设备会话发送识别文本及播放返回音频；麦克风由本地 Web 页面采集。用户听到提醒后，可从语音入口处理到期提醒，或使用“消息”页签中的回执按钮。Mac 睡眠、客户端退出或网络中断时无法主动播放，但回执状态不会丢失。

## 接入与运行

### 1. 启动基础服务

要求 Node.js 24 或更新版本。

```bash
cp .env.example .env
npm install
npm run dev
```

打开 <http://localhost:3000>，在“语音”页签按住按钮说话并在松开后发送；“消息”页签用于查看回执。也可从左下角进入设置页完成灵矽接入。首次运行前修改 `.env` 中的 `MCP_SHARED_SECRET`；`.env`、API Key、代理 Token 和本地 SQLite 不应提交到 Git。

### 2. 接入灵矽 MCP 广场

推荐使用 MCP 广场的“MCP 接入点”：

1. 在本机 `.env` 填写 `LINX_API_KEY=...`。
2. 启动原型；服务获取 Proxy Token 并连接灵矽 MCP Proxy WebSocket。
3. 执行 `npm run linx:copy-token`，将 `X-MCP-Token` 复制到剪贴板。
4. 在 MCP 广场开通接入点：
   - 传输协议：`Streamable HTTP`
   - MCP URL：`https://xrobo.qiniu.com/v1/mcpproxy/mcp`
   - 认证模式：`Normal`
   - Header `X-MCP-Token`：粘贴上一步的值
5. 将接入点绑定到目标 Agent。
6. 复制 Agent 提示词，保存后断开并重新连接 Web Demo，使最新工具列表生效。

### 3. 兼容直连 MCP

也可通过 HTTPS 隧道直接暴露本地服务：

- Streamable HTTP：`https://你的域名/mcp`
- Header：`Authorization: Bearer <MCP_SHARED_SECRET>`
- 兼容 SSE：`/sse` 与 `/messages`

公网仅开放 MCP 与 `/health`；语音交互、消息回执和调试 API 只接受 localhost 请求。

### 4. 激活 Mac 主动语音客户端

```bash
npm run linx:voice:activate
```

该命令生成并复用本机设备标识，调用灵矽 OTA 网关，并把连接配置保存到 Git 已忽略的 `.env`。在灵矽智控台的目标 Agent 中，用显示的激活码新增设备；绑定后再次运行激活命令刷新配置。

测试 TTS 与扬声器：

```bash
npm run linx:voice:test -- "请只回复：语音客户端连接成功"
```

## MCP 工具

| 工具 | 能力 |
|---|---|
| `calendar_create` | 创建点提醒或时间段日程，支持简单周期、弱提醒和冲突确认 |
| `calendar_query` | 查询自然日或明确范围；语音摘要、IM 完整结果 |
| `calendar_find` | 变更前查找候选，多条时要求用户指定 |
| `note_record` / `note_query` | 保存和查询 24 小时非敏感临时记录 |
| `reminder_list_due` | 查询当前到期主提醒 |
| `reminder_close` / `reminder_snooze` | 关闭或推迟当前提醒，不改日程 |
| `reminder_get_details` | 返回提醒的地点和备注 |
| `calendar_modify` | 按仅本次、本次及以后、整个系列修改日程 |
| `calendar_reschedule_occurrence` | 兼容旧 Agent 的仅本次改期入口，内部使用相同变更逻辑 |
| `calendar_skip_occurrence` | 确认后跳过本次；单次日程按取消处理 |
| `calendar_pause_series` / `calendar_resume_series` | 暂停到指定日期或提前恢复周期 |
| `calendar_terminate_series` | 确认后终止未来周期 |
| `calendar_delete` | 确认后删除单次日程或整个系列 |
| `calendar_undo` | 撤销最近 10 分钟内的日程变更 |

## HTTP 接口

| 方法 | 地址 | 用途 |
|---|---|---|
| `GET/POST/DELETE` | `/mcp` | MCP Streamable HTTP，需要 Bearer Token |
| `GET` | `/sse` | 兼容 MCP SSE，需要 Bearer Token |
| `POST` | `/messages` | MCP SSE 消息入口，需要 Bearer Token |
| `GET` | `/health` | 服务状态和演示时间 |
| `POST` | `/api/voice/interact` | 将浏览器识别文本发送给已绑定的灵矽 Agent |
| `GET/PUT` | `/api/settings/linx` | 读取脱敏状态或保存本地灵矽配置 |
| `POST` | `/api/settings/linx/mcp-token` | 获取并复制临时 X-MCP-Token |
| `POST` | `/api/settings/linx/activate` | 生成或刷新 Mac 设备激活配置 |
| `POST` | `/api/settings/linx/test` | 使用最新本地配置播放连接测试 |
| `GET` | `/api/receipts` | 本地 IM 回执列表 |
| `GET` | `/api/receipts/stream` | 本地 IM 实时事件流 |
| `POST` | `/api/reminders/:id/close` | IM“知道了” |
| `POST` | `/api/reminders/:id/snooze` | IM“10 分钟后” |
| `POST` | `/api/calendar/undo/:id` | IM 撤销 10 分钟内的变更 |
| `POST` | `/api/demo/clock/set` | 设置演示时间并扫描提醒 |
| `POST` | `/api/demo/clock/advance` | 推进演示时间并扫描提醒 |
| `POST` | `/api/demo/clock/reset` | 恢复真实时间 |

## 演示验收

建议依次验证：

1. 在“语音”页签按住按钮说“明天十点到十一点客户拜访，A 座 1503”，松开后确认 Mac 扬声器给出回复，“消息”页签出现创建回执。
2. 再创建 10:30 的事项，确认 Agent 先报告时间段冲突；拒绝时不落库，确认时两项并存。
3. “记一下，我车停在 B2 C18。”随后问“我车停哪了”。
4. 创建一个有明确开始和结束时间的日程。无需额外说明，推进到开始前 15 分钟时应先收到弱提醒，开始时再收到主提醒。
5. 主提醒分别验证“十分钟后提醒”“知道了”，确认日程本身不变；推迟三次后不再自动语音。
6. “把今天日报改到七点，其他不变。”确认明天仍为 17:30。
7. 分别验证“从今天起都改到七点”“暂停到下周一”“跳过明天”“终止未来周期”“删除系列”，检查确认、IM 回执和撤销。

## 当前边界

- 产品入口是语音；当前“消息”页签暂代真实 IM，只提供持久回执和受控操作，没有日历管理 GUI。
- 单机 SQLite、单个本地用户、固定 `Asia/Shanghai` 时区。
- 只支持每天、每周、每月，不支持完整 RRULE、工作日日历、农历节日、跨时区、共享日历和第三方日历同步。
- 临时记录保留 24 小时，不承担长期知识库或敏感凭证保管。
- 语音回复和主动提醒依赖持续运行且未睡眠的 Mac 客户端；Web Demo 仍不能被后台直接唤起。浏览器 ASR 依赖 Chrome 的语音识别能力和麦克风权限。
- 这是快速原型。生产版本仍需补多用户隔离、并发控制、审计、备份恢复、真实推送可靠性和更细的权限策略。
