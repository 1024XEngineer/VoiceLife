# GitHub 个人项目管理助手：产品原型设计文档

> 状态：原型设计草案
> 日期：2026-07-14
> 来源：PR #30 自动导入任务、PR #28 任务优先级排序与展示、PR #29 任务自动重排
> 用途：把三个 Proposal 收敛成一套可评审、可画低保真原型、可进入架构讨论的产品原型说明。

## 1. 原型结论

本期原型不做通用待办 App，也不做团队项目管理工具。它只补 GitHub 工作流里缺失的个人决策层：

```text
我有哪些事要做
-> 哪些今天先做
-> 为什么是这个顺序
-> 计划被打断后怎么重新排
```

三个 Proposal 的关系如下：

```text
Proposal 01：自动导入任务
    ↓
Proposal 02：输出排序结果与排序理由
    ↓
Proposal 03：根据排序结果生成今日计划，并在状态变化后重排
```

这里有一个边界必须先说清楚：Proposal 02 不改变计划。它只输出排序结果和理由；真正把任务放进「今日计划」「规划池」「待评审」「待估算」等位置，是 Proposal 03 的职责。

## 2. 本期范围

### 2.1 本期做什么

| 模块 | 做什么 |
| --- | --- |
| GitHub 绑定 | 用户授权 GitHub 账号，选择一个仓库 |
| 任务导入 | 导入与当前用户有关的开放 Issue、我的 PR、请求我 Review 的 PR |
| 任务池 | 将不同 GitHub 对象统一展示成个人行动项 |
| 排序展示 | 展示任务顺序和排序理由 |
| 今日计划 | 根据排序结果、预计投入和容量生成今日任务 |
| 自动重排 | PR 退回、任务未完成、新任务进入、阻塞变化后更新计划 |
| 变化摘要 | 告诉用户哪些任务被加入、移出、提前，以及原因 |
| 冲突处理 | 硬截止任务超过容量时，展示缺口并让用户选择处理方式 |

### 2.2 本期明确不做

| 不做 | 原因 |
| --- | --- |
| 不做复杂过滤器 | 首版先验证任务是否能导入和排序 |
| 不全量同步历史 Issue | 只看当前与我有关的开放任务 |
| 不写回 GitHub | 降低权限风险，首版只读 |
| 不做团队任务分配 | 本期只解决「我今天做什么」 |
| 不做长期日历 / 甘特图 | 会把问题扩大成长期排程 |
| 不做 AI 黑盒排序 | 用户必须能看懂排序依据 |
| 不自动猜预计投入 | 缺信息时显示「待估算」，让用户补 |
| 不自动安排后天或更远日期 | 今日放不下的任务先回规划池 |

## 3. 信息结构

### 3.1 核心对象

| 对象 | 说明 |
| --- | --- |
| GitHub 账号 | 当前绑定用户，是任务归属判断依据 |
| Repository | 首版只选择一个仓库 |
| GitHub 对象 | Issue、我的 PR、请求我 Review 的 PR |
| 个人任务 | 从 GitHub 对象转成的个人行动项 |
| 今日计划 | 今天建议执行的任务 |
| 规划池 | 暂时没有进入今日，但后续仍要处理的任务 |
| 待估算 | 缺预计投入，暂时不能进入容量安排 |
| 待评审 | 已提交，正在等别人 Review 或合并 |
| 阻塞任务 | 当前无法继续，不进入今日计划 |
| 已结束 | merged 或 closed 的任务 |

### 3.2 任务字段

| 字段 | 示例 |
| --- | --- |
| 标题 | `Issue #31 完成登录页` |
| 来源 | `Issue` / `My PR` / `Review Request` |
| 仓库 | `1024XEngineer/XE6-15` |
| GitHub 链接 | 原 Issue / PR URL |
| 主状态 | `On Progress` / `Pending Review` / `Done` |
| 位置 | 今日计划 / 规划池 / 待估算 / 待评审 / 阻塞 / 已结束 |
| 优先级 | P0 / P1 / P2 / 未设置 |
| 硬截止 | 今天 / 明天 / 3 天内 / 更晚 / 无 |
| 预计投入 | 1h / 2h / 待估算 |
| 排序理由 | 为什么排在当前位置 |
| 变化原因 | 为什么被加入、移出或提前 |

## 4. 页面原型

### 页面 1：GitHub 授权与仓库选择

用户路径：

```text
打开产品
-> 点击绑定 GitHub
-> 完成授权
-> 选择 Organization / Repository
-> 开启自动同步
```

页面内容：

```text
绑定 GitHub

当前状态：未绑定

[绑定 GitHub 账号]

绑定后将读取：
- 分配给我的开放 Issue
- 我创建或负责的 PR
- 请求我 Review 的 PR

不会修改：
- Issue 内容
- PR 状态
- Label
- Assignee
- Milestone
```

绑定成功后：

```text
选择仓库

Organization：1024XEngineer
Repository：XE6-15

[开始同步]
```

### 页面 2：同步结果页

```text
同步完成

已导入 12 个任务
- Issue：7 个
- 我的 PR：3 个
- 请求我 Review：2 个

需要补充信息：4 个
- 2 个缺预计投入
- 1 个缺优先级
- 1 个缺硬截止

[进入任务池]
```

规则：

- 同步失败必须显示原因；
- 空列表不能假装成功；
- 缺字段不让 AI 直接编，进入待补信息区；
- 用户可以重新同步，但重新同步仍然不写回 GitHub。

### 页面 3：个人任务池

任务池展示所有与我有关的任务，但不等于今日计划。

```text
个人任务池

全部 12    今日 3    待估算 2    待评审 1    阻塞 1

Issue #31 完成登录页
来源：Assigned Issue
状态：On Progress
优先级：P0
截止：今天
预计：2h
[打开 GitHub] [调整]

PR #45 配置页改版
来源：My PR
状态：Pending Review
原因：已提交，等待 Reviewer
[打开 GitHub]

PR #52 Review 数据模型
来源：Review Request
状态：On Progress
优先级：P1
截止：明天
预计：1h
[打开 GitHub] [调整]
```

### 页面 4：首页 / 今日计划

首页不先展示全量列表，而是先回答「今天先做什么」。

```text
今日计划                         7 月 14 日

今日容量：4h
已安排：3h
剩余：1h

1. Issue #31 完成登录页
   P0 / 截止今天 / 预计 2h
   原因：硬截止今天，且当前需要你处理

2. PR #52 Review 数据模型
   P1 / 截止明天 / 预计 1h
   原因：请求你 Review，截止早于其他 P1

规划池
- Issue #37 补充错误提示
  原因：今日容量不足，暂留规划池

待估算
- Issue #51 更新项目文档
  原因：缺预计投入，不能进入今日计划
```

### 页面 5：排序理由详情

用户点开任务后，看到它为什么排在这里。

```text
Issue #31 完成登录页

排序理由：
1. 硬截止是今天，优先于其他非今日截止任务
2. 当前状态是 On Progress，需要你处理
3. 优先级是 P0
4. 预计投入 2h，可以放入今日容量

当前不会修改 GitHub：
- 不改 Issue
- 不改 PR
- 不改 Label
- 不改截止时间
```

排序原则：

| 优先顺序 | 规则 |
| --- | --- |
| 1 | 硬截止越近越靠前 |
| 2 | 同一硬截止组内保留用户手动顺序 |
| 3 | 没有手动顺序时按 P0 / P1 / P2 |
| 4 | 条件相同时，预计投入短的靠前 |
| 5 | 无 DDL 且长期未活动的任务逐步上浮 |
| 6 | 缺预计投入的任务不进入今日容量 |

### 页面 6：变化摘要

当 GitHub 状态或用户计划信息发生变化后，用户看到变化摘要，而不是被迫重新整理。

```text
计划已更新

+ Issue #31 已加入今日计划
  原因：PR 收到 requested changes，需要你返工，预计 1h

- Issue #37 已移回规划池
  原因：今日容量不足，且截止晚于 Issue #31

今日计划已自动更新，无需逐项确认。

[查看今日计划] [查看规划池]
```

### 页面 7：硬截止容量冲突

```text
硬截止容量冲突

今日剩余容量：2h
必须今日完成：3h
缺口：1h

Issue #31 PR 返工              1h
Issue #42 提交训练营作业        2h

请选择处理方向：
[调高今日容量]
[调整任务范围 / 预计投入]
[手动移出任务]
[接受延期风险]
```

规则：

- 产品不静默延期；
- 产品不替用户承诺无法完成的计划；
- 用户选择前，冲突提示保留；
- 用户调整后，今日计划重新计算。

## 5. 状态流转

主状态只表达「用户现在是否需要行动」。

```text
On Progress
  当前需要用户处理
  可进入今日计划或规划池

Pending Review
  用户已提交或改完
  当前主要等别人 Review 或合并
  不进入今日计划

Done
  当前 GitHub 对象对用户没有待处理动作
  不参与重排
```

PR 状态流转：

```text
On Progress
  ↓ 提交 PR / 完成返工并重新请求 Review

Pending Review
  ↓ changes requested / 明确要求作者修改

On Progress
  ↓ 再次提交修改

Pending Review
  ↓ PR merged / PR closed

Done
```

补充规则：

- Approved 或普通评论不让任务回到 On Progress，除非明确要求作者修改；
- Closed 未合并也进入 Done，但显示「已关闭未合并」，不显示成「已合并」；
- Reopen 后回到 On Progress，并保留原优先级、硬截止、预计投入和手动顺序；
- blocked 不新增主状态，只作为状态原因和展示分区。

## 6. 自动重排规则

触发事件：

| 事件 | 原型行为 |
| --- | --- |
| 新 Issue 分配给我 | 进入任务池，参与排序 |
| 新 PR 请求我 Review | 进入任务池，参与排序 |
| PR 收到 requested changes | 从 Pending Review 回到 On Progress |
| 任务被标记 blocked | 离开今日计划，进入阻塞区 |
| blocked 解除 | 重新参与排序 |
| Issue 关闭 | 进入 Done |
| PR merged / closed | 进入 Done |
| 日期切换 | 未完成任务重新参与下一日安排 |
| 硬截止变化 | 重新排序，并展示原因 |

容量不足时：

```text
今日容量不足

Issue #37 已移回规划池
原因：今日剩余容量不足

它没有被删除，也不会自动安排到后天。
日期切换或查看下一日计划时，它会重新参与排序。
```

任务缺预计投入时：

```text
待估算

Issue #51 更新项目文档
说明：已展示优先级，但补充预计投入前不进入今日计划。

[补充预计投入]
```
