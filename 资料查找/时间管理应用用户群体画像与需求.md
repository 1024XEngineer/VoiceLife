# 时间管理应用用户群体画像与需求

生成时间：2026-07-08
目的：为时间管理应用收敛更合理的目标用户群体，形成可继续做 Proposal、原型和用户访谈的输入。
方法：结合已安装的 PM / UX skills 框架，包括用户画像、JTBD、机会树、问题界定、Magic Lenses、多方案筛选和头脑风暴。
证据来源：`需求.md`、`时间管理产品功能点调研.md`、`国外时间管理及衍生产品功能点调研.md`、`时间管理产品最大创新方向头脑风暴.md`。
置信度说明：当前结论是方向性假设，不是已验证用户研究；需要后续访谈和小原型验证。

---

## 0. 结论先行

最值得优先服务的人群不是“所有想自律的人”，而是：

> **曾经尝试过时间管理工具或方法，但因为复杂、计划总崩、执行不了而放弃；现在因为新学期、考试、工作压力、生活失控或自我恢复需求，又想重新开始的人。**

暂定命名：**重启型时间管理用户**。

这个人群比“从没用过时间管理工具的人”更适合做早期目标用户，因为他们已经知道自己有问题，也知道普通清单、日历、番茄钟的不足。他们不需要被教育“为什么要管理时间”，他们需要一个更低摩擦、更可恢复、更少自责的重新开始方式。

### 推荐定位

**一句话定位假设：**

> 给计划反复失败的人用的时间管理应用：不用从空白清单开始，而是根据场景生成今天可执行的计划，并在拖延、分心或崩盘后帮你重排。

### 优先做的人群顺序

| 优先级 | 用户群体 | 选择理由 | 主要风险 |
|---|---|---|---|
| P0 | 重启型时间管理用户 | 痛点强、覆盖学生和职场、与“计划失败后恢复”创新方向高度吻合 | 人群宽，需要用场景进一步聚焦 |
| P0 | 学生 / 备考计划崩盘用户 | 需求高频，模板、专注、打卡、锁机证据充足，适合快速验证 | 竞品多，付费意愿可能弱 |
| P1 | 多工具碎片化的知识工作者 | 海外竞品验证了任务聚合、时间盒、AI 排程方向 | 需要日历/任务/消息集成，MVP 成本较高 |
| P1 | 自由职业 / 内容创作者 / 项目制个人 | 对估时、时间账本、复盘有刚需，愿意为效率付费 | 人群规模和触达渠道需要验证 |
| P2 | 家长 / 亲子习惯养成用户 | 家长监督成本真实存在，假期场景强 | 容易变成亲子教育产品，偏离个人时间管理主线 |
| P2 | 家庭 / 伴侣生活协同用户 | 生活协同方向成立，但产品形态会变成共享日历/家庭 OS | 与当前单人时间管理主线差异大 |

## 1. 候选用户群体画像

### 1.1 重启型时间管理用户

**一句话画像：**用过滴答清单、番茄钟、Notion、Obsidian、Excel 计划表或手帐，但每次坚持几天到几周就断掉；现在又因为现实压力想重新开始。

| 维度 | 内容 |
|---|---|
| 典型触发 | 新学期、考试倒计时、项目延期、工作堆积、假期结束、连续摆烂、生活状态失控 |
| 代表想法 | “我不是不知道要做什么，是每次计划一复杂就坚持不下去。” |
| 当前做法 | 重新下载 App、找模板、看效率方法视频、列新清单、买手帐、复制 Notion 模板 |
| 放弃原因 | 初始配置太重、任务越列越多、计划被打断后不会补救、完成不了就自责、复盘成本太高 |
| 核心需求 | 低成本重新开始、今日计划自动生成、失败后重排、任务拆小、少填字段、少内疚 |
| 产品机会 | “重启模式”：选择场景 -> 导入/输入现状 -> 生成 3 天恢复计划 -> 每天只保留少量关键任务 |
| 不该做 | 一上来要求用户建文件夹、标签、四象限、长期目标体系、复杂项目结构 |
| 置信度 | 中。现有资料中“模板、摆烂后补救、拖延、自动汇总、复盘”均指向该群体，但需要访谈验证 |

**需求判断：**这个群体不缺方法，缺的是一个能把方法降级成“今天能做什么”的系统。他们最怕工具变成新的负担，所以产品第一价值不是功能完整，而是帮他们重新获得掌控感。

### 1.2 学生 / 备考计划崩盘用户

**一句话画像：**开学、寒暑假、考研、考公、期末或证书考试阶段想认真学习，但计划常被手机、作息和拖延打断。

| 维度 | 内容 |
|---|---|
| 典型触发 | 开学计划、寒暑假计划、考试倒计时、假期后恢复学习、发现同学进度更快 |
| 代表想法 | “我需要有人把我拉回学习状态，光提醒没用。” |
| 当前做法 | 番茄 ToDo、学霸模式、线上自习室、打印计划表、学习博主模板、手写打卡表 |
| 放弃原因 | 计划太满、手机诱惑强、连续几天没完成后直接放弃、只记录专注时间但不对应具体任务 |
| 核心需求 | 场景模板、考试倒计时、每日学习计划、专注锁机、共同自习、打卡反馈、补救计划 |
| 产品机会 | “备考恢复计划”：考试日期 + 当前进度 + 每天可用时间 -> 自动生成本周学习任务和专注块 |
| 不该做 | 直接做复杂社交、排行榜内卷、过度游戏化，或只给一个普通番茄钟 |
| 置信度 | 中高。已有抖音侧资料和竞品功能都强烈指向该需求 |

**需求判断：**这类用户的核心不是“任务管理”，而是“进入学习状态”。任务、时间、专注约束和反馈必须绑定在一起。

### 1.3 多工具碎片化的知识工作者

**一句话画像：**任务来自微信/飞书/邮件/会议/日历/脑子里的临时想法，每天看起来很忙，但不知道今天真正应该推进什么。

| 维度 | 内容 |
|---|---|
| 典型触发 | 会议增多、项目并行、消息里承诺太多、老板/同事临时打断、下班后还在补任务 |
| 代表想法 | “我不是没工具，是任务散在太多地方，我没精力整理。” |
| 当前做法 | 飞书/企业微信待办、日历、Excel、备忘录、Todoist/滴答清单、脑内记忆 |
| 放弃原因 | 手动搬运任务麻烦、日历和待办割裂、任务估时不准、突发事情后计划失效 |
| 核心需求 | 统一收集、承诺识别、任务转日历、自动重排、会议和深度工作冲突提醒、周报 |
| 产品机会 | “今日承诺收口”：把聊天/会议纪要粘贴进来，AI 提取我方承诺、等待对方、截止时间和建议时间块 |
| 不该做 | 直接做飞书式完整团队协同；早期更适合个人承诺和个人日历防守 |
| 置信度 | 中。海外产品已验证任务聚合和 AI 排程，但本项目的集成能力和用户授权意愿需要验证 |

**需求判断：**这类人群付费和长期使用潜力更高，但 MVP 不宜一开始做全链路集成。可以先做“粘贴输入 -> 承诺提取 -> 今日安排”。

### 1.4 自由职业 / 内容创作者 / 项目制个人

**一句话画像：**没有固定上级帮他排优先级，收入、交付和个人时间直接相关，经常低估任务耗时。

| 维度 | 内容 |
|---|---|
| 典型触发 | 接了多个单、内容更新断更、客户催稿、项目延期、发现实际耗时远超预估 |
| 代表想法 | “我每次都觉得这个活两小时能做完，最后拖到半夜。” |
| 当前做法 | Notion、Trello、Excel、Clockify/Toggl、日历、手动记账式时间记录 |
| 放弃原因 | 计时太烦、复盘没有反哺排期、项目任务和时间记录割裂 |
| 核心需求 | 计划耗时 vs 实际耗时、项目时间账本、交付倒排、估时偏差修正、可用产能提醒 |
| 产品机会 | “时间账本”：每个任务记录预计/实际/偏差原因，下次自动给同类任务更真实的估时 |
| 不该做 | 只做漂亮清单，不处理估时和交付风险 |
| 置信度 | 中。国外工时产品和时间账本脑暴方向支持该需求，但目标用户规模需要验证 |

**需求判断：**这个群体的时间管理不是为了“自律感”，而是为了交付和收入。产品可以更理性、更数据化。

### 1.5 轻度拖延 / 刷机失控用户

**一句话画像：**知道自己该做什么，但开始前会刷短视频、看社媒、反复切任务，最后靠焦虑赶工。

| 维度 | 内容 |
|---|---|
| 典型触发 | 睡前刷机失控、临近 deadline、任务越拖越焦虑、看到“克服拖延”内容 |
| 代表想法 | “提醒我没用，我会直接划掉。” |
| 当前做法 | 番茄钟、锁机 App、白名单、自习室、关机、把手机放远 |
| 放弃原因 | 强约束太痛苦，普通提醒太弱；任务太大时仍然不想开始 |
| 核心需求 | 5 分钟启动、任务自动拆小、分心阻断、离开提醒、可调强度的专注模式 |
| 产品机会 | “启动按钮”：把任务拆成第一步，只要求 5 分钟，并在开始后进入轻约束专注 |
| 不该做 | 默认强锁机、羞辱式失败提示、复杂习惯系统 |
| 置信度 | 中高。已有资料中番茄、锁机、防刷机、5 分钟启动是强信号 |

**需求判断：**这不是独立最大人群，更像 P0/P1 人群里的横向需求模块。它适合作为核心执行机制，而不是单独产品定位。

### 1.6 家长 / 亲子习惯养成用户

**一句话画像：**家长希望孩子在假期、开学或日常学习中形成主动计划和打卡习惯，同时降低自己天天催的成本。

| 维度 | 内容 |
|---|---|
| 典型触发 | 暑假、寒假、开学、孩子作业拖延、家长在评论区求打卡表/计划表 |
| 代表想法 | “我不想每天吼孩子，但也不能完全不管。” |
| 当前做法 | 打印计划表、手写打卡表、微信群监督、家长口头提醒、学习类 App |
| 放弃原因 | 孩子被动执行，家长维护成本高，打卡变成形式主义 |
| 核心需求 | 亲子计划、习惯打卡、孩子端正反馈、家长端周报、异常提醒、轻监督 |
| 产品机会 | “假期习惯计划”：家长设置目标，孩子每天用低压力方式确认，家长看趋势而不是实时盯人 |
| 不该做 | 过度监控、惩罚导向、把产品变成家长控制工具 |
| 置信度 | 中。资料中家长和学生假期计划需求明确，但产品边界需要谨慎 |

**需求判断：**这个方向可能真实，但会把产品推向亲子教育和家庭协作。除非团队想做这个垂直方向，否则先作为后续分支。

### 1.7 情绪低能量 / 状态恢复用户

**一句话画像：**计划失败不只是因为不会安排，而是因为低能量、焦虑、拖延、自责循环，导致一断就很难回来。

| 维度 | 内容 |
|---|---|
| 典型触发 | 连续几天没完成计划、睡眠差、工作学习压力大、看到情绪手帐/复盘模板 |
| 代表想法 | “我不是不想做，是我一想到计划就更焦虑。” |
| 当前做法 | 情绪手帐、日记、冥想、低强度打卡、暂时不用任何工具 |
| 放弃原因 | 工具只显示失败，不理解状态；任务越积越多，提醒越多越烦 |
| 核心需求 | 低压力恢复、任务降级、情绪/精力记录、失败后重排、不羞辱用户 |
| 产品机会 | “低能量模式”：只保留一个最小任务，自动延期非关键任务，并记录状态原因 |
| 不该做 | 医疗化承诺、诊断心理问题、用强刺激逼迫用户 |
| 置信度 | 中。已有资料有情绪管理手帐和计划失败线索，但需要访谈避免误判 |

**需求判断：**这个群体很重要，但适合成为“重启型用户”的设计原则：产品要可恢复、低羞耻、低负担。

### 1.8 家庭 / 伴侣生活协同用户

**一句话画像：**两个人或一家人共同管理家务、账单、接送、购物、纪念日、证件到期和生活安排。

| 维度 | 内容 |
|---|---|
| 典型触发 | 共同生活后事务增多、谁都以为对方会做、账单/证件/家务遗漏 |
| 代表想法 | “我们不是没有时间，是没人知道这件事到底谁负责。” |
| 当前做法 | 微信提醒、共享备忘录、日历、Any.do Family、口头约定 |
| 放弃原因 | 输入麻烦、双方都不维护、容易变成互相监督和指责 |
| 核心需求 | 共享日历、责任分配、备份人、到期提醒、周计划、低摩擦确认 |
| 产品机会 | “两个人计划”：共享本周事务和责任，自动提醒冲突和遗漏 |
| 不该做 | 早期塞进完整团队项目管理 |
| 置信度 | 低中。国外竞品有方向，但当前资料对本地用户证据不足 |

**需求判断：**这是一个独立产品方向，不建议和 P0 个人时间管理混在同一个 MVP。

## 2. 用户需求分层

### 2.1 表层需求

| 表层需求 | 用户说法 | 实际可能需求 |
|---|---|---|
| 我要一个计划表 | “有没有模板？” | 用户不想从空白开始，需要结构化起步 |
| 我要番茄钟 | “我想专注 25 分钟。” | 用户需要启动和抗干扰机制 |
| 我要打卡 | “想坚持下来。” | 用户需要看见进步和保持连续性 |
| 我要 AI 帮我排 | “能不能自动整理？” | 用户想减少手动维护、降低认知负担 |
| 我要复盘 | “我想知道时间去哪了。” | 用户想让过去的失败反哺下一次计划 |
| 我要锁机 | “我管不住手机。” | 普通提醒无效，需要可调强度的约束 |

### 2.2 深层需求

| 深层需求 | 说明 | 对产品的要求 |
|---|---|---|
| 可重新开始 | 用户计划失败后不能被系统惩罚到放弃 | 需要重启、补救、降级、自动重排 |
| 少做选择 | 用户不是没事可做，而是不知道先做哪件 | 每天给出少量关键任务，不把所有事项推给用户 |
| 少手动整理 | 手动填标签、优先级、时长、分类会让用户流失 | AI 建议日期、时长、优先级和任务拆分 |
| 计划必须落到时间 | 清单不等于执行 | 任务要能变成时间块或专注块 |
| 执行需要约束 | 对抗手机和拖延，靠提醒不够 | 提供从软提醒到强约束的强度梯度 |
| 复盘要能改变明天 | 统计本身不是价值 | 复盘结果要自动调整计划、估时和任务颗粒度 |
| 工具不能制造羞耻 | 时间管理用户很容易因失败自责 | 文案、机制和视觉反馈要鼓励恢复，而不是审判 |

## 3. JTBD：用户真正“雇佣”这个产品做什么

### 3.1 主 JTBD：计划失败后的重新开始

**Job Performer：**重启型时间管理用户。
**Circumstance：**曾经用过时间管理工具，但因为复杂、计划崩盘或拖延而放弃；现在遇到新阶段或压力，需要重新进入节奏。
**Job Statement：**

> 当我发现生活、学习或工作又开始失控，而过去的时间管理工具让我坚持不下去时，我想快速生成一个今天能执行的小计划，这样我可以重新获得掌控感，而不是又陷入自责和重新折腾工具。

**Functional Job：**

- 把当前任务、目标和时间约束收集起来。
- 自动生成今天/本周最小可执行计划。
- 在任务拖延、时间不够或突发事件后重排。
- 将任务转成具体时间块或专注块。
- 自动复盘计划和实际执行的偏差。

**Emotional Job：**

- 想感觉“我还能重新开始”。
- 想避免“我又失败了”“我连计划都坚持不了”的羞耻感。
- 想降低开始前的焦虑，而不是被更复杂的系统压迫。

**Social Job：**

- 对自己、同学、家人、同事或客户有交代。
- 看起来不是失控的人，而是正在恢复节奏的人。

**Competing Solutions：**

| 类型 | 当前方案 | 优点 | 不足 |
|---|---|---|---|
| 直接竞品 | 滴答清单、Todoist、Things、朝暮计划 | 功能完整，任务记录强 | 新手或重启用户容易被配置和任务堆积压垮 |
| 专注竞品 | 番茄 ToDo、Forest、Freedom | 执行约束强 | 不一定解决“今天该做什么”和计划失败后的重排 |
| 模板方案 | Notion/Obsidian/Excel/手帐模板 | 起步快，可视化强 | 需要用户持续维护，断掉后恢复成本高 |
| 非消费 | 不用工具，靠焦虑硬撑 | 零学习成本 | 容易漏事、熬夜、拖延、反复失控 |

**Hiring Criteria：**

- 必须一开始就能给出可执行计划，而不是空白页。
- 必须允许计划失败，不让用户从头配置。
- 必须减少手动字段和维护成本。
- 必须能把任务和时间/专注关联起来。
- 最好能根据实际执行自动改进后续计划。

### 3.2 次 JTBD：学生/备考进入学习状态

> 当考试、开学或假期计划让我感到压力，而我容易刷手机和拖延时，我想让系统帮我生成学习计划并约束我进入专注状态，这样我可以持续推进复习，而不是每天重新做计划。

核心产品要求：考试倒计时、学习模板、每日任务、专注绑定任务、锁机/白名单、共同自习、断档补救。

### 3.3 次 JTBD：知识工作者收口承诺

> 当任务分散在会议、聊天、邮件和日历里，而我害怕漏掉承诺时，我想让系统提取并安排我答应过的事情，这样我可以按时交付并保护深度工作时间。

核心产品要求：粘贴聊天/会议纪要提取承诺、我方/对方责任区分、截止时间、状态、跟进话术、日历时间块。

### 3.4 次 JTBD：项目制个人修正估时

> 当我经常低估任务耗时并导致交付延期时，我想知道计划时间和实际时间的偏差，这样我下次可以更真实地安排工作量。

核心产品要求：预计耗时、实际计时、偏差原因、同类任务估时修正、周报和项目风险提醒。

## 4. 机会解决方案树

**期望结果：**让新用户在 7 天内至少 3 天完成一个“系统生成或系统辅助调整过的今日计划”。
**当前状态：**未知，需要产品上线或原型测试后建立基线。
**目标状态：**早期原型中，5-8 名目标用户里至少 3 人愿意连续试用 3 天以上。
**Owner：**产品设计/需求负责人。

```text
Outcome: 7 天内让用户完成 >=3 天可执行今日计划
|
|-- Opportunity A: 用户不想从空白页开始
|   |-- 场景模板生成计划
|   |-- 3 天重启计划
|   |-- 学期/考试/项目倒排模板
|
|-- Opportunity B: 用户知道任务但开始不了
|   |-- 5 分钟启动
|   |-- 任务自动拆成第一步
|   |-- 专注强度梯度：提醒 -> 番茄 -> 白名单 -> 锁机
|
|-- Opportunity C: 计划被打断后用户不会恢复
|   |-- 一键重排今天
|   |-- 任务自动降级/延期
|   |-- 低能量模式
|
|-- Opportunity D: 用户不知道时间真实花在哪里
|   |-- 计划耗时 vs 实际耗时
|   |-- 每周偏差报告
|   |-- 同类任务估时修正
|
|-- Opportunity E: 任务散在多个地方
|   |-- 自然语言快速收集
|   |-- 粘贴聊天/会议纪要提取承诺
|   |-- 今日任务池自动分类
```

### 4.1 机会优先级

| Rank | Opportunity | Impact | Confidence | Effort | 判断 |
|---|---|---|---|---|---|
| 1 | 用户不想从空白页开始 | 高 | 高 | 中 | 模板和计划生成是现有资料里最强信号 |
| 2 | 计划被打断后用户不会恢复 | 高 | 中 | 中 | 与“重启型用户”定位强相关，差异化明显 |
| 3 | 用户知道任务但开始不了 | 高 | 高 | 中 | 防拖延/防刷机证据强，适合作为执行模块 |
| 4 | 用户不知道时间真实花在哪里 | 中高 | 中 | 中 | 适合增强长期复盘和估时准确性 |
| 5 | 任务散在多个地方 | 高 | 中 | 高 | 价值高，但集成成本高；早期可用粘贴输入降级验证 |

### 4.2 当前最值得测试的解决方案

**Priority Opportunity：**用户不想从空白页开始 + 计划失败后需要恢复。
**Priority Solution：**重启模式。

**重启模式 MVP 假设：**

用户打开产品后不需要先建清单，而是选择一个场景：

- 我又想重新开始
- 我要备考/学习
- 我最近工作任务堆积
- 我想减少刷手机

然后输入当前情况：

- 今天/本周必须完成的事
- 可用时间
- 最容易拖延的点
- 最近为什么计划失败

系统输出：

- 今天最多 3 个关键任务
- 每个任务的第一步
- 建议时间块或专注块
- 如果失败，晚上自动给出明天的补救计划

**最小验证标准：**

- 5 名目标用户中至少 3 名认为“比我自己列计划更容易开始”。
- 5 名目标用户中至少 2 名愿意连续 3 天试用。
- 用户不需要解释就能理解“重启模式”解决什么问题。
- 用户不会觉得“又是一个要我填很多东西的效率工具”。

## 5. Magic Lenses：候选目标用户筛选

候选 Approach：

- A：重启型时间管理用户
- B：学生 / 备考计划崩盘用户
- C：多工具碎片化知识工作者
- D：自由职业 / 内容创作者 / 项目制个人
- E：家长 / 亲子习惯养成用户

### 5.1 Customer Lens：目标用户是否容易理解并想要

| Approach | 用户感知 | 位置 |
|---|---|---|
| A 重启型 | “这就是我，每次都重新开始又放弃。”理解成本低 | 高价值 / 中可行 |
| B 学生备考 | “给我计划、锁机、自习。”场景明确 | 高价值 / 高可行 |
| C 知识工作者 | “能不能收口任务和承诺？”价值高但信任要求高 | 高价值 / 低中可行 |
| D 项目制个人 | “帮我估时和交付。”价值明确但小众 | 中高价值 / 中可行 |
| E 家长亲子 | “帮我少催孩子。”痛点明确但产品语境不同 | 中价值 / 中可行 |

Top per Customer Lens：A、B。

### 5.2 Pragmatic Lens：个人项目早期是否能高质量做出

| Approach | Build cost | Risk |
|---|---|---|
| A 重启型 | 中 | 中。需要做好体验，不一定依赖复杂集成 |
| B 学生备考 | 中 | 中。竞品多，但 MVP 可做 |
| C 知识工作者 | 高 | 高。需要日历、聊天、邮件或企业工具集成 |
| D 项目制个人 | 中 | 中。计时和报表可做，但体验需克制 |
| E 家长亲子 | 中高 | 中高。涉及多端/多人/儿童体验 |

Top per Pragmatic Lens：A、B、D。

### 5.3 Growth Lens：是否有自传播故事

| Approach | 传播故事 |
|---|---|
| A 重启型 | “适合计划失败后重新开始的人，不会因为你断了就惩罚你。” |
| B 学生备考 | “考试倒计时 + 每日学习计划 + 锁机专注。” |
| C 知识工作者 | “把聊天和会议里的承诺变成今天安排。” |
| D 项目制个人 | “终于知道自己每类任务真实要花多久。” |
| E 家长亲子 | “不用天天催孩子，家长看周报就行。” |

Top per Growth Lens：A、B、C。

### 5.4 Money / Value Lens：即使非商业项目，谁的持续价值最高

| Approach | 持续价值路径 |
|---|---|
| A 重启型 | 反复出现的恢复需求，可扩展到学生、职场和生活 |
| B 学生备考 | 高峰期强，但有季节性，且可能偏免费工具用户 |
| C 知识工作者 | 付费和长期价值高，但前期能力门槛高 |
| D 项目制个人 | 与收入/交付相关，价值感明确 |
| E 家长亲子 | 家长可能有付费意愿，但方向会转向教育管理 |

Top per Value Lens：A、C、D。

### 5.5 Custom Lens：自娱自乐项目适配度

问题：哪个方向既有真实痛点，又适合个人开发者快速做出有趣、有差异的原型？

| Approach | 评估 |
|---|---|
| A 重启型 | 最适合。可以先做单人体验，用 AI 生成计划和恢复建议，不强依赖集成 |
| B 学生备考 | 适合。模板、倒计时、专注模式容易成型，但竞品压力大 |
| C 知识工作者 | 有趣但重。若不接入工具，只能先做粘贴式承诺提取 |
| D 项目制个人 | 适合做工具感强的 MVP，但大众情绪共鸣弱于 A/B |
| E 家长亲子 | 需要多角色体验，个人项目维护成本较高 |

Top per Custom Lens：A、B、D。

### 5.6 Pattern Review

**Consistent winners：**A 重启型时间管理用户、B 学生 / 备考计划崩盘用户。
**Consistent losers：**E 家长 / 亲子习惯养成用户，本身不是坏方向，但容易偏离当前产品主线。
**Contradictions：**C 知识工作者价值高、付费强，但早期实现成本高；D 项目制个人清晰可做，但市场情绪和传播性弱于 A/B。
**Biggest trade-off：**广泛共鸣与场景聚焦之间的取舍。

### 5.7 Top Bet

**Top bet：A 重启型时间管理用户。**

选择它是因为它不是一个狭窄人口标签，而是一个强触发场景：计划失败后重新开始。这个场景能自然解释模板、AI 计划、专注、复盘、重排和低羞耻体验，也能覆盖学生、职场和个人成长用户。

### 5.8 Backup Plan

**Backup：B 学生 / 备考计划崩盘用户。**

如果重启型人群太宽，导致原型表达不清，可以收窄到学生/备考场景。这个备选方向足够具体，用户触发明确，且已有资料中模板、专注、打卡、锁机、自习室需求很集中。

### 6.3 暂不建议本期做

| 不做 | 原因 |
|---|---|
| 完整团队协作 | 会变成飞书/钉钉式任务系统，复杂度高 |

## 7. 可直接用于访谈的验证问题

### 7.1 筛选问题

1. 你过去 6 个月内有没有尝试过时间管理工具、手帐、计划表、番茄钟或 Notion/Excel 模板？
2. 你最近一次想重新开始管理时间，是因为什么触发的？
3. 你现在最想解决的是：任务太多、手机分心、计划总失败、时间不知道去哪了，还是别的问题？

### 7.2 深挖问题

1. 你上一次放弃时间管理工具是在什么时候？为什么放弃？
2. 你今天要做什么，通常是怎么决定的？
3. 当计划当天没完成时，你第二天会怎么处理？
4. 你有没有用过模板？模板帮到了哪里，又在哪里失效？
5. 提醒、番茄钟、锁机、自习室，哪个对你真的有用？哪个只是看起来有用？
6. 如果一个系统自动给你排今天的任务，你最担心它排错什么？
7. 你愿意每天花多久维护这个系统？30 秒、3 分钟、10 分钟还是更久？
8. 什么情况下你会连续用 7 天？什么情况下你第一天就卸载？

### 7.3 原型验证任务

1. 给用户一个“重启模式”表单，让用户填入当前状态，观察是否能 2 分钟内完成。
2. 输出一份今日计划，问用户是否愿意照着做，并让用户删改。
3. 模拟计划失败，让用户点击“一键重排”，观察重排结果是否被信任。
4. 让用户在 5 分钟启动模式里开始一个真实任务，观察是否降低拖延。
5. 第二天回访，问用户是否还记得计划、是否执行、为什么中断。

## 8. 产品设计原则

1. **恢复优先于完美计划。** 目标用户的核心痛点是计划断掉后回不来，不是第一次计划不够漂亮。
2. **少量关键任务优先于完整任务库。** 每天给 3 个能执行的任务，比给 30 个待办更有价值。
3. **自动建议优先于手动字段。** 日期、时长、优先级、任务拆分应由系统先给建议，用户只微调。
4. **任务必须落到执行场景。** 任务要能进入时间块、专注块或恢复计划，否则只是记录。
5. **失败反馈不能羞辱用户。** 不要把断签、未完成、延期设计成压力源；重点是下一步怎么恢复。
6. **约束强度可调。** 有的人只需要提醒，有的人需要锁机；默认不要上来就强控制。
7. **复盘要改进未来。** 如果复盘不能让明天的计划更准，就只是统计图。

## 9. 后续建议

### 9.1 下一步最小产品方向

建议先做一个“重启型今日计划”原型，而不是完整时间管理应用。

**MVP 流程：**

1. 用户选择重启场景。
2. 用户输入当前必须做的事、可用时间、最容易失败的原因。
3. 系统生成今天最多 3 个关键任务。
4. 每个任务都有第一步、建议时长和专注按钮。
5. 用户可以点击“今天崩了，帮我重排”。
6. 晚上做 2 分钟复盘，系统生成明天建议。

### 9.2 第一轮访谈样本

建议先找 12 人，分 3 组：

| 组别 | 人数 | 筛选条件 |
|---|---:|---|
| 重启型个人用户 | 5 | 过去半年用过时间管理工具但中断，现在想重新开始 |
| 学生/备考用户 | 4 | 近期有考试/学习计划，使用过番茄、计划表或自习室 |
| 工作任务堆积用户 | 3 | 每周任务来自多个渠道，常漏事或计划被打断 |

访谈目标不是问“你想要什么功能”，而是确认：他们什么时候想重启、为什么放弃旧工具、什么样的计划真的能让他们开始。

### 9.3 当前判断的最大风险

1. “重启型用户”可能太宽，需要通过场景继续收窄。
2. 用户嘴上说想自动排程，但实际可能不信任系统。
3. 如果输入成本超过 2-3 分钟，目标用户可能直接放弃。
4. 只做计划生成不够，必须解决计划失败后的恢复。
5. 专注/锁机需求真实，但强约束过重会让一部分用户反感。
